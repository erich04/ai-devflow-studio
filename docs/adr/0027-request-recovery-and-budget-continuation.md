# ADR 0027：按请求计量、按步骤恢复和受限继续授权

- 日期：2026-10-10
- 状态：实现；原生工具协议保留为默认关闭的隔离试点
- 关联：#201、#202、#224、#226、#229、#230、#231、#233、#234

## 问题

固定的短正文接收容量与提高后的模型输出额度互相冲突。一次格式错误消耗整轮恢复额度，成功查询之后再次失败仍不能恢复；手动重试又重复读取材料。中断响应缺少完整用量时，历史未知费用可能阻止整个项目继续，结算上传失败还会掩盖已经收到的有效结果。

任务预算、单次请求额度、流式接收容量、上下文容量、步骤恢复次数及展示长度是不同约束。本次分别建模，并让每次实际模型请求使用同一份请求策略和预算报价。

## 请求与接收

`resolveRequestPolicy` 同时供 Direct Provider、工作台对话、门禁审查、阶段生成和受治理的 OpenCode 中继使用。Token 额度写入实际请求的 `max_tokens`，预算准入使用同一值。UI 是否订阅推理不影响模型的 Thinking 设置或输出额度。

| 策略 | 已识别的官方 DeepSeek 配置 | 未核验的 OpenAI 兼容服务 |
| --- | --- | --- |
| 默认输出 | Thinking 关闭 8,192；low/high 65,536；max 131,072 tokens | 8,192 tokens；不套用 DeepSeek 能力 |
| 自动长度恢复 | 每次翻倍，最多 393,216；每次重新准入 | 不根据猜测自动扩大 |
| 上下文 | 1,048,576 tokens；为输出和系统提示预留空间 | 使用保守的本地估算，能力标为未核验 |
| 请求序列化容量 | 4 MiB，包含工具定义与完整工具历史 | 同左 |
| 正文 / 推理接收 | 分别 8 MiB UTF-8 字节 | 同左 |
| 未消费的 SSE 帧 / 非流式包络 | 64 MiB | 同左 |

这些仍然是有界容量，不代表可以无限输出。SSE 按增量解码，已消费帧释放；UTF-8、结束帧、工具索引、调用 ID 和参数完整性有明确校验。正文与推理分别统计。超过容量时保留限制名称、已接收字节、结束原因、响应标识和已观察到的用量，不把该错误统一归因为网络。

本地请求校验在预算预留前运行。即使调用期间发生另一项本地拒绝，错误也必须明确标为 `not_sent / not_incurred`，不能生成未知账单。字符数、UTF-8 字节数和 token 不互相冒充；已识别 DeepSeek 的费用上界使用完整上下文 token 上界，实际 token 仍只来自提供方。

## 步骤恢复和内容保存

- 每个失败步骤为首次调用加最多两次自动重试；成功的普通查询开启下一组恢复额度。正在生成关键提案时，查询、格式和完整性恢复共用同一个恢复组，防止通过补查询无限重置。
- 可恢复网络错误采用有界等待；长度恢复仅适用于已识别能力。取消、凭据错误、过滤拒绝和本地越界拒绝不自动重试。
- 每批至多 12 步；180 秒是开始新步骤的软边界。达到时间边界时先完成当前步骤最多两次的自动恢复，再暂停后续步骤并提供“继续当前步骤”。这不是整项任务总 token 配额。
- 检查点保留已查材料、来源、原生工具结果和失败历史。手动重试创建新 cycle；不会重复用户消息。仓库或正式材料发生变化时重新核实相应事实。
- 逐次记录 turn、step、cycle、recovery group、时间及失败元数据。只有完整通过业务校验的最终答复或提案才能保存为成功结果；查询成功不能替代完成。
- 大文本由主进程写入 SQLite 相邻的 `.contents` 私有目录。长字符串通过哈希引用保留，使用私有权限、原子发布及读取校验；相同内容并发写入时核验后复用已有文件，不覆盖正在读取的文件。实时正文和推理写入独立文件。IPC 提供有范围校验的分页读取，列表只传预览。
- 备份必须同时包含 SQLite 与其 `.contents` 目录。当前没有后台垃圾回收；不能将预览缩短描述为磁盘使用无限小。回退旧版本前需备份，旧代码不理解新的内容引用格式。

正式方案修订绑定当前方案和选定提案的版本摘要，发送完整输入，事务内再次检查版本。新方案、来源、用量及轨迹一并保存；旧版本保留，取消或持久化失败不推进 Gate。长方案按确定规则分块送审，清单明确标记 `deterministically_chunked`；重组全文必须与保存正文一致。

## 费用与继续使用

每次实际请求分别预留、记录发送、保存观察用量、写入最终状态并结算。完整、部分和未知用量明确区分；未知不是零。提供方返回有效结果后，结算上传失败只标记 `settlementStatus: pending`，后续重放已保存账本，不重新调用模型。

费用分为已确认实际费用、执行中的预留、待核实但有可靠上界的占用，以及无法估算的未知费用：

1. 已识别模型、输出额度和定价版本能够形成可核验上界时，未知最终费用按该上界占用预算。预算余额足够可以继续。
2. 旧记录缺少可靠上界或余额不足时，当前操作显示一张默认未勾选的继续确认卡。卡片展示操作名称、调用时间、已有答复状态、费用分类、下一次请求上界及整个授权的上限。
3. Lead/Owner 勾选后仅授权这次操作，绑定组织、身份、项目、提供方、模型、操作版本、策略版本、月份及待处理费用版本。最多 36 个请求、15 分钟，同时受金额总上限和单次上限约束。扩大单次请求额度不能沿用较小额度的确认卡。
4. 服务端事务内核验授权与余额；重复确认幂等，过期、身份变化、新未知记录、策略变化或取消都不会放行旧等待请求。
5. 确认继续不修改历史实际费用、不伪造 token 或账单，也不关闭预算。历史账单仍待核对；迟到的完整用量作为独立证据结算并释放占用。相互冲突的真实账单必须先核对，不能被继续授权覆盖。
6. 不再按固定十分钟把执行中的调用自动释放。未结束调用跨月仍占用；已结束旧月份记录保留可见，不计入新月的实际花费。

数据库迁移 0032 为继续授权新增保存位置。应用升级前正常执行迁移；回退应用时保留新增数据与审计记录，不用删表或把未知值改成零作为恢复手段。

### 分项发布和回退

以下是进程启动前的部署配置，默认启用。修改后重启相应服务；不是用户预算或 Provider 设置，也不回滚已发生的操作。

| 开关设为 `0` | 作用进程 | 停止的新行为 | 始终保留 |
| --- | --- | --- | --- |
| `DEVFLOW_LONG_CONTENT_ENABLED` | Electron / 调用模型的主机 | 新请求输出上限降至 8,192，不再自动扩大 | 接收中响应、已有长材料、内容引用读取和持久化；报价使用实际发送的较小额度 |
| `DEVFLOW_BUDGET_PENDING_HOLDS_ENABLED` | Team API | 不再允许借待核对费用上界或继续确认卡发起新请求；旧确认卡也不能准入 | 既有占用、审计、用量重传及迟到结算；不能借关闭开关释放费用 |
| `DEVFLOW_STEP_RECOVERY_ENABLED` | Electron / 调用模型的主机 | 停止自动格式/网络/长度恢复 | 已完成查询、逐次失败记录、检查点，以及用户明确点击的手动继续 |

这些开关只停止新执行能力，不能代替数据库降级。原生工具试点另有默认关闭的开关，见下文。部署开关变化不代表历史未知费用已确认或模型已经停止计费。

## 编码工具的会话授权

“允许本次”保持默认。用户可以选择仅在当前编码会话复用明确规则：

- 命令必须全文相同；文件规则只允许已列出的仓库相对路径集合内的编辑、写入和补丁，不使用通配符。
- 绑定身份、组织、项目、coding run、工作树、配置版本及阶段；每次仍重验策略和当前权限请求。
- 两小时到期，可主动撤销；会话结束、上下文改变或进程重启后不再有效。持久化审计不能恢复权限。
- 显式禁止优先；初始执行授权、最终改动接收、Gate 与交付批准不受该规则代替。
- 创建、命中、撤销、过期均记录审计。OpenCode 每次仍收到 DevFlow 核验后的单次响应，不把其全局 `always` 当作授权管理器。
- 暂不提供永久项目规则。跨会话持久授权需要独立的策略编辑、撤销和迁移设计。

## 门禁审查与原生工具试点

门禁审查设置独立于开发执行器：保留 `direct-provider` 材料审查、`local-agent` OpenCode 仓库审查，新增 `native-agent` 内置仓库只读审查。旧值及历史报告不重写，显式选择失效时不静默降级。

内置审查只允许列目录、读文件和搜索。主机核验实际读取、行范围、内容摘要及审查前后仓库一致性，报告引用不能只凭模型自述。每次模型请求受同一预算治理；没有 Shell、写文件或自动审批能力。

工作台的原生 Function Calling 是另一项试点：

| 组合 | 实现与证据 | 启用 |
| --- | --- | --- |
| 官方端点 + 精确模型 ID `deepseek-flash` | SSE/非流式、并列调用、Thinking 历史、引用、预算和取消有确定性及 Electron 本地端点验证；本次未验证真实端点 | 默认关闭 |
| DeepSeek Pro、别名、未知兼容服务 | 不宣称原生工具兼容 | 不启用此试点 |
| 旧 Direct Provider 正文 JSON / OpenCode | 原协议和保存历史保留 | 不因试点更改 |

隔离试用需在启动 Electron 前设置 `DEVFLOW_NATIVE_READONLY_PILOT_ENABLED=1`，并显式新建原生只读会话。开关默认隐藏该选择；关闭后旧记录仍可读，不能自动换协议重放。仅开关开启并不等于真实端点已经通过兼容性验收。

原生批次最多 16 个调用、每个参数 64 KiB，所有调用先完成名称、参数、项目、路径与符号链接校验，再写入检查点并按确定顺序执行。非法批次不执行任何工具，也不留下未配对的 `tool_calls`。最终答复和提案仍走原业务契约。
