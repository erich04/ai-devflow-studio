# 会话调查的边界、恢复与诊断

适用版本：在主干 `f8a97da` 的步骤恢复和原生会话能力上，整合本地 Memory 实现后的 A 工作包，覆盖 #248、#249、#250。#201/#202 的历史原始故障尚未重现，本轮只验证相应的防护与诊断能力。

## 执行方式

聊天面板「调查范围与诊断」允许为会话设置每批 1–60 步、30–600 秒。默认继续采用 12 步、180 秒；配置在下一次发送或继续时生效，运行中不能修改。30 步只是可选实验值，没有证据支持将其设为默认。

一次用户问题可以由多个批次完成。步骤、模型请求、恢复、只读查询、总结分别计数：单步仍复用主干的首次请求加最多两次恢复；继续或切换 Provider 保留本问题累计计数。宿主另限制累计 240 个请求尝试、24 次自动恢复、3,840 次工具查询，普通请求留出两个收尾位置；每批查询上限随步数取 `16 × maxSteps`，不存在普通协议旧有的 32 次截断。累计请求硬边界使用本地收尾，不再调用模型。

到达步数、时间或无进展边界后保存检查点，状态为 `paused`。Direct Provider 与 Native v2 使用无工具的结构化总结，最多两次、30 秒、每次 2,048 输出 tokens；所有调用经过同一个受治理 Provider 并保留实际用量。总结只接受正文和已有引用 ID，不能创建提案、批准 Gate 或执行工具。取消、拒绝和无法取得总结时，显示宿主保存的进度与证据索引，并明确尚未形成完整结论。

OpenCode 内部调用由其 harness 管理，宿主不叠加格式恢复或启动额外的工具型总结运行；到限以本地进度收尾。宿主把当前剩余步骤与查询额度传入专属执行器，OpenCode 的步骤配置与 MCP 查询上限按该额度执行，不再另设隐藏的 32 次查询限制。零查询额度不允许额外执行一次查询；超出最大调查范围的额度在启动前拒绝。其内部模型步骤不能冒充为宿主可观察的请求数量，界面明确显示累计调查启动次数，内部模型用量由执行器记录；诊断只报告宿主可核验的边界。

## 证据和 Memory

重复检测使用工具名、规范化参数、分页范围及结果摘要。连续或交替重复都能识别；只有原结果仍完整出现在实际发给模型的上下文中，且新读取验证内容未变时，才计作无进展。四次无进展触发暂停。复用有效来源 ID，避免把同一正文不断追加进上下文；验证来源仍发生真实本地读取，计入工具数，不宣称节省了磁盘读取。

上述可见证据判断适用于宿主组装的 Direct Provider 和 Native 请求。OpenCode 同一内部循环暂未提供可靠的逐请求可见证据回执，MCP 已返回某条结果不能证明它在后续模型上下文中仍完整存在，因此本轮不对这些内部重复查询计作无进展；仍执行宿主查询额度与 OpenCode 步骤边界。未来取得内部请求回执后才能扩大这项判定，不能把当前实现描述为三种执行器均具有相同的循环检测能力。

分页、内容变化、前次失败或旧结果被裁剪后的重读不当作死循环。继续时重新核验文件、流程及材料；不复用过期远端搜索句柄。Native 的原协议记录保留，来源失效时结束旧工具配对并建立新的上下文边界，不删一半工具对。所有原文、失败记录和已产生用量继续保存。

Native v2 每次请求重新召回当前用户与项目的项目记忆（ADR 0030），以临时用户消息附加，不写入静态系统提示或永久协议历史。沟通偏好另做一次小召回，放在同一条消息的 `communicationPreferences`；当前用户要求优先。发送前再次核验记忆版本及身份，记录实际附带的记忆 ID 和投递状态；容量不足时先移除可选记忆，回执同步反映移除结果。投递成功不等于模型已采纳。

## 诊断边界

逐调用元数据包括有效请求配置、协议/版本、开始结束时间、用量、传输和解析阶段、结束原因、正文长度与摘要、JSON 错误位置、SSE 完整性及恢复组。未知用量仍为未知，不按零计费；失败与取消后已返回的用量仍保存。Provider 原始错误与存储错误区分，落盘失败不能自动触发付费重试。诊断写入短暂失败而存储恢复可写时，保留原始模型失败及用量，同时标记 `diagnosticPersistenceFailed` 并提示本地存储故障；永久存储失败不冒充记录已经落盘。

导出通过显式白名单投影，包含应用版本、协议、调查策略/计数、调用及投递信息，不导出聊天、代码、工具参数、完整响应、提示词、推理或凭据。最近 200 次、30 天的附加诊断保留，单份导出最多 512 KiB；轮换仅去掉附加诊断，不删除原消息、原始财务记录和 Memory 回执。由于默认不留失败响应全文，导出会明确标为无法重放历史失败。

源码入口：`workbench-conversation-service.ts` 负责项目范围与主流程；`native-conversation.ts` 负责原生协议状态机；`investigation-policy.ts` 负责计数与边界；`investigation-summary.ts` 负责收尾；`conversation-diagnostics.ts` 负责轮换和导出；共享 `provider-diagnostics.ts` / `provider-response.ts` 负责安全元数据和响应分类。

验证结果记录在本轮独立验证报告中。确定性夹具、故障注入与真实模型请求分别报告；不能用其中一种替代另一种，也不能据成功回归关闭缺少原始现场的 #201/#202。
