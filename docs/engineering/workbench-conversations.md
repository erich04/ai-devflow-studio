# 工作流看板、节点详情与独立会话

本次基于 PR #127 的 `f11246c1c6b2be94ee7f12e8a91ae48f69a00d2d` 开发。
分支：`codex/unified-workbench-conversations-20260916`。

## 使用方式

工作台保留左侧项目与 Run，中间按需求、方案、开发、测试、交付、验收显示六个阶段。
上方阶段导航可以定位对应阶段；流程视图和列表视图共用真实节点，不创建另一套状态。

右侧只有两类 Tab：

- **节点详情**：固定入口。点卡片切换到对应详情；点产物、测试证据、轨迹计数直接进入相应内部标签。
- **对话**：点加号先打开新建窗口，选择 Direct Provider 或 OpenCode，确认后才建立独立会话。取消不会创建空会话或调用模型。卡片的“讨论此问题”和“向项目提问”使用同一创建流程，保留预填问题，由用户创建后自行发送，不把会话绑定到该节点。

执行方式保存在各自会话中，已有会话只读显示实际方式和当前模型；更换方式请另建对话。
“会话信息”旁的小问号打开可关闭的详细说明，解释共享与独立资料、保存提案、工具范围和权限。

任何会话都能查询当前本地项目的其他节点和其他 Run。关闭 Tab 后可以从历史恢复；
不会取消仍在进行的调查。需要停止时使用对话里的“停止调查”。切换 Tab 不清空输入；
应用重启恢复历史、草稿、问题和执行方式，未完成的调用标记中断并等待用户重试。
旧版手动备注仍可查看，但已停用，不再加入模型输入。

## 调查与追问

会话使用 Agents 中安全保存的当前 Provider。Electron Main 运行最多 12 次调用、总时限
180 秒的只读调查循环。模型可以按问题选择真实工具：

| 工具 | 内容 |
| --- | --- |
| `workflow` | 最新 Run/节点状态，支持按标题搜索、按 Run 查询和分页。 |
| `node` | 任意节点的产物、测试、轨迹、Gate 检查，以及真实 Coding、权限、Delivery 状态。 |
| `artifact` | 指定 Run 的产物正文，过长内容明确截断。 |
| `repo_list/read/search` | 当前本地仓库内的受限只读目录、文本读取和搜索。 |
| `knowledge` | 已配置的项目知识来源，保留读取时间、来源和内容摘要。 |

工具读取会留在本会话记录中。回答可以包含来源、节点跳转按钮、追问选项和提案预览。
选项填入输入框后由用户发送；也可以自由回答。用户转而询问其他节点时，旧问题继续待答。
对话中的导航按钮重新校验真实目标，使用原有 Inspector 和执行入口。

每次调用适配现有 Provider 的 32,000 字符输入合同：较早消息、过长查询和流程摘要按需限制，
完整历史仍保留。常规界面不再展示已使用/省略的消息计数，仍保留实际容量限制与失败提示；
上下文选取和持久化机制不变。这里没有宣称无限上下文或自动摘要记忆。
只记录 Provider 实际返回的 token，未返回或部分缺失时明确显示，费用不填虚构数字。
失败保留中文恢复提示，以及可展开的阶段、错误代码和 HTTP 状态诊断。

## 共享与隔离

共享查询来源是最新流程、已保存产物和证据、仓库代码与项目知识。
每条会话的历史、待答问题和未保存提案相互隔离。会话表只在本地 SQLite 中存在，
不加入 Team 同步、远端概览或 `loadState()` 的共享工作流数据。

点击“保存为节点提案”后，只把展示出来的提案保存到指定节点，标记“待确认”。保存与会话
引用原子提交，并使用版本检查防止并发覆盖。后续阶段生成可以读取这份提案；仍需通过原有
正式产物、测试和人工 Gate。聊天不会直接批准 Gate、修改代码或发布 PR。

读取工具不执行 shell，不读取其他项目或会话，不跟随符号链接，不读取凭据/环境变量文件。
通用业务数据库、任意 MCP 调用和新的 Coding 执行器不在本次会话工具中。
原有 Direct Provider、OpenCode 和 Native Coding 的正式工作流入口继续保留。

## 所有节点的覆盖范围

| 节点 | 保留的详情标签 | 执行与状态覆盖 |
| --- | --- | --- |
| 需求澄清 | 状态、产物、测试证据、轨迹、Gate 影响 | 初始、调查/追问、生成澄清、版本化产物。 |
| 需求确认 Gate | 状态、产物、测试证据、轨迹、Gate 条件、引用来源、Remediation | 等待上游、审查、批准及生效。 |
| 方案设计 | 状态、产物、测试证据、轨迹、Gate 影响 | 等待、生成设计、下游评审。 |
| 方案评审 Gate | 状态、产物、测试证据、轨迹、Gate 条件、引用来源、Remediation | 阻断与审查、批准进入实现。 |
| 开发实现 | 状态、产物、测试证据、轨迹、Gate 影响 | Executor、审批、managed worktree 修改、Diff、取消/恢复。 |
| 测试证据 | 状态、产物、测试证据、轨迹 | 真实测试命令、结果保存、失败与通过。 |
| PR 交付 | 状态、产物、测试证据、轨迹、Handoff | 准备、审批、精确分支发布、Draft PR 回执、重启与撤销。 |
| 业务验收 | 状态、产物、测试证据、轨迹、引用来源、Final Gate | 交付前阻止、验收包、审查、最终批准完成。 |

八个默认节点覆盖六个阶段、五种界面类型；底层 `agent` 和 `task` 均展示为 Task。
新增会话测试逐个读取这些节点，保留既有完整 Inspector 测试。打包交付测试在整条流程
实际完成后，再让新会话读取所有节点，核对测试、Coding、Delivery 和最终 Gate 的真实结果。

## 验证命令与证据

- `corepack pnpm verify`：类型检查、完整单元/组件回归、跨平台静态检查。
- `corepack pnpm test:e2e`：浏览器工作流与 Web 交互回归。
- `corepack pnpm test:electron-smoke`：真实 Electron 主进程、IPC、SQLite 和既有流程。
- `corepack pnpm test:native-coding-electron-smoke`：真实本地 HTTP 模型、Native 修改审批、worktree、测试、Diff、Trace、Evidence。
- `corepack pnpm test:workbench-conversation-electron-smoke`：新会话、全部节点和详情标签、双会话隔离、提案、失败重试、取消、冷启动、浅色及窄窗口。
- `corepack pnpm build:desktop-pilot` 后运行 `corepack pnpm test:v15-github-delivery-packaged-smoke`：打包应用、一次性 Postgres、离线 GitHub 服务和本地 bare remote，完整走到验收并查询所有已完成节点。

`delivery-report.json` 和真实 Electron 截图。视觉核对记录位于项目根目录 `design-qa.md`。
