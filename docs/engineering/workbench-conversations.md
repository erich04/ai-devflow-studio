# 工作流看板、节点详情与独立会话

初始实现基于 PR #127 的 `f11246c1c6b2be94ee7f12e8a91ae48f69a00d2d` 开发。
初始分支：`codex/unified-workbench-conversations-20260916`。
2026-09-26 候选布局已按 #171、#174、#175、#177 更新；下面的使用方式反映本次候选，历史验证不改写为新的全流程完成证据。

## 使用方式

左侧工作区按需求、方案、开发、测试、交付、验收展示六阶段导航及节点详情；右侧独立会话与左侧顶部对齐，独立滚动。上方阶段导航可定位阶段，流程视图和列表视图共用真实节点，不创建另一套状态。“正在查看”与“实际当前进度”分别标注。

节点详情保持“概览 / 内容与审查 / 产物与证据 / 执行记录”四个一级入口。标题、状态、页签和底部动作常驻；不再将整套节点工作区藏在一个折叠区中。正文按内容语义分组，证据与执行明细在相应页签查询。

右侧页签只管理独立会话。点加号先打开新建窗口，选择 Direct Provider（直接模型调用）或 OpenCode，确认后才建立会话；取消不会创建空会话或调用模型。“讨论此问题”和“向项目提问”使用同一创建流程，保留预填问题，由用户创建后自行发送，不把会话绑定到该节点。

常态会话布局是页签栏、消息区、输入框，不再常驻重复标题和会话信息头部。Token 用量放在会话顶部，按需查看明细；未返回、部分缺失与真实零值分别展示。
右键会话 Tab、按 Shift+F10 / 菜单键，或点击 Tab 的「…」，选择“会话详情”打开独立弹窗。
详情始终属于操作的那个 Tab；查看未激活会话不会切换当前聊天，也不重新挂载消息区或输入框。
关闭详情恢复入口焦点，保留原聊天草稿、滚动位置和进行中的请求。切换项目会关闭旧项目详情。

详情可以显式保存新名称，查看项目、状态、执行方式、上下文统计、旧版备注和实际模型调用记录。
下次发送使用 Agents 当前选中的模型；历史调用使用的模型以各条已保存记录为准，两者分别展示。
执行方式保存在各自会话中；更换方式请另建对话。详情内的小问号打开可关闭的详细说明，
解释共享与独立资料、保存提案、工具范围和权限。打开详情和说明不会触发模型调用或生成产物。

任何会话都能查询当前本地项目的其他节点和其他 Run。关闭 Tab 后可以从历史恢复；
不会取消仍在进行的调查。需要停止时使用对话里的“停止调查”。切换 Tab 不清空输入；
应用重启恢复历史、草稿、问题和执行方式，未完成的调用标记中断并等待用户重试。
旧版手动备注仍可查看，但已停用，不再加入模型输入。

## 调查与追问

会话使用 Agents 中安全保存的当前 Provider。Electron 主进程 运行最多 12 次调用、总时限
180 秒的只读调查循环。模型可以按问题选择真实工具：

| 工具 | 内容 |
| --- | --- |
| `workflow` | 最新 Run/节点状态，支持按标题搜索、按 Run 查询和分页。 |
| `node` | 任意节点的产物、测试、轨迹、Gate 检查，以及真实编码、权限和交付状态。 |
| `artifact` | 指定 Run 的产物正文，过长内容明确截断。 |
| `repo_list/read/search` | 当前本地仓库内的受限只读目录、文本读取和搜索。 |
| `knowledge` | 已配置的项目知识来源，保留读取时间、来源和内容摘要。 |

工具读取会留在本会话记录中。回答可以包含来源、节点跳转按钮、追问选项和提案预览。
选项填入输入框后由用户发送；也可以自由回答。用户转而询问其他节点时，旧问题继续待答。
对话中的导航按钮重新校验真实目标，使用既有节点工作区和执行入口。

每次调用适配现有 Provider 的 32,000 字符输入契约：较早消息、过长查询和流程摘要按需限制，
完整历史仍保留。消息计数和实际容量限制移入按需打开的会话详情；失败、重试、追问和取消
仍在聊天中处理。上下文选取和持久化机制不变，详情明确只有消息数量和容量限制记录，
没有完整的逐条输入追踪。这里没有宣称无限上下文或自动摘要记忆。
只记录 Provider 实际返回的 token，未返回或部分缺失时明确显示，费用不填虚构数字。
失败保留中文恢复提示，以及可展开的阶段、错误代码和 HTTP 状态诊断。

## 共享与隔离

共享查询来源是最新流程、已保存产物和证据、仓库代码与项目知识。
每条会话的历史、待答问题和未保存提案相互隔离。会话表只在本地 SQLite 中存在，
不加入 Team 同步、远端概览或 `loadState()` 的共享工作流数据。

点击“保存为节点提案”后，只把展示出来的提案保存到指定节点，标记“待确认”。保存与会话
引用原子提交，并使用版本检查防止并发覆盖。后续阶段生成可以读取这份提案；仍需通过原有
正式产物、测试和人工 Gate。聊天不会直接批准 Gate、修改代码或发布 PR。

读取工具不执行 shell，不读取其他项目或会话，不跟随符号链接，不读取凭据/环境变量文件。
通用业务数据库、任意 MCP 调用和新的 编码执行器不在本次会话工具中。
原有 Direct Provider、OpenCode 和 Native Coding 的正式工作流入口继续保留。

## 所有节点的覆盖范围

所有节点共用四个一级页签，内容按节点职责呈现：

| 节点 | 内容重点 | 执行与状态覆盖 |
| --- | --- | --- |
| 需求澄清 | 澄清正文、验收标准、来源与修订 | 初始、调查/追问、生成澄清、版本化产物。 |
| 需求确认 Gate | 审批核对清单、被审查澄清与审查意见 | 等待上游、审查、批准及生效。 |
| 方案设计 | 实现方案、验证计划、交付与风险 | 等待、生成设计、下游评审。 |
| 方案评审 Gate | 核对清单、设计正文、审查意见与处理入口 | 阻断与审查、批准进入实现。 |
| 开发实现 | 变更、差异与测试证据，权限和执行轨迹 | 执行器、审批、托管工作树修改、取消/恢复。 |
| 测试证据 | 测试结果、输出证据和执行记录 | 真实测试命令、结果保存、失败与通过。 |
| PR 交付 | 交付包、就绪情况与发布证据 | 准备、审批、精确分支发布、草稿 PR 回执、重启与撤销。 |
| 业务验收 | 验收资料包、上游交付证据与最终决定 | 交付前阻止、验收包、审查、最终批准完成。 |

八个默认节点覆盖六个阶段、五种界面类型；底层 `agent` 和 `task` 均展示为 Task。
新增会话测试逐个读取这些节点，保留既有完整节点详情测试。打包交付测试在整条流程
实际完成后，再让新会话读取所有节点，核对测试、编码、交付和最终 Gate 的真实结果。

## 验证命令与证据

- `corepack pnpm verify`：类型检查、完整单元/组件回归、跨平台静态检查。
- `corepack pnpm test:e2e`：浏览器工作流与 Web 交互回归。
- `corepack pnpm test:electron-smoke`：真实 Electron 主进程、IPC、SQLite 和既有流程。
- `corepack pnpm test:native-coding-electron-smoke`：真实本地 HTTP 模型、Native 修改审批、工作树、测试、差异、轨迹和证据。
- `corepack pnpm test:workbench-conversation-electron-smoke`：新会话、全部节点和详情页签、双会话隔离、提案、失败重试、取消、冷启动、浅色及窄窗口。
- `corepack pnpm build:desktop-pilot` 后运行 `corepack pnpm test:v15-github-delivery-packaged-smoke`：打包应用、一次性 Postgres、离线 GitHub 服务和本地裸仓库远端，完整走到验收并查询所有已完成节点。

本次运行记录保存在 `out/workbench-conversation-qa/`，包括 `report.json`、
`delivery-report.json` 和真实 Electron 截图。视觉核对记录位于项目根目录 `design-qa.md`。
浏览器与会使用 Next 的 Electron 测试应顺序运行，避免共享 `.next` 开发缓存引起页面刷新。

这些自动化测试使用隔离数据和受控模型/GitHub 服务，没有向用户的 GitHub 仓库发布修改。
真实 DeepSeek 联调另行区分：`scripts/workbench-conversation-live.mjs` 是需显式启用，
只尝试在一次性数据目录中使用指定的已有加密凭据，不打印密钥、不修改源数据库。
联调启动器使用正常系统钥匙串，移除 Playwright 的模拟钥匙串参数，并限制最多 4 次 HTTP
请求。本次 `deepseek-flash` 实际调用 3 次完成代码读取、任意节点查询、来源和跳转按钮，
结果与真实 token 保存在 `live-report.json`。同时修复并回归了“JSON 字符串内含 Markdown
代码示例被误拒绝”的兼容问题。原始演练数据和代码未作为可写测试数据使用。
