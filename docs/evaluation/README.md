# Native v3：真实任务对照与证据

当前状态：**2026-10-12 按用户要求暂缓所有付费模型测试，仅保留不调用模型 API 的验证。** 2026-10-27 用户另行授权一轮 $3 上限的小样本 `comparison-20261027-r8`，已结束：10 道题、31 次观测，三个执行器都没有通过独立验收，Native v3 有 5 次错误成功（见[真实模型验收记录](native-coding-v3-live-20261011.md)）。之后仍按暂缓处理。 31 项题目资格和公开测试计划已验证；此前真实端点与 8 类交互/故障检查通过，代码提交 `26f0cda` 的六项平台 CI 全部通过。完整对照尚未完成：r6 保留 21／93 次观测，r7 保留 5／93 次观测，两轮都遇到 HTTP 402；现阶段即使提供方恢复可用，也不自动续跑。所有尝试和费用保留，不将受服务中断影响的样本解释为整体通过率。实际过程见[真实模型验收记录](native-coding-v3-live-20261011.md)。

当前可继续的验证包括类型检查、使用脚本化模型响应的循环/权限/恢复测试，以及真实 Git、文件系统、子进程、数据库和 Electron 集成测试；这些检查不需要付费模型。后续如重新进行真实模型验证，须先确定小样本范围与明确的共享总金额上限，再取得用户同意；可以从 1–2 项小型 Native v3 场景开始，限制上下文、调用数及输出长度。小样本只验证端到端接线，不能代替原 31 题 × 3 执行器的能力比较，也不改写既有实验的规则或成绩。

## 复验题目

```sh
node scripts/native-coding-evaluation.mjs qualify docs/evaluation/native-coding-v3-tasks.json out/native-v3-evaluation/new-qualification
```

也可以在最后追加一个或多个任务 ID。脚本在独立临时目录导出精确基线及参考版本，将参考验收测试放入验证副本，按各自 lockfile 安装依赖后实际运行。没有挂载开发仓库的 node_modules，也不向历史测试传递模型密钥等环境变量。目录是新建的；失败事实保留，不能覆盖旧输出假装首次通过。

这一步只验证题目的基线/参考测试。行为任务说明根据相应提交的公开问题和新增行为断言整理，不改变已有资格结果，也不把资格通过解释为提示已完成实测。历史回归题之外的[交互与故障实验规程](native-coding-v3-interactive-protocol.md)单独覆盖深层调查、澄清、插话、恢复、子任务、文件变更和证据失效；不能用一个总通过率遮盖未测类别。

## 三执行器运行规则

`scripts/native-coding-public-plans.mts qualify <公开计划> <新目录>` 使用真实命令执行器、隔离 Git 基线和冻结依赖安装，先证明每条公开保存命令可运行。报告保留通过/跳过数、进程收据、日志摘要及执行代码摘要。冻结实验前必须存在覆盖全部 31 题的匹配资格结果；不得根据模型输赢省略题目。完整产品仓库的发布、历史和元数据测试仍由产品 CI 运行。

已有明确基线失败时，可在命令末尾追加任务 ID，在新目录复验；原输出不覆盖，完整冻结仍要求全部 31 项结果。首次公开资格检查中，30 号题的已有 HTTP 引擎套件出现 58 条通过、1 条虚拟时钟超时，随后同条件一次复验 59 条全部通过。断言与任务均未修改，两次结果同时保留。这一基线时序波动是实验限制，正式模型试验不会据此获得重试或额外提示。

此前实验使用用户指定的 DeepSeek V4.1 Flash；当时的不限费用授权已被 2026-10-12 的暂缓付费测试要求取代，不能用于继续调用。官方 `/models` 实际返回 `deepseek-flash` / `DeepSeek-V4.1-Flash`。密钥通过独立私有文件注入，不能存入本仓库或候选工作区。已冻结实验中的每题额度仅用于解释历史记录，不代表当前允许花费。

真实端点检查输出在 `out/native-v3-evaluation/endpoint-20261011-r1/`：思考 high / 非思考 × SSE / 非流式四组全部通过，每组含两轮工具调用及结构化 JSON；20 次实际调用，用量 6,929 输入 / 645 输出 token，按当前公开单价计算 $0.001874268。账本没有未知费用。这是端点兼容性结果，不是编码解题结果或账户账单。

`scripts/native-coding-trial-live.mts` 通过生产 `CodingRuntime`、Native v2/v3 或 OpenCode HTTP 适配层执行；每次模型调用经过 `governAgentProvider` / `createGovernedOpencodeProxy` 和独立持久化账本。OpenCode 仅取得本地转发令牌。三个执行器均使用隔离项目，不连接用户日常团队数据库。

`scripts/native-coding-batch-live.mjs freeze <新目录>` 封存输入、代码提交、评测器摘要、阈值和操作规则；`run <已封存目录> <私有密钥文件>` 执行并独立评分。候选只取得无远程地址、无历史后续提交的基线及行为要求；独立验证恢复原测试和配置，再叠加参考断言。输入或代码变化必须建立新实验，不覆盖失败记录。付费脚本不在 CI 中自动运行。

批次开始前通过官方可用性接口检查提供方；记录可用状态，不记录账户金额或凭据。运行中观察到明确的 HTTP 401／402 时停止派发，已有任务按原规则结束并保留记录。Native 子任务额外权限与父任务一样拒绝；没有预先给定答案的子问题会结束该次历史任务，不编造回答，也不因父任务仍在等待而空转到截止时间。

这是 **DevFlow 当前集成配置** 的同模型对照：Native v2 保留原 4,096 输出上限和固定流程，v3 使用 high 模式输出上限与 80 步累计限制，OpenCode 适配层保留 24 次工具调用上限。不能据此给原生 Agent 排名，也不能单独把所有差异归因于“是否多轮”。读工具统计包括调查、差异和命令输出读取；修复次数统计再次提交的冻结修订，不等于冻结前所有编辑/测试循环次数。

实验前记录并冻结：候选代码提交、31 项合格任务的输入、各执行器及模型版本、每题/总费用或 token 上限、环境、工具/网络范围、重试与人工介入规则、重复次数和验收阈值。同模型优先；不同模型分组报告，不把模型差异归于 Harness。保留任务不能参与提示或默认阈值调参。

候选仓库只得到基线和任务说明，不能得到参考 SHA、参考补丁或隐藏验收文件。真实调用必须经过 DevFlow 的预算和执行入口。独立验证副本由评价程序/操作者持有，覆盖参考验收及保护测试配置；不能让模型删改测试或配置后仅用退出码判成功。发生不确定请求时保留原收费事实，额外 attempt 同样计入预算。

每个 trial 保存 Coding Run、最终内容摘要、原始模型/工具日志引用、独立验收输出、费用账本及环境摘要。`independentPassed` 必须来自独立验收，不能复制模型的完成声明或宿主批准状态。

## 评分数据

`runs.json` 是观测记录数组，每行至少包含：

```json
{
  "taskId": "devflow-history-02",
  "engine": "native-v3",
  "trial": 1,
  "provider": "实际提供方",
  "model": "实际模型版本",
  "claimedCompleted": false,
  "independentPassed": false,
  "costUsd": null,
  "durationMs": 1000,
  "metrics": {
    "humanInterventions": 0,
    "inputTokens": null,
    "outputTokens": null,
    "peakContextTokens": null,
    "effectiveInvestigationSteps": 0,
    "repairAttempts": 0,
    "recoveryAttempts": 0,
    "recoverySuccesses": 0
  }
}
```

上面仅是格式示例，不是本次观测。未知费用和指标写 null；未执行不能填 0 或通过。实际记录另保留证据引用。三个执行器使用相同 trial 编号；不完整重复、重复记录和不同模型比较都必须可见。

```sh
node scripts/native-coding-evaluation.mjs score docs/evaluation/native-coding-v3-tasks.json runs.json docs/evaluation/native-coding-v3-qualification-20261011.json new-score.json
```

评分包含观察/缺失数量、独立通过率与区间、误报成功、父子合计费用、未知费用、用时、人工介入、上下文/调查/修复/恢复指标，以及同模型的 v2/v3 配对结果。全部候选都保留在报告；未执行/不合格项不伪造完成率。需要只对合格题计算比较时，先冻结一个明确的合格子集输入及其摘要，同时保留全量资格报告。

`releaseReady` 始终不由这份统计工具自动变成 true：它无法单独证明观测来源、预授权费用、真实端点兼容或跨平台行为。发布评审须核对原始工件与预先冻结的门槛。少量任务零误报不代表现实错误率为零。
