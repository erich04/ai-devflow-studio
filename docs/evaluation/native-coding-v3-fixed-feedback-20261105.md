# Native Coding v3 固定验收反馈模式

2026-11-05，用户明确选择“给失败反馈，让 V3 继续修，先跑通十题”。下一轮使用宿主冻结的原验收用例，把实际失败原因返回 V3，允许它在原有额度内继续修改并重新提交。该模式单独记录，既有盲测结果保留。

## 实现范围

- 原十道题的题面、基线、公共测试命令、参考验收文件及模型配置保持原值。每题最多 15 分钟、80 步、192 次调用，单次输出上限 65,536 token，整轮费用上限为 2.70 美元。
- 宿主接收按原文件路径和内容摘要冻结的测试包，绑定本次目标、批准来源和基线。模型无法通过编码工具替换这份测试包。目标变更后需要重新绑定验收来源，当前任务会暂停。
- 固定模式直接使用这份测试包。原生成式私有验收路径继续服务未提供固定测试的任务。
- 每份修订在分别拥有的验证目录里运行公共测试与固定测试。固定测试目录从该修订的精确内容生成，恢复基线的测试配置并覆盖原固定验收文件。固定测试由实际 Vitest 入口运行，完整报告由宿主留存。模型收到文件名、失败用例和有长度限制的错误信息。
- 必须执行全部指定文件，实际用例数必须等于原资格记录的数量，所有用例通过，运行期间源码保持一致，才允许完成交付。测试跳过、模块加载错误、缺失报告、失败或取消均不能放行。
- 固定模式允许超过三次失败后继续修复，共享原任务步数、活动时间、墙钟和费用限制。可信基线的依赖准备也计入本次限时。最终独立外部评分继续分别观察交付 D 和候选 C。

宿主测试包属于评测适配器提供的可选输入。本次沿用正常 V3 会话、权限、工具、修订审批和事务交付入口。

## 回归覆盖

新增实际 Node、Vitest、SQLite 和 Git 路径测试，模型端使用确定性替身，依赖安装复用本地测试框架。

- 连续四次固定验收失败后，模型收到具体原因并修改代码。重启后仍按持久化的同一测试包验证，通过后才交付。
- 候选修改测试文件或运行配置，固定验收仍使用批准版本。
- 跳过用例、数量不符、模块加载失败和验证过程修改源码均被拒绝。
- 原步数限制仍生效。依赖准备耗尽活动时间时中止进程，模型尚未调用。
- 运行中的固定测试可以取消，验证进程结束后清理副本，原交付保留。
- 测试包内容不可替换，新的目标不能复用旧验收。默认生成式验收继续执行自己的既有回归。

## 沙箱内的包管理器缓存

R11 的 11 题曾在下载 pnpm 本体时遇到 TLS 连接错误；[R12](native-coding-v3-phase2-r12-20261105.md) 的 03 题又在同一位置遇到 DNS 错误。原执行器每条沙箱命令使用独立 HOME，基线的 pnpm 包存储 seed 不包含 Corepack 的 pnpm 本体。

新会话使用依赖缓存版本 2：为明确固定 pnpm 版本的项目绑定工作副本内的 `.cache/devflow-corepack`，缓存位置也进入命令和依赖计划摘要。旧会话的版本 1 及未启用缓存的计划保持原语义。候选、公共验证、固定验证各持独立可写副本；只有成功准备依赖且尚未执行私有检查的 B 可以发布 seed。包存储与包管理器均逐文件验证摘要，最终 V 不读取 C 的缓存。

## 可恢复的编辑前置条件错误

R13 的 05 在固定反馈返回后连续修改失败。原记录显示模型把 `agent-memory-projection.ts` 的 64 位 SHA-256 抄成了 63 位，漏掉一个字符；它在多次重新读取到正确摘要后仍复用了抄错的参数，最后尝试旧摘要和整个工作区的 revision。原补丁片段实际只匹配一处。文件保护正确拒绝了写入，但通用 Native Tool 注册层把具体原因统一隐藏为 `handler_failed`，模型最终误认为该路径的编辑通道失效并停止。

新逻辑只保留三类写入前已知错误的安全说明：文件摘要不匹配、补丁片段不存在、补丁片段不唯一。摘要错误返回当前文件的完整摘要及重新读取提示；不跳过校验、不自动替换参数。权限、单次 grant 消耗、失败审计与未知效果恢复继续由原注册层负责，任意其他异常仍使用原脱敏错误。安全说明按具体操作绑定，取消及其他错误不能被覆盖。

回归在修改前得到笼统错误，修改后验证旧摘要、63 位抄错摘要、零匹配和多匹配均拒绝且不改文件；重新读取并明确提交正确摘要后编辑成功，越界路径的任意错误仍被隐藏。30 项相关回归通过。

使用 05 保存的原文件字节和原失败参数，在两个临时独立副本中分别运行冻结版本与修复版本：前者返回 `handler_failed`，后者返回确切的摘要不匹配；两边只纠正摘要都能成功应用同一补丁。原评测源码 SHA-256 前后不变、零模型调用，临时副本已删除。原版证明保存在评测工作区 `out/phase2-fixed/edit-conflict-original-replay.json`，新版证明在开发工作区 `out/phase2-fixed/edit-conflict-fixed-replay.json`。这项诊断不改变 R13 的 05 原成绩。
