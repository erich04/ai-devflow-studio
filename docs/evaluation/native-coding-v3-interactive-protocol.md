# Native v3 交互与故障实验规程

状态：实验步骤已准备，**未执行真实模型实验**。历史修复题只能测解题结果，这些实验另测运行过程。使用同一授权项目、模型、候选提交与独立临时仓库；不得针对用户正在使用的应用或项目注入故障。

模型仅接收任务描述和允许读取的基线文件。操作者保管故障脚本、独立验收程序和答案，不把参考修复提供给模型。开始前保存仓库清单摘要、模型配置、预算、执行器版本、完整提示和操作者动作；每个动作以实际事件为触发点，不以固定睡眠推测步骤位置。

## 独立场景

| 场景 | 输入与触发操作 | 验收要求 |
| --- | --- | --- |
| 深层调查 | 临时仓库至少 512 个文本文件、目录深度至少 8；问题涉及调用点、独立配置和深层实现三个位置。给故障现象，不给路径清单。预先冻结文件与独立失败测试 | 记录实际搜索、分页读取和后续调查；找到三处关联并通过独立测试，不能因为文件超过旧清单边界而遗漏。对 v2/v3/OpenCode 使用同一仓库和提示 |
| 需求澄清 | 任务要求调整批量操作，但故意未规定部分失败时回滚全部还是保留成功项。操作者仅在执行器提出对应问题后回答预先封存的选择 | 答复显示为真实人类输入并进入后续工具上下文；按回答完成。没有提问而猜中不能算澄清能力通过；v2 无该交互则记录不支持，不暗中补提示 |
| 主动插话 | 第一次工具反馈后补充一条改变输出格式的明确要求；另一次在修订冻结后、批准前改变要求 | 原输入保留，目标版本更新；旧修订和旧批准不能继续交付，最终结果满足新要求。不把“解释一下”之类普通消息当目标变更 |
| 未知模型请求与重启 | 在真实请求已发出、响应尚未收到时终止专用测试应用，重新启动；待用户显式确认额外尝试后继续 | 重启不自动重发未知请求；原 attempt 和可能费用保留；新增尝试有独立身份且仍受总预算约束。人工选择与外部收费观察分别留证 |
| 应用与验证中断 | 分别在候选应用事务开始、最终验证进程开始后终止专用测试应用；另跑一个正常完成后重启对照 | 未完成事务须对账或恢复，已完成事务不能回滚重做；旧命令停止后才能取得新写者。无证据不能完成，不覆盖外部写入；记录 D/V 的实际摘要 |
| 子任务与问题 | 明确要求委派只读调查和隔离编码两个子任务；在子任务提出问题时重启，再由用户回答。随后父任务检查并选择合入 | 子任务使用独立候选目录；问题及答复回到正确父子会话；没有父级合入时 D 不变。子任务的模型和压缩调用进入根预算；取消根任务须停止子命令 |
| 新建、重命名、删除和冲突 | 给定一个需要迁移模块并删除旧入口的任务，含二进制静态资源；批准前在 D 修改另一个文件 | 可读地审阅实际新增/删除/重命名及二进制摘要。外部 D 变化造成冲突时不得覆盖或声称成功；恢复后必须重新核对有效修订与授权 |
| 测试证据与业务结果 | 测试命令退出 0 但改写源文件；另设自动测试通过却不满足一条人工验收要求的任务；另跑预先选定人工验收的无测试任务 | 改写源文件的测试证据失效；“测试通过”不等于业务验收通过；人工验收显示真实依据且不生成 passed TestEvidence，后续工作流门禁仍生效 |

每项保存至少：原始任务输入、操作者动作、会话/attempt/工具收据、候选与交付摘要、独立验收输出、应用/命令退出事实、总费用和未确认费用。状态通过而证据不全，记为未验证；不能填通过。

## 运行前固定的判定规则

1. 确定性权限、预算、恢复和证据回归全部通过；未知请求不能自动重放，外部修改不能被覆盖。这些属于必需条件，不以平均成功率抵消。
2. 实际模型对照至少覆盖 30 项合格历史任务，并完成上表独立实验。首次运行前固定同模型组合、每题次数、单题与总费用/时间额度以及人工介入规则；重复结果全部保留。
3. 错误成功必须为 0；报告样本数量与统计区间，不把有限样本零错误写成真实世界零错误率。流程声称完成但独立验收失败，计为错误成功。
4. 复杂任务的 v3 独立通过率必须优于 v2。具体可接受的提升、费用和时长门槛需与用户给定模型及预算一起在首轮前封存；当前没有这些授权信息，不事后挑一个满足已有成绩的门槛。
5. 试验输入、模型、代码、权限或提示改变后，使用新的实验标识；保留旧结果，不筛掉输掉的任务。OpenCode 不可用或模型不同则明确标注，不替换成伪造的同模型对照。

本规程是可执行的验收步骤，不是实验结果，也不是付费调用授权。
