# Native v3 交互与故障实验规程

状态：**历史真实模型的 8 类场景已有记录；历史题完整对照仍未完成并暂停付费续跑**，结果见[真实模型验收记录](native-coding-v3-live-20261011.md)。历史修复题只能测解题结果，这些实验另测运行过程。使用同一授权项目、模型、候选提交与独立临时仓库；不得针对用户正在使用的应用或项目注入故障。

模型仅接收任务描述和允许读取的基线文件。操作者保管故障脚本、独立验收程序和答案，不把参考修复提供给模型。开始前保存仓库清单摘要、模型配置、预算、执行器版本、完整提示和操作者动作；每个动作以实际事件为触发点，不以固定睡眠推测步骤位置。

## 独立场景

| 场景 | 输入与触发操作 | 验收要求 |
| --- | --- | --- |
| 深层调查 | 临时仓库至少 512 个文本文件、目录深度至少 8；问题涉及调用点、独立配置和深层实现三个位置。给故障现象，不给路径清单。预先冻结文件与独立失败测试 | 记录实际搜索、分页读取和后续调查；找到三处关联并通过独立测试，不能因为文件超过旧清单边界而遗漏。对 v2/v3/OpenCode 使用同一仓库和提示 |
| 需求澄清 | 任务要求调整批量操作，但故意未规定部分失败时回滚全部还是保留成功项。操作者仅在执行器提出对应问题后回答预先封存的选择 | 答复显示为真实人类输入并进入后续工具上下文；按回答完成。没有提问而猜中不能算澄清能力通过；v2 无该交互则记录不支持，不暗中补提示 |
| 主动插话 | 第一次工具反馈后补充一条改变输出格式的明确要求；另一次在修订冻结后、批准前改变要求 | 原输入保留，目标版本更新；旧修订和旧批准不能继续交付，最终结果满足新要求。不把“解释一下”之类普通消息当目标变更 |
| 未知模型请求与重启 | 在真实请求已发出、响应尚未收到时终止专用测试应用，重新启动；待用户显式确认额外尝试后继续 | 重启不自动重发未知请求；原 attempt 和可能费用保留；新增尝试有独立身份且仍受总预算约束。人工选择与外部收费观察分别留证 |
| 应用与验证中断 | 分别在候选应用事务开始、最终验证进程开始后终止专用测试应用；另跑一个正常完成后重启对照 | 未完成事务须对账或恢复，已完成事务不能回滚重做；旧命令停止后才能取得新写者。无证据不能完成，不覆盖外部写入；记录 D/V 的实际摘要 |
| 子任务与问题 | 明确要求委派只读调查和隔离编码两个子任务；在子任务提出问题时重启，再由用户回答。随后父任务检查并选择合入 | 子任务使用独立候选目录；问题及答复回到正确父子会话；没有父级合入时 D 不变。子任务的模型和压缩调用进入根预算；取消根任务须停止子命令 |
| 新建、重命名、删除和冲突 | 给定一个需要迁移模块并删除旧入口的任务，含二进制静态资源；批准前在 D 修改另一个文件 | 可读地审阅实际新增/删除/重命名及二进制摘要。外部 D 变化造成冲突时不得覆盖或声称成功；恢复后必须重新核对有效修订与授权 |
| 测试证据与业务结果 | 测试命令退出 0 但改写源文件；另设自动测试通过却不满足一条人工验收要求的任务；另跑预先选定人工验收的无测试任务 | 改写源文件的测试证据失效；“测试通过”不等于业务验收通过；人工验收显示真实依据且不生成 passed TestEvidence，后续工作流门禁仍生效 |

每项保存至少：原始任务输入、操作者动作、会话/attempt/工具收据、候选与交付摘要、独立验收输出、应用/命令退出事实、总费用和未确认费用。状态通过而证据不全，记为未验证；不能填通过。

## 运行前固定的判定规则

1. 确定性权限、预算、恢复和证据回归全部通过；未知请求不能自动重放，外部修改不能被覆盖。这些属于必需条件，不以平均成功率抵消。
2. 实际模型对照至少覆盖 30 项合格历史任务，并完成上表独立实验。首次运行前固定同模型组合、每题次数、单题与总费用/时间额度以及人工介入规则；重复结果全部保留。
3. 错误成功必须为 0；报告样本数量与统计区间，不把有限样本零错误写成真实世界零错误率。流程声称完成但独立验收失败，计为错误成功。
4. 复杂任务的 v3 独立通过率必须优于 v2。历史不限金额授权已在 2026-10-12 暂停付费测试时失效；2026-10-16 的有限缓存复验不等于重新授权完整对比。新一轮必须明确项目、Provider、总金额与调用次数；具体提升、费用和时长门槛在实验 `experiment.json` 中于首轮前封存，不事后挑一个满足已有成绩的门槛。
5. 试验输入、模型、代码、权限或提示改变后，使用新的实验标识；保留旧结果，不筛掉输掉的任务。OpenCode 不可用或模型不同则明确标注，不替换成伪造的同模型对照。

本规程是可执行的验收步骤，不是实验结果，也不是付费调用授权。

## 交互脚本的整轮预算（2026-10-16）

`native-coding-interactive-live.mjs` 现在先初始化一轮预算，再把初跑和重跑放在该轮下。原先的「输出目录 + 密钥文件」命令已拒绝执行。以下数字只是操作示例，执行前仍须有该轮授权；`init` 不读取密钥、不请求模型。

```sh
# 一次性冻结这一轮的总金额与总调用次数，不允许覆盖已有目录。
node --import tsx scripts/native-coding-interactive-live.mjs init out/interactive-round 1 200
# 全部 12 个交互场景，共用上述额度。
node --import tsx scripts/native-coding-interactive-live.mjs run out/interactive-round first /private/path/key
# 只重跑选定场景；换 attempt 名称不会恢复额度。
node --import tsx scripts/native-coding-interactive-live.mjs run out/interactive-round retry /private/path/key unknown,children,child_cancel
```

权威账本是轮次目录中的 `budget.sqlite`，使用 Node 24 自带 SQLite 的立即事务；初跑、选定场景重跑、父子任务、恢复 worker 及同时启动的独立进程都对同一账本原子准入。`round.json` 固定身份、模型、价格版本、最大输出量和限额；修改金额或次数（提高、降低均包括）会被拒绝。普通运行遇到缺失账本时直接失败，不能自动新建。创建另一个轮次就是另一笔预算，须另获授权；禁止用删除或新建轮次规避旧预算。

每次预留先计入完整的已验证请求费用上界，再调用 provider。请求是否送达不确定、取消或用量不完整时，预留一直保留；确认 `not_sent` 才记费用为 0，且调用次数不退还。完整用量结算只替换该次预留，不重放模型请求。无已验证上界的报价拒绝执行，不使用估算值承诺硬上限。父子会话的请求预算金额也使用同一冻结限额。

当前 `deepseek-flash`、最大输出 65,536、上下文容量 1,048,576 的单次预留约 $0.393216（以冻结价格版本为准），通常高于实际费用。未知调用累积后，一轮 $1 的预算可能在跑完所有场景前停止；这是正确的预算阻断，不能为了让场景通过而提高原轮次限额。脚本发现余额不足时不会启动下一个场景的 worker，并以非零退出码报告阻断；场景内部每次调用仍独立受原子准入约束。

`attempts/<名称>/` 保存该次配置、故障记录、结果与日志。每场景 `ledger.json` 仅是带 `readOnlyProjection` 标记的导出，不参与准入。每次运行的 `round-budget.json` 是带观察时间的整轮快照，列出 `knownCostUsd`（已知费用）、`unknownCosts`、`reservedUsd`（未释放预留）、`accountedUsd`（已知费用加预留）、总次数及各场景分项；不能把已知费用当成整轮占用。并发运行结束时间不同，报告快照可能不同，以权威账本为准。

本次门槛**仅覆盖这个交互入口**。`native-coding-batch-live`、`trial`、`endpoint`、`deep` 与 `native-conversation-live` 的历史独立账本未迁移，不能宣称已有整轮 $1 上限，也不能据此直接恢复 31×3 收费比较。完整历史题验收及其预算改造仍是后续工作。
