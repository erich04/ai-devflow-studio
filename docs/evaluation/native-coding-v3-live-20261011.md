## 实测问题与修复

1. 长命令快速轮询耗尽步骤：`read_command` 支持可中止的有界等待，默认 10 秒，每次仍记录实际工具调用。运行中没有新输出不伪装成完成；暂停等待不擅自重新启动命令。
2. 应用事务回滚后继续：改为核对候选/交付摘要及目标/策略版本，重新展示同一修订并等待新的批准；不让模型重复发送完成说明，不重放旧批准。内容漂移进入冲突。
3. 不同措辞的完成说明：文本本身不计为执行进展；缺乏新行动和结果时按无进展暂停，不能跑满 80 步才停止。
4. HTTP 200 的无效模型输出：已收到回复和用量时保留为已完成但无效的 attempt，暂停为 `invalid_model_response`；不误标未知交付，也不执行其中内容。真正未知的请求仍须另行授权。
5. 子任务问答后父任务只看见旧等待记录：增加明确标注来源的宿主状态通知，让父任务重新收集子任务结果；关机保留持久等待状态。`await_task` 和其他暂停型控制工具一样必须单独调用；非法批次先整体拒绝并闭合所有配对，不插入半截对话。
6. 评测驱动修正：对正在变化的任务，取消/暂停可有界刷新版本；批准和未知模型请求不因此自动重试。报告读取 v3 的实际 Harness 状态，失败而被删除的 D 不再丢掉整次评分。每次变更后使用新实验标识。
7. 真实命令临时目录：曾把 `TEMP/TMPDIR` 指向深层私有 HOME，实测 Node socket 返回 `EINVAL`；目录还落在外围 Git 树中。现使用短、私有、带归属标记的临时目录，HOME 继续隔离。停止得到确认后才清理；无法核对归属或进程状态时保留并交给恢复处理。POSIX socket、Windows 命名管道和取消/归属恢复有实际命令回归。
8. 多轮工具反馈：搜索现在区分无匹配文件、无文本命中与分页结束，返回实际页容量和截断信息；模型收到父子共享的剩余步骤/时间，但没有额外额度。v3 Coding Brief 区分初始候选编辑授权和最终修订批准，保留用户与仓库原指令。`cancel_command` 只停止当前任务拥有的指定命令，保留真实终态；不依据孤立 PID 杀进程。
9. 公开计划资格：隔离输入故意不包含未来 Git 历史，因此不能把全仓库发布/来源测试当作每题保存命令。改为同一套固定的局部基线回归，在实际命令环境逐题先验；独立评分仍覆盖原参考验收。不是删除失败的隐藏测试，也不把局部回归称为全仓库验证。
10. 结构化结果脱敏与恢复：对已编码 JSON 做文本脱敏，会在 `"alpha"/"beta"` 这类内容附近吞掉引号前的转义，导致宿主解码失败。工具现在先对结构化叶子脱敏，再序列化；对账返回也保持脱敏。若冻结效果已持久化且对账确认完成，恢复分支同样进入人工审查，不再让模型重复“等待批准”直至无进展暂停。实际工具与 SQLite 循环回归均先复现再通过。
11. 交互驱动：产品递归展示子任务自己的问题/权限卡。复验驱动补齐对子权限卡的同一拒绝规则，不替用户回答新问题，不扩大已授权命令范围。旧的子任务超时仍保留。

探索轮 `comparison-20261011-r1/r2/r3/r4` 的所有真实尝试继续保留，停止调度时让活动任务结束。它们不能混入正式轮成绩，也不能因失败被抹掉。r1 暴露命令轮询；r2 暴露真实中断后的审批恢复和错误状态分类。r3 暴露子任务工具配对边界；r3/r4 还显示脚本等待整个会话时未落实声明的 15 分钟截止，已改为独立的操作截止与实际中止，旧数据不并入正式成绩。保留集断言未进入模型输入，也未用于修改任务提示。
