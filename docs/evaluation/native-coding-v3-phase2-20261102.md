## 冻结约束

- 输入取自本机 `comparison-20261027-r8/experiment.json` 与 `runs.json`，只重跑原来有 Native v3 观察的 `devflow-history-02` 至 `11`，顺序不变。原需求、基线、公开测试、参考提交和隐藏验收保持原样。
- 使用已保存的项目开发 DeepSeek 提供方，模型 `deepseek-flash`、thinking high。用户已授权开展第二阶段及必要权限；本轮 **3 美元总上限由执行者主动设置**，不是把历史 r8 的一次性预算当作新授权。开跑前冻结提交、运行器摘要、规则、每题限制及预算；凭据不进仓库、模型输入和报告。
- 一次只跑一道题，每题最多 80 步、192 次调用和 15 分钟。实际调用沿用产品治理协议，未知费用按预留上界计入总额，禁止自动重试未知交付。余额/认证错误、运行器失败立即停止后续分发。
- 使用系统沙箱，明确开启依赖安装所需 IP 网络，额外命令使用冻结的字面 argv 规则。额外询问默认拒绝，澄清问题不编造答案；精确修订批准只允许进入产品验收。记录主任务及所有子任务的询问、自动允许和自动拒绝次数。
- 独立检查作者只见 B 和已批准需求，隐藏参考测试不进入任何模型输入。外部评分恢复基线测试及配置，再覆盖原参考测试；同样在 OS 沙箱运行，不把评分失败反馈给实现者。
