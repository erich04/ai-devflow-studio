## 用量问题诊断

按以下可证伪假设验证：

1. 预算代理结算没有写入 Coding Run（代码中已发现缺口）；以真实 HTTP 代理 → SQLite → UI 汇总回归复现。
2. 旧执行快照或取消状态覆盖最新消费；验证幂等结算、取消后的迟到用量和重启回读。
3. 缺失/部分用量被显示为零或免费；验证保留未知金额和不完整 token 提示。

初始代码证据：coding budgetProxy 没有 call reporter；local-store 仅为 Native 的 trace 累计费用；顶部仅汇总持久化 runtimeCostSummary。

## 公共接口变化

- `main.ts` 仅为编码治理代理增加归属/费用回调；同一次项目执行器解析返回配置版本和执行器，传入新增内部 `CodingRuntimeDeps.executorConfigVersion`。新建预留与后续执行器快照保留可信版本，避免实际 Electron 创建链路丢失版本后被代理拒绝。未修改 IPC、preload 或共享运行类型。
- `OpencodeHttpCodingEngineConfig.onSessionCreated` 在父会话核验后、首调用前登记可信父会话；私有插件提供 4 个内部 scope 头。`createCodingRelayCallContext` 再核对 Coding Run、工作树、用户、Provider 和配置版本，将父子实际 HTTP 调用写入已有事件及费用投影。预算预留 ID 在发送前持久化，崩溃恢复复用同一 ID。
- 治理代理新增可选 `resolveCodingCall(session): Promise<CodingRelayCallContext>`，上下文只提供既有 operation 和 report 回调。四个私有头为 `x-devflow-coding-run`、`x-devflow-root-session`、`x-devflow-session`、`x-devflow-workspace`；插件覆盖大小写别名，宿主以可信 session 映射再次校验，不接受头本身作为授权。
- 父会话内部 `metadata.devflow.stopReason` 为 `tool_turn_limit | model_call_limit | task_limit`；超限先锁定内存准入再持久化，宿主经新增 `CodingEngineTaskLimitError` 保留具体原因。没有增加公共 IPC 或共享持久化类型。
- `local-store.ts` 将已有按请求 ID 幂等的费用累计入口用于 `opencode-http`。不改变学习、读取、删除或其它 Memory 行为。超过 32 次 HTTP 请求时仅合并同阶段、同完整费率快照的展示行，保留所有原始调用/预算 ID；未消费失败不作为未知消费。
- #245 新增独立 `ProposalBody` 展示组件；工作台仅替换提案展示调用点，原始正文和保存命令不变。
- 单次权限详情新增独立 `CodingPermissionCommand` 纯展示组件，直接显示精确命令；不修改权限 IPC 或审批行为。
- #226 的共享提示构造函数新增可选 `toolProtocol: 'native-json'`，只有内置审查传入；默认 OpenCode 提示不变。修复工具名称与单轮唯一 JSON 契约，通用 Provider 解析器仍严格拒绝多个对象。
- `packages/shared/src/workflow.ts` 仅更正 PR 包的预算展示：disabled/unavailable 不再把占位 0 格式化为费用估算。输入类型、交付契约与有效估算不变。
- `apps/web/next.config.ts` 新增可选 `DEVFLOW_NEXT_DIST_DIR`，默认仍 `.next`，用于隔离本包 Web dev 和验证 build 输出；不提交 Next 自动生成的 tsconfig/next-env 路径。
