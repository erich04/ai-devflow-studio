## Cursor 讨论与取舍

方案讨论使用 Cursor `grok-4.7-xhigh`，会话 `f7baa462-bf9d-4db4-9fd7-c7b5198d7b79`；只读结论为无阻塞项、七项风险。逐项处理：

- 接受跨进程 JSON 覆盖风险，采用 `node:sqlite` 的 `BEGIN IMMEDIATE`。本机 Node 24.18.0 已实际导出 `DatabaseSync`，不需要额外 experimental 参数或新原生依赖。
- 接受 worker 内仍有 $100 任务预算的指出，改为轮次冻结金额；场景身份存在账本行上，不塞入会被解析器丢弃的报价扩展字段。
- 接受限额必须显式、不可重开修改；设计为初始化时必填，普通运行从已冻结的轮次加载，避免重复输入把限额抬高。
- 接受报表区分已知费用与预留占用，并明确其他历史测试入口尚未迁移。
- 接受 question 的进程隔离和专用协议要求，作为下一独立增量的前置验证；不混入本次脚本改动。

顾问意见不代替代码测试或付费实验授权。本次实际验证结果在本增量 PR 中记录；后续勾选验收项必须附对应运行证据。
