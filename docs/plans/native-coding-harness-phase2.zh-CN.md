## 第 7 条：独立验收

现有 V 会重跑公开测试，但不能据此断言需求全部实现。新增检查由独立模型请求在编码前生成，依据已批准需求、人工补充和不可变输入 B；检查正文保存在宿主私有记录，不进入实现者、子任务或压缩摘要的对话。

- 生成请求沿用现有模型调用收据、请求字节预算、取消、未知交付及重试机制；不另建绕过预算的提供方入口。
- 检查逐项绑定来源、目标版本与内容摘要。宿主冻结后不能替换；需求更新需生成新版本。
- 精确修订批准后，先跑公开测试，再在 V 运行冻结检查。必须有实际断言与完整宿主结果记录；单纯退出 0 不算通过。
- 失败只向实现者反馈来源明确的未通过验收条目，不泄露私有检查正文和预期值。恢复 D 后最多自动返修两轮，再停下等人处理。
- 人工验收保留原来的明确入口与 `manual_accepted` 证据，不能冒充独立自动验收。历史会话保留原证据含义。

## 第 8、9 条

默认 OS 沙箱：macOS Seatbelt，Linux bubblewrap/Landlock，工作区外写入与未授权联网默认拒绝；不可用则停止。权限统一为 deny → ask → allow，支持逐条确认、沙箱规则、无人值守模式和本任务授权；子任务请求由父任务界面处理。

实施按第 7 → 8 → 9 条分别提交与验证。每条的 PR 面向 V3；本地 verify 和六项 CI 全部通过后才合入。最终重跑 r8 的十道题，记录独立验收、假完成、沙箱与权限中断次数。真实评测结果单独记录，不能用模拟模型测试替代。

第 8 条执行边界：默认命令配置为 `os_sandbox/network:none`，显式授权后才允许 IP 联网；候选、子任务、依赖、最终检查与 MCP 使用同一执行器。每次先探测策略可强制执行，再启动实际命令。Linux 严格回退拒绝命名/抽象 Unix socket、宿主进程控制、未受 Landlock 约束的元数据修改，以及构建头文件尚未覆盖的新系统调用。此限制可能影响部分安装/构建工具；指南列出受管容器选择，禁止自动回退。Windows 保留明确选择可信执行或容器的入口。

第 9 条权威：规则仅由宿主配置提供，开工模式由人工 IPC 命令选择，二者随会话冻结并由子任务继承。规则基于直接 argv 的字面前缀，拒绝优先；解释器内联脚本和复合 shell 不获自动放行，可信本机也不自动放行。单次批准绑定操作 ID，任务批准绑定参数摘要、任务、目标版本、策略摘要和有效期。真实执行前再次核对目标与暂停状态，已授权但尚未执行的旧操作不能跨越人工修改边界。
