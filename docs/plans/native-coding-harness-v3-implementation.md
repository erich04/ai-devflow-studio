## Cursor 审查与处理

只读顾问使用 `grok-4.7-xhigh`；意见逐项对照当前实现，不采用其“通过/不通过”标签代替验证。

| 第一轮发现 | 处理与验证 |
| --- | --- |
| 冻结前插话可能漏入下一轮，旧批准仍有效 | 将目标更新与 review 的提交绑定 CAS；批准再次核对 pendingInput/目标/修订；插话冻结回归通过 |
| 晚到模型回包的状态检查和提交分离 | mutation 内核对 writer/epoch、状态及取消信号；晚到只记录用量，不追加可执行工具；顺序用例通过 |
| 工作流取消、完成事务及重启恢复分叉 | 取消中止最终验证并等待事务收尾；完成 WAL 恢复实际证据，未完成才恢复 D；真实取消回滚及已完成事务重启用例通过 |
| writer 已清，但旧命令仍存活 | 新写者前先核对真实进程；starting/running 不当作完成；带身份标记的存活 worker 回归通过 |

同时修正测试证据 cwd 指向实际 V，稳定 v3 服务实例与授权续期的子任务停止顺序。针对新增人工验收完成第二轮聚焦复核，顾问未报告新的阻塞项；其三项建议独立处理如下：

| 追加复核意见 | 独立判断与处理 |
| --- | --- |
| 换成另一配对成员后，人工依据仍记原请求人 | **不采纳该触发结论。** 生产运行的 context receipt 会经 `assertExecutionContext → assertCodingContextCurrent → executionScope` 校验当前配对；即使没有 Memory 内容，成员改变也会拒绝。补充同项目换成员回归并通过。现有契约要求原执行身份，不新建另一套代批权限 |
| 验收后、结算前 D 被外部改动，历史完成与当前工作流状态不清 | **接受并修复提示。** 只读投影明确显示交付冲突，保留不可变的历史验收，阻止无效操作与工作流完成；真实文件漂移、恢复目标内容后再次结算的回归通过 |
| 切到不支持 Harness 的执行器后，未结算任务被静默跳过 | **接受并修复。** CodingRun 记录暂停原因；主进程按项目当前配置返回明确提示，界面保留历史并隐藏不可执行的批准/继续操作。切回 v3 后按原会话恢复，不交给其他执行器重放 |

上述聚焦回归共 11 项通过（含既有身份约束），随后对修改后的代码重新执行完整检查与 Electron 流程。顾问的建议仅作输入，所有结论以这里列出的代码路径与实际验证为准。

## 尚未满足的发布条件

1. **真实模型授权与能力证明。** 需要明确项目、模型提供方和总费用上限后，执行端点兼容与至少 30 项 Native v2/v3/OpenCode 对照。当前没有取得这批实验额度，因此未调用。题目资格成立不证明 Harness 优于 v2。
2. **冻结实验配置并执行。** [逐题行为说明](../evaluation/native-coding-v3-task-briefs.json)和[交互/故障规程](../evaluation/native-coding-v3-interactive-protocol.md)已准备。取得模型与预算信息后，冻结其摘要、代码、重复次数、效果及费用/时间门槛再运行。保留开发/保留集、所有失败与未知费用；统计工具不会自动给出发布许可。
3. **当前提交的平台检查。** PR 必须通过 macOS、Windows、Linux 及数据库/容器检查。已加入真实 Windows Electron；首次实际失败与修复见上文，不以静态检查替代进程树、文件锁、长路径和恢复行为的实机证据。
4. **最终发布复核。** 上述证据齐备后，按预先约定的成功率、误报、时间与费用门槛决定是否达到完整发布要求。当前不自动切换 OpenCode、不宣称正式发布、不自动合并或部署。
