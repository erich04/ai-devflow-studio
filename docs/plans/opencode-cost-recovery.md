# OpenCode 费用恢复：第二、三批

2026-10-04，用户授权在现有 `codex/opencode-error-reporting` 分支连续完成第二、三批；不等待第一批合并，不推送或合并。第一批保留为独立本地提交。

## 账目与核对

- `model-cost-recovery.ts` 使用与预算相同的历史去重关系和 UTC 调用归属月份，生成费用列表、实际费用和运行中预留。上一月未知记录仍可查看，但不加入本月阻断。
- Postgres v31 新增 `model_cost_events`，追加人工核对、迟到结算确认和冲突，按数据库序号排序；原调用者、原结算和历史用量不被核对命令覆盖。稳定来源为 `model_call + 调用 ID` 或 `legacy_usage + 既有费用投影 ID`，不猜测旧记录关联。
- 核对命令只接受来源、精确财务版本、幂等键、金额或完整用量、原因、非敏感依据和已核实执行状态。操作者从服务端会话取得；仓库和 API 都检查 Lead/Owner 权限。组织和项目沿用 reserve/settle 的事务锁。身份字段不能由请求正文指定。
- 小于等于十分钟的预留不能人工结清；超过十分钟只成为候选。核定零需要账单或未发送证明；有已记录用量时禁止声明未发送。金额确定时 Token 可继续未知。历史源数据更新会使旧核对失效，重新进入冲突状态。
- 项目/成员报告、预算准入、批准剩余额度和 Web/Electron 展示都读有效投影。核对后仍超限、仍有适用未知项时继续阻断，不自动重跑工作流。

## 同步与界面

- 最终结算与执行前占位使用显式 final 标记。桌面 SQLite 保存原组织、用户、团队项目和本地项目，写入/删除/冲突回执均立即持久化。绑定变化不允许把旧费用发往新账户。
- 服务端和桌面旧队列中无明确 final 标记的 `failed` 且无用量记录，保守视为执行占位；不能自动或手动作为最终失败上传。旧占位可由原调用随后保存的真实最终结果替换。
- 手动重传只上传已保存最终结果；旧队列缺身份时必须由同项目服务端调用记录证实当前调用者。原设备未上传的数据无法从 Web 读取。服务端重传只读取当前用户的最终队列。
- settle 保留原调用者校验。冲突先持久保存，再返回 `conflict_recorded` 和冲突 ID；客户端核验 ID/项目/状态后保留完整本地结果及回执，退出自动重传。普通无结构 200 不删除本地记录。同一冲突重传幂等，不重复计费，也不会在人工处理后被旧重传重新打开。
- 与有效核对结果相符的迟到结算追加确认事件，返回带确认 ID 的 `confirmed` 回执；可补齐此前未知的 Token，不重新打开预算阻断。费用缺定价本身不能推翻已有可靠账单；金额或已知用量冲突则仍需人工复核。
- Web 预算页显示来源、模型、时间、状态、月份、待核对数量、核对表单和历史。桌面失败记录可进入当前项目模型/预算设置，在那里查看同一云端账目并重传本机最终结果。
