## 实施结果

### H1（本 PR）

冒烟从 #168 起在生成方案前失败，原因有两层：

1. 从 #168 起，阶段 Agent 的每一轮模型调用都要先取得已配对团队项目的策略快照并通过预算准入。冒烟把 Team API 指向不可达端口，也没有配对，治理中转直接拒绝，合成模型收不到请求。
2. 补上 Team API 后，取消前的那一轮正常，重试时 OpenCode 报 `cli_unavailable`：治理中转把 OpenCode 的每一轮以 `stream:false` 转发，并按一个 JSON 完整回答解析；合成模型只会返回流式结果。

修改只在冒烟脚本：启动内存版演示 Team API，创建团队项目并配对，关闭该测试项目的预算守卫；合成模型按请求是否流式返回对应格式；测试用的凭据适配器同时接受配对令牌。产品代码不变。生成失败时，冒烟会输出最近的执行记录和页面状态，便于定位。

这项冒烟需要本机安装 OpenCode，仍未加入 CI。

### H2

**契约变化**（同步摘要，向后兼容）：运行摘要新增可选的 `nodes`，按顺序列出每个步骤的标识、阶段、类型、状态和所需角色。这些字段与原有的 `currentNode` 相同，都是结构元数据；步骤标题、副标题、材料和正文仍只留在桌面端，上云范围不变。API 校验：列表非空且不超过 64 项，只允许上述字段，标识不重复、不能使用团队存储前缀，并且必须包含与 `currentNode` 一致的当前步骤。旧桌面端不带列表时，API 保持原来的行为。

- 桌面端：`createRemoteRunSummary` 带上整个步骤列表。
- 内存仓储与 Postgres 仓储：有列表时逐个写入步骤，不再把此前进行中的步骤猜测为已完成；从其他摘要生成的子步骤（例如测试证据）保留。步骤标题按阶段和类型写成中文（`remoteStepTitle`），与桌面端的模板显示名一致；副标题为“步骤状态由桌面端同步。”。Postgres 在冲突更新时一并更新标题，已有的英文占位标题会在下一次上传时改掉。
- Web：旧数据中的占位标题（`Synced … node`、`Test Evidence`）和模板英文名显示为中文；进度百分比随完整列表计算。

验证：共享层、两种仓储和 Web 页面的新增测试；与同步相关的 74 个测试文件、1384 项通过；全仓类型检查通过；`test:electron-smoke` 与 `test:e2e`（41 项）通过。本机完整 `pnpm verify` 因内存压力过慢而中止，以 CI 的完整运行为准；真实 Postgres 由 CI 的 Postgres 集成作业覆盖。
