## 实施结果

### H1（本 PR）

冒烟从 #168 起在生成方案前失败，原因有两层：

1. 从 #168 起，阶段 Agent 的每一轮模型调用都要先取得已配对团队项目的策略快照并通过预算准入。冒烟把 Team API 指向不可达端口，也没有配对，治理中转直接拒绝，合成模型收不到请求。
2. 补上 Team API 后，取消前的那一轮正常，重试时 OpenCode 报 `cli_unavailable`：治理中转把 OpenCode 的每一轮以 `stream:false` 转发，并按一个 JSON 完整回答解析；合成模型只会返回流式结果。

修改只在冒烟脚本：启动内存版演示 Team API，创建团队项目并配对，关闭该测试项目的预算守卫；合成模型按请求是否流式返回对应格式；测试用的凭据适配器同时接受配对令牌。产品代码不变。生成失败时，冒烟会输出最近的执行记录和页面状态，便于定位。

这项冒烟需要本机安装 OpenCode，仍未加入 CI。

### H2

**契约变化**（同步摘要，向后兼容）：运行摘要新增可选的 `nodes`，按顺序列出每个步骤的标识、阶段、类型、状态和所需角色。这些字段与原有的 `currentNode` 相同，都是结构元数据；步骤标题、副标题、材料和正文仍只留在桌面端，上云范围不变。API 校验：列表非空且不超过 64 项，只允许上述字段，标识不重复、不能使用团队存储前缀，并且必须包含与 `currentNode` 一致的当前步骤。旧桌面端不带列表时，API 保持原来的行为。

- 桌面端：`createRemoteRunSummary` 带上整个步骤列表。
- 内存仓储与 Postgres 仓储：有列表时逐个写入步骤，不再把此前进行中的步骤猜测为已完成；从其他摘要生成的子步骤（例如测试证据）保留。步骤标题按阶段和类型写成中文（`remoteStepTitle`），与桌面端的模板显示名一致；副标题为“步骤状态由桌面端同步。”。Postgres 在冲突更新时一并更新标题，已有的英文占位标题会在下一次上传时改掉。
- Web：旧数据中的占位标题（`Synced … node`、`Test Evidence`）和模板英文名显示为中文；进度百分比随完整列表计算。

验证：共享层、两种仓储和 Web 页面的新增测试；与同步相关的 74 个测试文件、1384 项通过；全仓类型检查通过；`test:electron-smoke` 与 `test:e2e`（41 项）通过。本机完整 `pnpm verify` 因内存压力过慢而中止，以 CI 的完整运行为准；真实 Postgres 由 CI 的 Postgres 集成作业覆盖。

### H3

只记录 `HEAD` 不够：托管工作树在交付提交之前一直带着未提交的改动，`HEAD` 不变时代码也可能已经变了。因此新证据记录被测工作树的**指纹**，覆盖三部分：`HEAD`、`git diff HEAD --binary`，以及未跟踪、未忽略文件的内容哈希（`git hash-object --stdin-paths`，不写入对象库）。Git 以 `GIT_OPTIONAL_LOCKS=0` 运行，读取指纹不改动仓库。

- **写入**：`TestEvidence` 新增只留在本机的可选字段 `sourceTree`（指纹，以及在托管工作树中运行时的工作区标识）。三条测试路径都会记录：任务中的“运行检查”、编码运行的工作树测试、Native v2 的 `runTests`。测试前后各算一次；测试只生成未跟踪文件时记录测试后的指纹，测试改动了已跟踪文件时不记录，按旧证据处理。上传的测试摘要字段是显式列出的，不包含这个字段；交付仍只用 `sourceCommitSha` 选择证据。
- **读取**：新增只读 IPC `getTestEvidenceFreshness({ runId })`，主进程重新计算当前指纹，逐条返回 `current`、`stale`、`unrecorded` 或 `unavailable`（工作区已清理或无法读取）。窗口重新获得焦点、证据或编码运行变化时重新读取。
- **显示**：任务检查器的测试证据与“设置 › 本地项目”的测试记录中，`current` 显示“结果对应当前代码。”；`stale` 加“已过期”标记并提示重新运行检查；其余情况沿用“适用性无法核实”。只作显示，不阻止测试、门禁或交付。

已知限制：测试后删除测试自己生成的未跟踪文件，也会显示“已过期”，结论偏保守。数据库结构不变（证据整体存为 JSON）。

验证：指纹与适用性判断的主进程测试、视图模型测试和 App 测试新增用例；桌面端 161 个测试文件、2236 项通过；全仓类型检查通过；`test:electron-smoke` 新增一段：测试后在被测工作树写入文件，界面显示“已过期”，删除后恢复为“结果对应当前代码”；`test:native-coding-electron-smoke` 通过。

### H4

只改文案和错误的显示方式，存储值、审批对象与写入路径不变。

- **代码改动审批面板**：标题改为“代码改动审批（Change Set）”；事实栏改为编码运行、步骤、风险、文件数、改动指纹、审批截止、受管工作树；按钮改为“批准这些改动”和“拒绝改动”，最终接收的拒绝按钮改为“拒绝并保留工作树”。风险值按 `safe/warn/blocked` 显示为“低／需注意／已阻止”（权限摘要里的风险同样处理），权威测试状态显示为中文，截止时间用本地时间格式，“unavailable”改为“不可用”，“fail closed”等混排说明改为中文；无障碍名称同步改成中文。
- **PR 交付包正文**：小标题改为“改动文件／证据／核对清单”，字段与核对项改为中文；测试和策略状态沿用桌面端已有的说法，预算状态写成中文短语。这份正文也是发到 GitHub 的 PR 正文；没有代码解析这些标题，已生成的交付包和它的摘要值不受影响，只有新生成的交付包使用新文案。PR 标题（`PR Draft: …`）未改。
- **编码失败摘要**：模型调用的执行记录和失败摘要改为“模型名 · 阶段 · 原因（耗时） · 费用 · 是否可重试”，例如“deepseek-flash · 分析 · 模型输出达到上限，回答未完成（12 秒） · 费用已确认 · 不建议直接重试。”。内置 DeepSeek 仍显示 DeepSeek，其他 Provider 显示所选模型名；Provider 内部 ID、错误码和原因代码只留在执行记录的元数据中。编码执行的两条兜底摘要也改为中文。OpenCode 失败没有对应的元数据，摘要仍带 OpenCode 的错误代码。
- **IPC 原始错误**：新增 `ipcErrorMessage`，去掉 Electron 的 `Error invoking remote method '…':` 前缀；渲染层 38 处读取 IPC 错误的地方统一使用它（原来 21 处各自写了同一个正则，另有 17 处没有去掉前缀，包括预算读取和会话操作）。会话栏的预算提示只显示“云端预算不可用，请先同步团队策略。”，具体原因留在“设置 › 模型与执行方式”。

未包括：验收证据包正文、编码运行的其余英文摘要（如 `Preparing a managed Coding Agent run.`、`Coding Agent run cancelled by user.`）和编码运行记录的英文无障碍名称；主进程抛出的错误本身仍可能是英文。

验证：完整 `corepack pnpm verify` 通过（345 个测试文件、4625 项）；`test:e2e`（41 项）、`test:electron-smoke`、`test:workbench-conversation-electron-smoke`、`test:native-coding-electron-smoke` 通过。均使用模拟模型。
