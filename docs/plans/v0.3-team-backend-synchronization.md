# v0.3 团队后端同步计划

<a id="goal"></a>

## 目标

将 DevFlow Studio 从本地 Electron MVP 和使用样例数据的 Web/API 界面，发展为由真实后端提供共享 Run、项目、成员、费用及管理看板的团队平台。

本文保留 v0.3 历史实现与演示认证约定，不代表当前生产认证配置；当前状态以[路线图](../roadmap.md)为准。

<a id="code-facts-checked"></a>

## 已核实代码事实

- `apps/api/src/server.ts` 已将 `/api/runs`、`/api/team/overview`、`/api/skills`、`/api/mcp` 委托给团队路由解析器及仓储边界。
- `apps/api/src/repositories/postgres-team-repository.ts` 将 Postgres 行映射为共享 DevFlow 领域类型，并通过 Postgres 更新或插入写入脱敏 Run/测试证据摘要。
- `apps/api/src/repositories/repository-runtime.ts` 在配置 `DEVFLOW_DATABASE_URL` 或 `DATABASE_URL` 时选择 Postgres 仓储，否则保留种子仓储供本地演示和测试。
- `apps/api` 提供 `db:migrate`、`db:seed`、`db:setup`，可按已提交迁移和演示样例准备本地 Postgres。
- `scripts/postgres-smoke.mjs` 通过数据库准备、启动连接 Postgres 的 API、读取种子团队数据、上传脱敏摘要及经 `/api/team/overview` 回读，验证真实 Postgres 路径。
- `apps/web/app/page.tsx` 经 `apps/web/app/lib/devflow-api.ts` 获取团队概览，不再直接导入管理看板样例。
- `apps/worker/src/index.ts` 当时仍从样例 token 用量计算汇总。
- `packages/shared/src/domain.ts` 已有面向后续的数据来源类型：`DataOrigin = 'seed' | 'local' | 'remote' | 'adapter'`。
- `apps/desktop/src/App.tsx` 区分 `seed`、`local`、`remote`：本地 SQLite 保存私有执行证据；显式同步后，远端团队快照可替换桌面团队概览中的项目、成员和费用汇总。
- Electron 本地执行已形成实际边界：本地项目、测试命令、Run、Artifact、Event、测试证据、主题偏好及 MCP 界面状态保存在 SQLite 结构 v2。

<a id="product-scope"></a>

## 产品范围

v0.3 增加团队同步，不增加真实 LLM 编排、真实 MCP 进程管理、HoneyAI 适配器执行或生产 Electron 打包。

保持跨平台 Electron 兼容性。Windows 11 为主要 Windows 目标，Windows 10 尽力支持，见 `docs/adr/0006-cross-platform-electron-compatibility.md`。

<a id="architecture"></a>

## 架构

- SQLite 继续作为 Electron 本地/离线/私有来源，保存仓库状态和执行细节。
- 增加 Postgres 作为团队共享状态的事实来源。
- 通过 `apps/api` 暴露团队状态。
- `apps/web` 从 `apps/api` 获取数据，不再导入样例。
- Electron 通过显式同步读取远端状态并上传已批准本地摘要。
- `adapter` 保留给未来 HoneyAI 或其他执行引擎集成。

<a id="cross-platform-constraints"></a>

## 跨平台约束

- API、Web、Postgres、Electron 同步和冒烟代码不引入仅 macOS 可用的假设。
- 不硬编码 POSIX 路径、`/tmp`、正斜杠分隔符或 `bash`/`zsh` 行为。
- 本地执行和持久化使用跨平台 Node/Electron API：`path`、`os.tmpdir()`、显式 `cwd`/`env` 的 `spawn`、Electron `app.getPath('userData')`。
- 命令安全检查兼容 PowerShell 和 `cmd`。
- 路径展示和脱敏证据摘要兼容 Windows 盘符与反斜杠。
- 保持 `corepack pnpm test:cross-platform` 通过，作为包脚本/冒烟运行器 POSIX 专属假设的首层静态防护。
- Windows CI 覆盖类型、单元及跨平台审计；完整 Windows Electron 冒烟仍是下一项兼容扩展，需要真实桌面窗口运行器策略。

为 API 客户端明确 v0.3 演示认证契约。Web 和 Electron 远端同步默认发送 `x-devflow-organization-id`、`x-devflow-user-id`、`x-devflow-user-role`、`x-devflow-project-roles`，同时允许未来调用方覆盖会话请求头。Postgres 冒烟以 `DEVFLOW_REQUIRE_AUTH=true` 启动 API，证明种子读取和脱敏同步写入不依赖未认证演示回退。

**验证：**

```bash
corepack pnpm test packages/shared/src/remote-sync.test.ts apps/web/app/lib/devflow-api.test.ts apps/desktop/electron/remote-sync.test.ts
corepack pnpm test:postgres-smoke
corepack pnpm verify
```

<a id="non-goals"></a>

## 非目标

- 不实现真实 LLM 或多 Agent 编排。
- 不实现真实 MCP 进程生命周期管理。
- 不实现 HoneyAI 适配器。
- 不实现 Electron 签名、公证、自动更新或发布打包。
- 不实现 Windows 安装器、代码签名或自动更新打包。
- 不实现 Git Markdown 知识索引管线。

<a id="completion-criteria"></a>

## 完成标准

- `apps/api` 不再直接从共享样例提供团队概览。
- `apps/web` 不再直接从共享样例导入管理看板数据。
- Electron 界面状态模型能区分 `seed`、`local`、`remote`。
- 显式同步后，桌面团队概览可呈现远端项目、成员和费用汇总。
- 本地 SQLite 继续作为私有执行细节来源。
- 团队 Postgres/API 成为共享管理看板来源。
- 无数据库 URL 时 API 可使用种子数据；配置 `DEVFLOW_DATABASE_URL` 或 `DATABASE_URL` 后切换 Postgres。
- 可用 `corepack pnpm --filter @ai-devflow/api db:setup` 准备本地 Postgres 演示。
- CI 包含由 Postgres 支持的 API 同步集成冒烟。
- Web 和 Electron 演示客户端发送显式会话请求头；Postgres 冒烟验证关闭演示回退的 API 路径。
- 本地执行、SQLite `userData`、路径处理和冒烟设计保留 Windows 兼容。
- `corepack pnpm verify` 稳定通过。
