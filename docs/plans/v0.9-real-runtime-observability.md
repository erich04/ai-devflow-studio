# DevFlow Studio v0.9：真实 OpenCode 运行时、可观察性与演示准备

<a id="summary"></a>

## 摘要

v0.9 将 v0.6/v0.6.x 已本地签署的真实编码运行时提升为可演示、可观察、可信赖的能力：审阅者能逐步看到真实工具调用、权限决定、差异与测试证据，无需仅依赖日志或模拟引擎。

模拟编码引擎仍是默认 `verify` 路径。真实 OpenCode 加固沿用 CodingEngineAdapter 边界，不破坏确定性验证。本历史里程碑不含 Windows Electron 冒烟、打包/签名、真实 MCP 进程管理、RAG/向量、多 Agent 或 HoneyAI 桥接；Windows 兼容仍受 ADR 0006 架构约束，但非本版交付。

不盲从旧外部审查：v0.9.1 必须先按当时工具链重核契约，再修改 v0.9.2 运行时；若与 ADR 0009/v0.6 记录不符，先更新决策与研究，再调整范围。

<a id="why-now"></a>

## 为什么现在做

v0.6 对 OpenCode 1.17.5 选定 HTTP/ACP 路线；macOS 火山 Ark double/ark-code-latest 已完成多步 bash → edit → bash → bash 本地签署，但尚未达到发布演示水平。v0.8 在其上加策略重试，底层契约却未重新检查。工具版本/接口可能变化，故先重核。

<a id="current-runtime-seams-reference-not-new-work"></a>

## 既有运行时边界：参考，不是新工作

- `packages/shared/src/coding-agent.ts`：编码简报、脱敏、差异上限。
- `apps/desktop/electron/coding-engine.ts`：CodingEngineAdapter 的 ensure/start/approvePermission/cancel、模拟适配器及环境选择。
- `apps/desktop/electron/opencode-http-adapter.ts`：会话、消息、权限、diff。
- `apps/desktop/electron/opencode-process.ts`：受管 opencode serve 生命周期。
- `apps/desktop/electron/coding-runtime.ts`：工作树、依赖准备、差异、测试证据。
- `apps/desktop/electron/coding-runner.ts`：桌面编排和推送 IPC。
- `scripts/opencode-smoke.ts`：显式环境开关的真实冒烟，默认跳过。
- `scripts/opencode-smoke-preflight.ts`：运行前要求 DEVFLOW_RUN_OPENCODE_SMOKE=1、DEVFLOW_CODING_ENGINE=opencode-http、服务商/模型 ID 及配置好的密钥环境。
- `scripts/opencode-runtime-status.mjs`：不联系模型服务商，检查本地二进制/版本、默认模拟状态、真实调用门禁和配置完整性。

<a id="phases"></a>

## 阶段

<a id="v091-runtime-contract-refresh"></a>

### v0.9.1 运行时契约复核

改运行时前确认契约：

- 按当前 OpenCode 版本重做 ADR 0009 的 HTTP/ACP 比较，记录 HTTP 是否仍是首选。
- 真实调用前执行 `corepack pnpm opencode:status`，检查本地工具、默认模拟、显式门禁和服务商配置。
- 固定或记录目标版本；v0.6 时是 1.17.5。
- 无秘密地记录演示配置。候选是火山 Ark 的 OpenAI/Anthropic 兼容编码端点及 ark-code-latest，但地址、协议族、模型、环境变量、代理必须核实，不能依据旧截图猜测。
- 明确传输、会话生命周期、授权转交、取消、超时、diff 和测试证据边界。
- 确认凭据仅注入托管进程，从不写全局 OpenCode 认证。
- 依据契约决定 v0.9.2 加固内容。
- 输出 ADR 0009 补充，若换传输则新 ADR，以及 docs/research 记录；本阶段不改运行时代码。

退出标准：报告明确测试版本、传输、配置和不可接受风险；权限请求/回复、取消、超时/默认拒绝、diff、清理逐项标支持/不支持/延后；边界变化时修订 ADR。

<a id="v092-real-opencode-runtime-hardening"></a>

### v0.9.2 真实 OpenCode 运行时加固

按已确认契约从可签署提升到可演示：

- 通过现有 coding-runner 推送 IPC 实时呈现长时运行步骤，不只结束后展示。
- 多步权限在 Agents 可观察、可批准，保留过期行为。
- HTTP abort 实现真实取消，清理工作树和 opencode serve。
- 运行/权限超限以 timed_out 终结，与用户取消和正常完成区分。
- 支持时使用 POSIX 进程组，SIGTERM 后必要时升级 SIGKILL；无 PID 或不支持平台回退 child.kill()。
- 当时计划以 git worktree remove --force 清理受管工作树，重试文件删除及 git worktree prune；明确记录失败，不吞错。仅描述历史托管运行时实现，不授权删除用户工作区。
- 保存脱敏 cleanup 事件；清理失败标 workspace=cleanup_failed，不覆盖业务终态。
- 真实运行后的测试证据与模拟结构一致，测试页无需引擎特判。
- 真实引擎必须显式 DEVFLOW_CODING_ENGINE=opencode-http；默认 verify 用模拟，缺开关或其他引擎时前置拒绝真实冒烟。

退出标准：默认 verify 持续通过；`DEVFLOW_RUN_OPENCODE_SMOKE=1 corepack pnpm test:opencode-smoke` 验证已选真实传输和文档配置；取消、超时和进程/工作树清理有确定性测试或冒烟断言，不仅人工观察。

<a id="v093-runtime-observability"></a>

### v0.9.3 运行时可观察性

让开发者和管理者看懂真实执行，且不暴露原始日志：

- Agents 从持久化事件和摘要呈现权限关联工具调用/结果、权限决定、diff、测试、token/费用。
- 明确区分真实和模拟证据。
- 原始 stdout/stderr/cwd/提示词留本地，只同步脱敏摘要，沿用 v0.5/v0.6 边界。
- v0.9.4 五分钟演示用于检验可读性；无法解释的步骤视为展示尚未完成。

退出标准：能区分引擎；工具/技能时间线、权限、差异、依赖/测试、清理、终态和费用来源可见且无秘密/原始正文。tool_call 已有，本轮加 tool_result、元数据归一化和界面分组；Web/API 不上传补丁或原始轨迹。

<a id="v094-demo-readiness"></a>

### v0.9.4 演示准备

必须有演示，而非只有测试：五分钟串联选项目 → Run → Gate 约束 → 处理计划 → 编码重试 → 真实权限 → 差异 → 测试 → 清理/终态 → 轨迹；更新用户指南与截图；确定性 verify 和真实 OpenCode 冒烟双路径均通过。

演示脚本不延后到 v1.0，它是 v0.9 证明运行时可理解的验收标准。

## v0.9 范围外

<a id="next-milestone-after-v09"></a>

## v0.9 后的下一里程碑

v1.0 改为团队试用基础：小型自托管团队可登录、建项目、配对、同步摘要并在 Web 看共享状态，不只展示本地演示。

串行切片为：v1.0a 基于 organizations/users/projects/project_members 的身份基础；v1.0b OAuth/项目；v1.0c 配对/认证同步；v1.0d Compose 自托管。

真实 OpenCode token/费用遥测转至 v1.1 运行费用与预算保护，使 v1.0 专注认证团队连接。工具/技能轨迹仍基于权限；仅在 OpenCode 提供稳定结果流后才增加 opencode_event_stream。此前 tool_result 表示 DevFlow 转交决定/结果，不是原始 stdout/stderr 或私有 Skill 返回。
