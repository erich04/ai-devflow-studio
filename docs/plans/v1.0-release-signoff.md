# DevFlow Studio v1.0.0 发布签署

<a id="summary"></a>

## 摘要

v1.0.0 将 DevFlow 签署为最小自托管团队试用产品。小团队可在 Web 认证、创建项目、配对桌面、同步脱敏本地工作流摘要，并在 Web 查看共享状态，超出仅本地作品集工作台的范围。

此历史版本不是公共 SaaS，不含分发打包、自动 HTTPS、邀请管理、计费、真实 MCP 执行或多桌面并发保证。

<a id="scope-signed-off"></a>

## 已签署范围

- v1.0a 身份基础：真实 User、AuthAccount、认证会话及基于身份的团队投影；演示与认证显式分离。
- v1.0b OAuth 与项目：首用户组织所有者初始化、GitHub OAuth 启动/回调/退出、仅所有者可创建最小项目。
- v1.0c 配对与同步：一次性项目配对码、通过本地凭据边界保存的限定 bearer、无演示头回退的认证脱敏 Run 同步。
- v1.0d 自托管：API/Web/Postgres Compose 栈、.env.example、自托管指南、显式 Docker 冒烟及 GitHub Actions 覆盖。

<a id="verification-evidence"></a>

## 验证证据

创建 v1.0.0 标签前，候选本地检查通过：`corepack pnpm typecheck`、`corepack pnpm test`（48 文件/295 项）、`corepack pnpm build`、`corepack pnpm verify`（含类型、单元、跨平台、浏览器端到端及 Electron）、`git diff --check`。

Docker 验证：`corepack pnpm test:docker-smoke` 不在默认 verify 内，但必须在发布提交的 GitHub Actions 通过，本机可能没有 Docker。

仅发布时进行的真实服务商验证：

- 真实 OpenCode 冒烟会消耗额度，保留在默认 verify 和 GitHub CI 之外。
- 从 v1.0.0 之后的下一产品发布起，打标签前必须使用已配置的豆包/火山引擎配置完成一次真实 OpenCode 冒烟。
- 通过 `docs/plans/release-only-real-opencode-smoke.md` 记录。
- 声称真实运行时能力时，不得用模拟引擎证据替代。

打标签前必需 GitHub Actions：Docker smoke、Postgres integration、Windows compatibility、macOS verify。

- `apps/desktop/package.json`

<a id="release-procedure"></a>

## 发布流程

1. 提交版本与签署文档。
2. 推送 main，等待 GitHub Actions Verify 通过。
3. 后续版本运行并记录仅发布时的真实 OpenCode 冒烟。
4. 在已验证发布 commit 创建附注标签 v1.0.0。
5. 推送标签。

以上为历史流程，不因阅读本文而授权执行发布。

<a id="known-boundaries"></a>

## 已知边界

- Docker 试用 API 使用 tsx src/server.ts 解析 TypeScript 包；更小的预构建镜像留待后续。
- 真实 OpenCode 和付费服务商调用仅通过明确冒烟/签署执行，不进默认 CI。
- 最终人工验收仍需手动进行；Playwright/Electron 冒烟覆盖可重复路径，电脑点击自动化不作为事实源。
