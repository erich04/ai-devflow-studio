# DevFlow Studio v1.0：团队试用基础

<a id="summary"></a>

## 摘要

v1.0 从本地/作品集工作台走向最小自托管团队试用，证明小团队可认证、建项目、配对桌面、同步脱敏本地流程摘要，并在 Web 看共享状态；不以公共 SaaS 或全部协作功能为目标。

建立在 v0.9 本地运行时基础上，默认 CI 仍为模拟引擎 verify，真实 OpenCode/付费服务商仅通过明确冒烟和签署。本文保留历史计划及完成过程。

<a id="current-starting-point"></a>

## 当时的起点

- v0.9 已完成真实生命周期、可观察性、工具/技能时间线和双路径签署。
- API 已有 organizations、users、projects、project_members，以及 TeamSession、演示回退工具和 allowDemoFallback。
- TeamMember 只是显示模型，未成为身份或成员事实源。
- 计划开始时桌面/Web 同步仍默认演示头，不能视为真实认证连接。
- 随下文进度推进，阶段 0 清理及 v1.0a 身份、v1.0b OAuth/项目、v1.0c 配对/同步、v1.0d 部署均完成；不能将上述起点误读为完成后的现状。

<a id="v10a-identity-foundation"></a>

## v1.0a：身份基础

先建身份，再做 OAuth/配对。扩展已有团队 schema，不建平行成员体系；明确 User、AuthAccount、认证会话；project_members 保持项目成员事实，TeamMember 从 users/project_members 派生，不双写独立事实。分开 DemoSession 与 AuthenticatedSession，演示仅用于测试、种子或明确演示模式；通过投影保持 Web/桌面原显示。

完成标准：API 无演示 owner 回退也能解析认证；演示仅显式允许；团队台继续可用；测试证明两种会话不会静默混用。

范围外：OAuth 界面、配对、邀请、多组织切换。

<a id="v10b-github-oauth--minimal-team-project"></a>

## v1.0b：GitHub OAuth 与最小团队项目

实现最小 Web 认证入口：OAuth 启动/回调/退出和 cookie；全新自托管部署首个成功 GitHub 登录创建默认组织并成为 owner。已有组织时，后续用户必须解析到既有认证账户/成员关系，或未来明确邀请/管理流程，不能通过回退静默成为 owner。

所有者可创建含名称、slug、描述和仓库显示元数据的最小项目。Web 不再默认 u-erich owner，演示头仅限测试/演示。

完成标准：首用户可登录并初始化组织，owner 可创建和查看项目，受保护 API 拒绝缺失/无效认证。

范围外：邀请、GitHub App 安装、仓库权限扫描、计费/SaaS 入门。

<a id="v10c-desktop-pairing--authenticated-sync"></a>

## v1.0c：桌面配对与认证同步

Web 生成一次性项目码，桌面换取绑定用户/组织/项目的限定令牌。码默认 10 分钟、高熵、服务端哈希保存、五次失败预算；localhost 外要求 HTTPS。凭据通过专用边界保存，不将明文写仓库或日志；令牌认证失败不回退演示。同步仅摘要，不含 cwd、原始 stdout/stderr/提示词/补丁、秘密或完整源码。

完成标准：Web 建码、桌面配对并同步一条摘要、Web 项目下可见；过期或撤销令牌明确提示重连。

范围外：轮换/撤销界面、多桌面并发保证、完整审计看板。

<a id="v10d-self-hosted-minimum-deployment"></a>

## v1.0d：最小自托管部署

在开发 shell 之外运行：增加 API/Web/Postgres Compose、.env.example 和数据库/OAuth 配置说明；Docker 冒烟启动栈、迁移、使用测试会话或模拟 OAuth、建项目、配对、同步并验证 Web。

完成标准：干净机器按指南启动，容器 Postgres 迁移成功，认证桌面到 Web 的摘要链路有冒烟覆盖。

范围外：Kubernetes、自动 HTTPS、安装器/签名/自动更新、托管云。

<a id="v10-release-criteria"></a>

## v1.0 发布标准

团队基础端到端工作才完成：OAuth、首用户 owner、建项目、配对、认证脱敏同步、Web 项目显示、Compose 最小栈均可用，演示和真实认证明确分开，默认 CI 确定性无费用。

不要求十人真实并发、邀请/成员管理、GitHub PR 创建、真实 MCP、RAG/向量、公共 SaaS、桌面打包/签名或 Windows 真实冒烟。

<a id="v10x-follow-up"></a>

## v1.0.x 后续

至少三客户端并发测试、成员增删、令牌撤销/轮换、登录/配对/同步/override/撤销审计，以及备份恢复和健康检查指南。
