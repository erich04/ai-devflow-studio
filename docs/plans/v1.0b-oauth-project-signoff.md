# DevFlow Studio v1.0b 签署：GitHub OAuth 与最小团队项目

<a id="summary"></a>

## 摘要

v1.0b 为团队试用基础建立最小 Web 认证入口。不包含邀请、GitHub App 安装、仓库权限扫描、桌面配对或 Docker 部署，这些留给后续 v1.0 切片。本文记录历史签署。

<a id="scope-completed"></a>

## 完成范围

- GitHub 身份初始化：已有认证账户解析为 `User`、`AuthAccount` 及基于 `project_members` 的成员关系；空部署可将首个 GitHub 用户初始化为默认组织所有者；已有部署拒绝未知 GitHub 账户，不静默授予权限。
- 最小项目创建：共享 `Project` 增加 `slug`、`description`，团队 schema v5 保存两字段；`POST /api/team/projects` 仅允许组织所有者创建，并为创建者写入 `project_members`。
- OAuth/会话边界：API 解析启动、回调、退出；签名 `devflow_session` cookie 保存认证声明；先解析会话 cookie，再考虑明确开启的演示模式；GitHub OAuth 客户端由环境配置，不把服务商密钥放进文档或样例。
- Web 团队台：API 客户端不再默认 `u-erich owner` 演示头；有 `devflow_session` 时转发 cookie；提供 OAuth 入口和最小创建项目表单。
