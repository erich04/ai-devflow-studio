# DevFlow Studio v1.0c 签署：桌面配对与认证同步

<a id="summary"></a>

## 摘要

v1.0c 使 Electron 能连接真实团队项目，无需演示会话头。Web 签发短期、仅可复制一次的项目配对码；桌面将其交换为限定作用域的 bearer 令牌，本地只保存加密材料，并以令牌进行脱敏团队同步。

此历史阶段不包含令牌轮换/撤销界面、多桌面并发保证或完整审计看板，留待 v1.0.x 加固。

<a id="scope-completed"></a>

## 完成范围

- 配对模型/API：共享 `DesktopPairingCode`、`DesktopPairingExchangeResult`、`DesktopPairingCredential`；Postgres schema v6 增加 `desktop_pairing_codes`、`desktop_tokens`；服务端保存配对码哈希，不保存明文。有效期 10 分钟，失败预算五次。`POST /api/team/projects/:projectId/pairing-codes` 要求项目 lead 权限；`POST /api/desktop/pairing/exchange` 换取限定作用域 bearer 令牌。
- 认证同步：API 通过仓库解析 `Authorization: Bearer ...`，无效令牌不回退演示。桌面存在配对凭据时使用 bearer 头，仅未配对/本地演示模式保留演示同步。
- 凭据边界：SQLite schema v7 分开保存配对元数据与加密令牌；IPC 提供 `loadDesktopPairing`、`pairDesktop`；成功配对后渲染层不接收明文 bearer。
- 用户入口：团队项目卡片可创建配对码；同源 Web 路由代理该操作，浏览器不构造演示头或直接跨源调用 API；桌面顶部显示配对状态并接收 Web 配对码。
- Postgres 冒烟：lead 创建码，桌面换令牌，使用 bearer 上传脱敏 Run 摘要；团队概览显示同步 Run 且不泄露配对码或 bearer。

## 说明

- Postgres 使用本地 initdb/pg_ctl 临时实例和数据库，完成后移除。
- 桌面 bearer 属于运行时凭据，本地加密，不进入渲染状态或团队概览载荷。
- 当时 v1.0d 自托管最小部署须等本分支合并到 main。
