# DevFlow Studio v1.0d 签署：最小自托管部署

<a id="summary"></a>

## 摘要

v1.0d 完成团队试用基础的部署部分：在开发 shell 之外运行 API、Web、Postgres 最小栈，明确的 Docker 冒烟验证配对码交换、认证桌面同步、Web/API 可见性及脱敏边界。

这仍是试用部署，不是公共 SaaS。此历史范围不含自动 HTTPS、Kubernetes、托管云、Electron 打包/签名、令牌轮换界面或多桌面并发保证。

<a id="delivered"></a>

## 已交付

- API/Web/Postgres 的 `Dockerfile`、`docker-compose.yml`。
- 带自托管占位配置的 `.env.example`。
- API 监听主机配置，允许容器绑定 `0.0.0.0`。
- Web 内部/公开 API URL 解析以支持容器网络。
- `scripts/docker-smoke.mjs` 和 `corepack pnpm test:docker-smoke`。
- GitHub Actions `Docker smoke` 任务。
- `docs/guides/devflow-studio-self-hosted-pilot.md` 指南。
- README、路线图和 v1.0 团队试用计划中的部署路径。

<a id="verification"></a>

## 验证

本地确定性验证：

- `corepack pnpm typecheck` 通过。
- `corepack pnpm test`：48 文件、295 项通过。
- `corepack pnpm build` 串行重跑通过；首次与 typecheck 并行争用 Next 的 .next 目录，此次失败归为执行顺序问题，不计成功。
- `corepack pnpm verify` 通过，含类型、单元、跨平台、浏览器端到端和 Electron 冒烟。
- `corepack pnpm exec vitest run scripts/docker-deployment-doc.test.ts apps/api/src/server-config.test.ts apps/web/app/lib/devflow-api.test.ts` 通过。
- `git diff --check` 通过。

本机 Docker 验证未运行：没有 docker 可执行文件，报 `spawn docker ENOENT`。因此 Docker 冒烟显式依赖环境，不放进默认 verify，也不能将本地缺失算成通过。

PR #8 的 GitHub Actions 中 `Docker smoke`、`Postgres integration`、`Windows compatibility`、`macOS verify` 均通过。

## 说明

- 当时 API 容器运行 `tsx src/server.ts`，确保试用镜像中 TypeScript 工作区边界可靠解析；更小的预构建运行镜像留给后续发布工程。
