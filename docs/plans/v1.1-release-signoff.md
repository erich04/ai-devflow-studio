# DevFlow Studio v1.1.0 发布签署

<a id="summary"></a>

## 摘要

v1.1.0 在团队试用基础上签署运行费用与预算保护：真实编码用量的脱敏费用摘要、团队运行预算、超预算 lead 审批，以及付费 OpenCode 启动前的桌面预算检查。

本历史版本不提供公共计费、SaaS 计量、发票、托管支付或自动真实服务商 CI。

<a id="scope-signed-off"></a>

## 已签署范围

- 共享费用估算与预算决定模型。
- Electron 在 engine.start(...) 前估算编码费用。
- 团队预算策略、评估和批准端点。
- Postgres 保存预算策略、批准和脱敏编码费用摘要。
- 团队费用汇总包含编码运行费用。
- 远程编码摘要含费用与预算决定元数据。
- 真实 OpenCode 冒烟仍需明确授权付费并仅用于发布。

<a id="verification-evidence"></a>

## 验证证据

发布前本地检查：`corepack pnpm typecheck`、`test`（50 文件/314 项）、`test:e2e`（3 项）、`test:electron-smoke`、`verify`、`build`、临时本地 Postgres 的 `test:postgres-smoke` 和 `git diff --check` 全部通过。

真实服务商发布验证：

- `DEVFLOW_RUN_OPENCODE_SMOKE=1 corepack pnpm test:opencode-smoke` 在火山引擎配置 double/ark-code-latest 通过。
- 观察到真实 bash → edit → bash 权限转交、受管工作树变更，运行样例测试证据并清理工作树。
- 密钥只通过 shell 环境传入，未写入项目文件、文档、全局 OpenCode 认证或冒烟输出。

v1.1 合并 commit 的 macOS verify、Windows compatibility、Postgres integration、Docker smoke 均通过。

<a id="release-procedure"></a>

## 发布流程

1. 提交 1.1.0 版本及签署文档。
2. 推送 main，等待 Verify 通过。
3. 在已验证发布 commit 创建附注标签 v1.1.0。
4. 推送标签并等待发布产物工作流。

此为历史流程记录。

<a id="known-boundaries"></a>

## 已知边界

- 预算策略编辑与审批界面当时计划在 v1.2 实现。
- 桌面无法访问团队预算 API 时，v1.1 记录“未应用团队预算决定”，不在本地猜测策略。
- 真实 OpenCode 冒烟有意排除在默认 verify 和 GitHub CI 外，保留为仅发布的本地签署路径。
