# DevFlow Studio v1.2：运行费用界面与预算管理

<a id="summary"></a>

## 摘要

v1.2 将 v1.1 的预算策略、批准、评估和 Electron 调用前保护变成可操作流程：Web 查看/编辑预算并明确批准；桌面 Agents 展示预算轨迹；重试可携带用户输入的预算批准 ID。

默认验证仍使用确定性免费引擎，真实 OpenCode/服务商冒烟仅在发布时通过明确环境开关执行。本文保留历史交付结果。

<a id="delivered-scope"></a>

## 已交付范围

- Web 客户端增加 `GET /api/runtime/budget-policy`、`PUT /api/runtime/budget-policy`、`POST /api/runtime/budget-approvals`。
- 运行预算面板展示策略启用状态、月限额、预警、已花费、既有批准，以及保存策略/创建批准表单。
- 桌面编码输入和 IPC 解析增加 `runtimeBudgetApprovalId`，仍拒绝原始提示词；主进程预算边界增加 approvalId。
- 保留 v1.1 边界：桌面仅传批准 ID，API/运行时将其解析为完整记录后再调用 evaluateRuntimeBudgetGuard。
- Agents 轨迹显示状态、原因、预计/当前/限额费用、批准 ID，并为 requires_lead_approval 提供明确的“使用批准重试”动作。

<a id="non-goals"></a>

## 非目标

不新增数据库 schema 或外部产品 API，不自动匹配批准，不提供申请队列/通知，不在 CI 调付费模型，不上传提示词、cwd、stdout/stderr、补丁正文或秘密。

`corepack pnpm typecheck`、`corepack pnpm test`（50 文件/318 项）、`corepack pnpm build`、`corepack pnpm verify` 均通过；后者含类型、单元、跨平台、浏览器及 Electron 冒烟。针对性测试也通过：

<a id="release-only-real-provider-smoke"></a>

## 仅发布时的真实服务商冒烟

默认 verify 必须使用模拟引擎。发布若声称真实服务商预算行为，之前须运行并将结果写入签署记录：

```bash
DEVFLOW_RUN_OPENCODE_SMOKE=1 corepack pnpm test:opencode-smoke
```

会消耗火山引擎/豆包额度，不进默认 CI。

2026-06-21 签署记录：main 的默认 verify/build 通过；真实冒烟使用本地火山/豆包配置 `DEVFLOW_OPENCODE_PROVIDER_ID=double`、`DEVFLOW_OPENCODE_MODEL_ID=ark-code-latest`、`DEVFLOW_OPENCODE_API_KEY_ENV=ARK_API_KEY`。首次发现工具元数据含绝对工作树路径，修复后持久化前脱敏命令元数据中的本地工作树/项目路径。再次真实运行通过，原始输出为 `opencode smoke passed; changed paths: devflow-opencode-smoke.txt`（冒烟通过，变更为该文件）。
