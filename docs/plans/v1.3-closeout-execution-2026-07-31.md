<a id="decision"></a>

## 决策

v1.3 的重点是状态完整性和发布加固。只有一个请求能无渲染进程绕过地完成六阶段、本地事实经同步保持、映射显式，且全部门禁在同一 SHA 通过，候选版本才可接受。

包括 Cursor/Grok 审查在内的独立建议均是参考意见。采纳前必须对照仓库代码、测试和 v1.3 发布标准核实。

<a id="scope-boundary"></a>

## 范围边界

<a id="required-for-v13"></a>

### v1.3 必须项

- Clarify、Design、Build、Test、PR 和 Acceptance 写入共用一个权威工作流命令/证据求值器。
- Electron 主进程依据最新持久化 Run 写入，不依据渲染进程提供的 Run 快照。
- 工作流变更原子保存：Run、Artifact、Event 和 Evidence 一起提交或全部不提交。
- 显式检查当前节点、终态、证据作用域及最新证据。
- 只有已完成编码 Agent Run 和编码差异都存在时，编码完成才能将 Build 完成写回流程 Run。
- 测试仅在当前 Test 节点运行；通过推进 PR，失败停留 Test 并阻止下游交付。
- PR 草稿要求当前 PR 节点、显式仓库映射、编码差异及最新通过的测试证据，成功后推进验收。
- 验收证据包和最终批准要求当前节点及完整交付证据检查。
- 已完成的本地 Run 及其本地产物/事件在团队同步后仍是权威来源。
- v1.3 配对必须显式将一个所选 Local Project 绑定到已配对 Team Project。新请求必须带 `localProjectId`；保存字段可选仅用于读取和识别旧凭据。旧的未绑定凭据必须拒绝继续，要求重新配对。
- 测试证据在秘密脱敏前替换 CWD/stdout/stderr 中已知工作区根路径。
- `DEVFLOW_ENABLE_FAKE_RUNTIME=true` 无需凭据即可开放内置确定性模拟工作流/审查提供方；标志关闭行为不变。
- 单元、E2E、Electron 冒烟、跨平台、Windows、Postgres、Docker、构建输出及电脑操作走查门禁通过。
- API 和 Worker 干净构建输出具备已测试的最小启动契约。
- 全部工作区包版本为 `1.3.0`；发布状态绑定版本、候选 SHA、走查证据、标签名和标签目标。
- 在发布标签之前记录已有发布专用真实 opencode 冒烟。

<a id="deferred-to-v14"></a>

### 延后至 v1.4 及以后

- 超出配对项目作用域的生产认证/预算信任边界加固。
- 真实仓库知识索引。
- Web 请求录入及完整 Web 写入路径。
- 桌面多项目或多令牌映射。
- 持久远端同步发件箱、退避和操作员可见重试/恢复状态。
- 安装器、签名、公证、自动更新、部署/升级/回退打包。
- 真实 Windows Electron/安装器测试。
- 真实 GitHub PR 创建、推送、合并、MCP 执行及向量检索。

<a id="invariants"></a>

## 不变量

每次工作流写入必须满足：

1. 目标节点等于 `run.currentNodeId`。
2. 终态 Run 拒绝后续工作流写入。
3. 命令匹配当前节点种类、阶段及允许状态。
4. 证据属于同一 Run 及预期节点/项目作用域。
5. 以最新证据决定是否就绪；旧的通过不能掩盖更新的失败。
6. 转换只能激活由已声明工作流边连接的待处理节点。
7. 拒绝不得修改或保存 Run。
8. 非终态 Run 恰有一个当前活动节点，下游保持待处理。
9. 已完成 Run 的验收成功，且没有运行中的节点。
10. 远端摘要不能以有损表示覆盖更完整的本地流程状态。
11. 只有正式 Run 摘要可更新团队端 Run 状态/当前节点；Test、Review、Coding 摘要只是证据读取模型，不推进或合成 Run。
12. 渲染代码不能直接发布 Run、测试证据或编码摘要；Electron 主进程重载正式 LocalStore 实体，构建绑定团队的载荷。
13. 测试证据、派生测试报告/事件、PR/验收交付文字及团队可见摘要不含原始本地绝对路径或秘密；数据库打开时永久规范化旧本地记录。
14. 已接受 Gate 覆盖仅适用于精确的当前阻断 ID 集合和策略版本；新增或替换阻断均需重新覆盖。
15. 已覆盖 Gate 在批准时仍校验当前 lead 操作者及职责分离；其他操作者不能复用批准的覆盖。
16. Team Gate 覆盖依据 API 已持有、由创建人拥有的正式当前节点求值。独立 lead 只提交标识符和原因，不重新发布 Run。Postgres 带作用域节点 ID 在比较时规范化，持久审计外键时恢复，幂等更新保留该命名空间。
17. 未签名身份请求头默认禁用且浏览器来源不可用；生产 Team 写入要求签名会话 Cookie 或已配对桌面 Bearer Token。
18. 正式远端 Run 只能由最初经过认证的同步创建人更新；其他项目成员不能覆盖状态/当前节点或用未来时间戳锁定它。
19. Test、Agent Review、Coding 摘要必须挂接同一已认证同步创建人拥有的正式 Run；仅项目成员身份不能向其他 Run 注入证据。
20. Test、Agent Review、Coding 子摘要的组织、项目、Run、节点身份不可变；复用 ID 但作用域不同属于冲突，不能作为更新或插入目标。
21. 子摘要先上传；只有明确的正式 Run 缺失冲突，才触发一次最新正式 Run 上传和一次子项重试。其他错误均拒绝继续。
22. 延迟子摘要不能重新激活或阻断非当前节点；正式 Run 摘要独占团队端 Run 状态及当前节点推进权。
23. 团队可见策略意见保留精确脱敏阻断身份；只有数量的远端意见不足以支持覆盖。
24. 编码结构化元数据、费用/模型、预算/原因对象采用严格白名单投影；允许字符串进行路径/秘密脱敏，未知嵌套键丢弃。
25. 持久同步发件箱、退避及操作员重试状态延后至 v1.4；v1.3 保持本地提交权威，使用上述有界的正式 Run 缺失恢复。

| 既有写入路径 | v1.3 处置 |
| --- | --- |

| `runProjectTests` | 仅 ID；重载、求值、运行、事务提交 |
| PR 草稿 | 专用命令；重载、求值、事务提交 |
| 验收证据包 | 专用命令；重载、求值、事务提交 |
| 最终验收 | 使用新鲜证据的专用 Gate 命令 |
| 渲染进程 `saveRun` | 从 IPC 契约、预加载和主进程处理器移除 |
| 渲染进程 `saveArtifact` | 从 IPC 契约、预加载和主进程处理器移除 |
| 渲染进程 `saveEvent` | 从 IPC 契约、预加载和主进程处理器移除 |
| 渲染进程构造的 `createRunningRun` 变更 | 不再作为写入机制 |

直接调用已移除或旧通用 IPC 通道必须不可用或返回硬错误，且 LocalStore 不变；只停止当前 UI 调用点不足以满足要求。

<a id="execution-slices"></a>

## 执行切片

<a id="slice-1-workflow-command-core"></a>

### 切片 1：工作流命令核心

失败测试（RED）：

- 拒绝非当前 Gate/验收批准。
- 拒绝终态 Run 写入。
- 拒绝激活非待处理的下一节点。
- 验收缺少编码差异、最新通过测试、PR 草稿、验收包、策略授权或必需审查/预算证据时拒绝。
- 验证旧通过加新失败会阻断。

最小实现（GREEN）：

- 增加共享的可区分工作流命令及证据快照求值器。
- 返回结构化阻断码及纯工作流变更。
- 澄清/设计 Gate 批准要求对应产物。
- 保留显式测试失败/重跑语义。

重构：

- 现有 Agent 完成及 Gate 辅助函数共用这些不变量。
- 产物格式化与授权分离，但公开产物创建必须拒绝无效证据快照。

<a id="slice-2-trusted-electron-workflow-runtime"></a>

### 切片 2：可信 Electron 工作流运行时

失败测试（RED）：

- 测试 IPC 不再接受完整渲染进程 Run 快照。
- 直接调用旧通用 `saveRun`、`saveArtifact`、`saveEvent` 流程通道不可用或被拒绝，LocalStore 不变。
- 被拒绝命令不调用测试运行器或保存 Run/Event。
- 注入产物/事件写入失败不会留下部分推进的 Run。
- 重复/过期命令不能提交两次。

最小实现（GREEN）：

- 增加薄层 Electron 工作流运行时，从 LocalStore 重载当前聚合。
- 增加一个事务型 LocalStore 工作流变更方法。
- 用专用 IPC 命令替换渲染进程 `saveRun/saveArtifact/saveEvent` 交付编排。
- 从 IPC 契约、预加载桥、渲染 API、主进程处理器移除通用流程实体保存通道；LocalStore 保存原语仍是主进程内部实现。
- 先本地提交，再尝试远端摘要上传。

硬性停止条件：

- 渲染 API 不接受完整 `WorkflowRun` 作为权威输入。
- `runProjectTests` 仅接受 ID；任何运行器副作用前，主进程重载最新 Run。
- Clarify/Design/Build/Test/PR/Acceptance 转换均不能绕过共享求值器。

<a id="slice-3-build-and-test-continuity"></a>

### 切片 3：开发与测试连续性

失败测试（RED）：

- 编码 Agent 不能从非当前 Build 节点启动。
- 编码完成但没有编码差异时不推进。
- 已完成编码 Agent 加差异将 Build 推进到 Test，且重载后保持。
- 编码失败/取消/超时，或其工作树测试失败时不推进。
- 当前为 Build 时不能运行 Test。
- 测试通过推进 PR，失败保留当前 Test 并阻止 PR。

最小实现（GREEN）：

- 让编码运行时访问权威工作流变更写入器。
- 移除渲染进程 `createRunningRun` 工作流写入机制。
- 编码运行时的工作树测试证据限定在 Build，不能悄悄替代独立测试阶段完成。

<a id="slice-4-pr-and-acceptance-continuity"></a>

### 切片 4：PR 与验收连续性

失败测试（RED）：

- 非当前 PR/验收动作隐藏或禁用，并被 Electron 拒绝。
- PR 拒绝缺少映射、差异或最新通过测试，不回退到第一个 Team Project。
- PR 成功原子保存产物/事件并推进验收。
- 证据包创建要求完整证据，但保持验收为当前节点。
- 最终批准重新评估当前证据/策略；更新的失败使旧证据包失效。
- 第二次最终批准被拒绝，不产生重复事件。

最小实现（GREEN）：

- 增加专用 PR 草稿及验收证据包 IPC 处理器。
- 最终验收结合工作流就绪情况与门禁执行授权。
- 修正各阶段成功提示。

<a id="slice-5-sync-and-project-binding"></a>

### 切片 5：同步与项目绑定

失败测试（RED）：

- 节点为空/有损的同 ID 远端 Run 不能覆盖完整本地 Run。
- 同 ID 远端 Artifact/Event 始终保留本地记录。
- `remoteRunIds` 只标记仅存在远端的 Run。
- 团队同步不将有损远端 Run/Artifact/Event 覆盖写入本地流程实体；冲突的本地内容同步后不变。
- 没有 Local Project 绑定的旧配对凭据不能远端写入。
- 缺少 `localProjectId` 或 Local Project 未知的新配对请求被拒绝。
- 配对保存并重载选中的 Local Project 绑定。
- 每个 Run/证据/审查/编码/策略/预算/覆盖远端操作，解析已配对 Team Project ID，而非本地项目哈希。
- PR 只使用已绑定 Team Project 的仓库。
- 项目范围桌面令牌不能读写其他 Team Project。
- 通过的 Test、Agent Review 或 Coding 摘要不改变正式远端 Run 状态/当前节点，也不能创建缺失的正式 Run。

最小实现（GREEN）：

- 配对凭据增加为兼容旧记录而可选的 `localProjectId`；所有新配对必须提供 `{code, localProjectId}` 并核实本地项目存在。
- 增加集中绑定解析器及遇不确定情况拒绝继续的远端写入封装。
- 合并仅远端记录，冲突时始终保留本地记录；团队同步只做渲染/读取模型合并，不将有损远端流程实体写入 LocalStore。
- 将已配对令牌会话限定在配对项目，不改变普通 Web owner 语义。
- Test/Review/Coding 摘要接口只更新证据/读取模型表；必须存在由 Run 摘要创建的正式 Run，否则返回前置条件冲突。
- 先尝试依赖摘要；只有明确的正式 Run 缺失冲突，才上传最新正式本地 Run 并重试子项一次。其他错误拒绝继续，且不写 Run。
- Run 摘要更新保持单调，拒绝将已有 Run 转移到其他组织/项目归属。

硬性停止条件：

- v1.3 实现配对项目作用域并修复未签名请求头/浏览器写入绕过；更广的生产认证和预算加固不在范围内。
- 未绑定旧凭据在用户重新配对前仅本地可用，不推断或回退到首个项目。
- `remoteRunIds` 恰好包含仅远端 ID，不包含冲突的本地 Run ID。

<a id="slice-6-privacy-and-deterministic-no-cost-path"></a>

### 切片 6：隐私与确定性无费用路径

失败测试（RED）：

- 已知工作区路径的 POSIX、Windows 和 `file://` 形式从测试证据 CWD/stdout/stderr 消失。
- 路径替换后仍进行秘密脱敏。
- 模拟提供方仅在模拟运行时标志开启时出现且可解析。
- 模拟提供方不读取或写入凭据。

最小实现（GREEN）：

- 先精确替换已知根路径，再保守处理跨平台路径/URL，保留显式 API 路由和 Web URL，最后秘密脱敏。
- 显式模拟运行时标志下开放并解析 `createFakeAgentProvider()`。
- Electron 冒烟使用内置提供方，替代临时 HTTP 桩。

<a id="slice-7-deterministic-validation-and-runnable-outputs"></a>

### 切片 7：确定性验证与可启动输出

失败测试与实现：

- 在演示样例边界测试中规范化 Windows 相对路径。
- Docker 冒烟将 `DEVFLOW_ENABLE_DEMO_DATA` 传入 API 容器。
- E2E 在知识审查前先到达正确 Gate，默认隔离服务端口/状态。
- 将已修改知识 Markdown 与内置样例副本同步。
- 增加 `test:build-output-smoke`。
- 生成最小 API/Worker Node 打包输出及启动脚本，验证干净构建启动。
- 将必需确定性门禁加入 Verify 和 Release 工作流。

<a id="slice-8-release-metadata-and-signoff"></a>

### 切片 8：发布元数据与签收

失败测试与实现：

- 增加标签前、已打标签两种发布状态模式。
- 功能及自动门禁通过后，才将全部包版本设为 `1.3.0`。
- 创建干净候选提交 `C`，含发布代码、文档、工作流及对齐包版本，再针对 `C` 运行全部候选门禁和带日期电脑操作走查。
- 为产生费用的真实 opencode 冒烟取得明确批准/凭据，仅记录非敏感证据。
- 创建第一父提交为 `C` 的签收提交 `S`。`C..S` 恰好包含 `walkthrough.json`、`required-gates.json`、`real-opencode.json` 和带日期走查结果；三份 JSON 的 `candidateSha` 均为 `C`。
- 标签前模式在干净 `S` 运行，版本标签必须不存在；建标签后在同一个 `S` 运行已打标签模式，要求 `v<rootVersion>` 精确解析为 `S`。

<a id="verification-ladder"></a>

## 分层验证

每个失败测试/实现步骤后运行最小测试，再扩大范围：

1. 共享工作流、本地执行、远端同步单元测试。
2. Electron 运行时、LocalStore、IPC、编码运行时测试。
3. 渲染视图模型及 App 测试。
4. `corepack pnpm typecheck`。
5. `corepack pnpm test`。
6. `corepack pnpm test:cross-platform`。
7. `corepack pnpm test:e2e`。
8. `corepack pnpm test:electron-smoke`。
9. `corepack pnpm test:postgres-smoke`。
10. `corepack pnpm test:docker-smoke`。
11. `corepack pnpm build` 和 `corepack pnpm test:build-output-smoke`。
12. `corepack pnpm verify:demo`。
13. 提交干净候选 `C`，再针对 `C` 运行带日期电脑操作走查及全候选门禁。
14. 明确批准后运行发布专用真实 opencode 冒烟。
15. 仅提交四份证据文件形成 `S`，在 `S` 运行标签前签收，在 `S` 建立标签，再运行已打标签签收。

<a id="stop-conditions"></a>

## 停止条件

- 任一必需门禁失败时，不创建或推送发布标签。
- 通用渲染进程流程保存通道仍可用，或测试 IPC 仍接受完整 Run 时，不进入发布验证。
- 团队同步仍能将有损远端流程实体覆盖写入 LocalStore 时，不推进。
- 未绑定旧配对凭据仍能进行 Team 写入或仓库解析时，不推进。
- 未经用户明确批准，不运行付费提供方，不安装/配置真实 opencode 提供方。
- 不覆盖 2026-07-25 失败走查，新增带日期结果。
- 保留所有预先存在的工作树文档修改和未跟踪文件。
- 不把安装器或生产部署完整性声明为 v1.3 已完成内容。
