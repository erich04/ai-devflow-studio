## Decision

v1.3 is not a feature-expansion milestone. It is a state-integrity and release-hardening milestone.

The release candidate is acceptable only when one request moves through all six stages without a
renderer bypass, local truth survives sync, mapping is explicit, and every gate passes on one SHA.

Independent advice, including Cursor/Grok review, is advisory. Every proposed change must be
confirmed against repository code, tests, and the v1.3 release criteria before adoption.

## Scope Boundary

### Required for v1.3

- One authoritative workflow command/evidence evaluator for Clarify, Design, Build, Test, PR, and
  Acceptance writes.
- Electron main-process writes based on the latest persisted Run, never a renderer-supplied Run
  snapshot.
- Atomic persistence of a workflow mutation: Run, Artifact, Event, and Evidence either commit
  together or do not commit.
- Explicit current-node, terminal-state, evidence-scope, and latest-evidence checks.
- Coding completion writes Build completion back to the Workflow Run only when a completed Coding
  Agent Run and Coding Diff exist.
- Test execution is allowed only at the current Test node. A pass advances to PR; a failure stays at
  Test and blocks downstream delivery.
- PR Draft creation requires the current PR node, an explicit repository mapping, Coding Diff, and
  latest passing Test Evidence, then advances to Acceptance.
- Acceptance Bundle and final approval require current-node and complete delivery evidence checks.
- Completed local Runs and their local Artifacts/Events remain authoritative after Team Sync.
- Pairing explicitly and mandatorily binds one selected Local Project to the paired Team Project
  for v1.3. New pair requests require `localProjectId`. The stored field is optional only so legacy
  credentials can be read and identified; old unbound credentials fail closed and require
  re-pairing.
- Test Evidence replaces the known workspace root in CWD/stdout/stderr before secret redaction.
- `DEVFLOW_ENABLE_FAKE_RUNTIME=true` exposes the built-in deterministic fake workflow/review
  provider without credentials; flag-off behavior remains unchanged.
- Unit, E2E, Electron smoke, cross-platform, Windows, Postgres, Docker, build-output, and Computer
  Use walkthrough gates pass.
- API and Worker clean-build outputs have a tested minimal start contract.
- All workspace package versions become `1.3.0`; release status binds version, candidate SHA,
  walkthrough evidence, tag name, and tag target.
- The existing release-only real opencode smoke is recorded before the release tag.

### Deferred to v1.4+

- Production auth/budget trust-boundary hardening beyond paired-project scoping.
- Real repository knowledge indexing.
- Web request intake and complete Web write paths.
- Multi-project or multi-token Desktop mapping.
- Installers, signing, notarization, auto-update, deploy/upgrade/rollback packaging.
- Real Windows Electron/installer testing.
- Real GitHub PR creation, push, merge, MCP execution, and vector retrieval.

## Invariants

Every workflow write must satisfy these invariants:

1. The target node equals `run.currentNodeId`.
2. A terminal Run rejects further workflow writes.
3. The command matches the current node kind, stage, and allowed status.
4. Evidence belongs to the same Run and expected node/project scope.
5. The latest evidence determines readiness; an older pass cannot hide a newer failure.
6. A transition can only activate a pending node reached by a declared workflow edge.
7. Rejection does not modify or persist the Run.
8. A non-terminal Run has exactly one current active node; downstream nodes remain pending.
9. A completed Run has Acceptance successful and no running node.
10. Remote summaries never replace richer local workflow state with a lossy representation.
11. Only the canonical Run Summary may update a team-side Run status/current node. Test, Review,
    and Coding summaries are evidence read models and never advance or synthesize a Run.
12. Renderer code cannot publish Run, Test Evidence, or Coding summaries directly. Electron main
    reloads canonical LocalStore entities and constructs team-bound payloads.
13. Test Evidence, derived Test Reports/Events, PR/Acceptance delivery text, and team-visible
    summaries contain neither raw local absolute paths nor secrets; legacy local records are
    permanently normalized on database open.
14. An accepted Gate override applies only to the exact current blocker-ID set and policy version;
    any new or replaced blocker requires a fresh override.
15. An overridden Gate still validates the current lead actor and separation of duties at approval;
    another actor cannot reuse an accepted override.
16. A Team Gate override is evaluated against the canonical current Node uploaded by Electron main;
    Postgres-scoped node IDs are normalized before blocker comparison, and accepted remote audits are
    mapped back only to the explicitly paired local Run.
17. Unsigned identity headers are disabled by default and unavailable to browser origins. Production
    Team writes require a signed session Cookie or paired Desktop Bearer Token.
18. A canonical remote Run can only be updated by its original authenticated sync creator; another
    project member cannot overwrite its status/current Node or lock it with a future timestamp.
19. Test, Agent Review, and Coding summaries must attach to a canonical Run owned by the same
    authenticated sync creator; project membership alone cannot inject evidence into another Run.
20. Test, Agent Review, and Coding child-summary identity is immutable across organization, project,
    Run, and Node scope. A reused ID with a different scope is a conflict, never an upsert target.
21. Child summaries upload first. Only an explicit canonical-Run-missing conflict may trigger one
    upload of the latest canonical Run followed by one child retry; an independent Lead override
    never republishes a creator-owned Run.
22. A delayed child summary cannot reactivate or block a non-current workflow Node. The canonical
    Run Summary alone owns team-side Run status and current-node progression.
23. Team-visible policy findings preserve their exact redacted blocker identity; count-only remote
    findings are insufficient. Coding structured metadata, cost, and budget fields pass strict
    allowlists and nested secret redaction.
24. Durable sync outbox, backoff, and operator-visible retry state are deferred to v1.4; v1.3 keeps
    local commits authoritative and uses the bounded canonical-missing recovery described above.

## Authoritative Write-Path Inventory

The closeout is not complete until every workflow write path has one explicit disposition:

| Existing write path | v1.3 disposition |
| --- | --- |
| `completeWorkflowAgentNode` | Dedicated command: reload, evaluate, transact |
| `approveGate` | Dedicated command: reload, evaluate workflow + policy, transact |
| Coding Runtime completion | Internal dedicated command using the same workflow runtime |
| `runProjectTests` | IDs only; reload, evaluate, run, transact |
| PR Draft | Dedicated command; reload, evaluate, transact |
| Acceptance Bundle | Dedicated command; reload, evaluate, transact |
| Final Acceptance | Dedicated Gate command with fresh evidence |
| Renderer `saveRun` | Remove from IPC contract, preload, and main handler |
| Renderer `saveArtifact` | Remove from IPC contract, preload, and main handler |
| Renderer `saveEvent` | Remove from IPC contract, preload, and main handler |
| Renderer-built `createRunningRun` mutation | Remove as a write mechanism |
| Renderer `uploadRunSummary` / `uploadTestEvidenceSummary` / `uploadCodingAgentSummary` | Remove from IPC contract and preload; main automatically syncs canonical local entities |
| Browser preview workflow fallbacks | Do not maintain a second state machine; fail closed for Agent, Gate, Test, PR, and Acceptance execution without Electron main |
| Legacy TestEvidence/Test Report/Event/Coding Event rows | Normalize and permanently rewrite on LocalStore open; leave unrelated Artifacts unchanged |

Direct invocation of removed or legacy generic IPC channels must be unavailable or return a hard
error, and must leave LocalStore unchanged. Merely stopping current UI call sites is insufficient.

## Execution Slices

### Slice 1: Workflow command core

RED:

- Reject non-current Gate/Acceptance approval.
- Reject writes on terminal Runs.
- Reject activation of a non-pending next node.
- Reject Acceptance missing Coding Diff, latest passing Test, PR Draft, Acceptance Bundle, policy
  authorization, or required review/budget evidence.
- Verify old pass plus newer failure is blocked.

GREEN:

- Add a shared discriminated workflow command and evidence snapshot evaluator.
- Return structured blocker codes and a pure Workflow mutation.
- Make Clarify/Design Gate approval require their corresponding artifacts.
- Preserve explicit Test failure/rerun semantics.

REFACTOR:

- Route existing agent completion and Gate helpers through the same invariants.
- Keep artifact formatting separate from authorization, but make public artifact creation reject an
  invalid evidence snapshot.

### Slice 2: Trusted Electron workflow runtime

RED:

- Test IPC no longer accepts a full renderer Run snapshot.
- Direct calls to legacy generic `saveRun`, `saveArtifact`, and `saveEvent` workflow channels are
  unavailable or rejected without changing LocalStore.
- A rejected command does not call the test runner or persist Run/Event.
- An injected Artifact/Event write failure leaves no partially advanced Run.
- Duplicate/stale commands cannot commit twice.

GREEN:

- Add a thin Electron workflow runtime that reloads the current aggregate from LocalStore.
- Add one transactional LocalStore workflow-mutation method.
- Replace renderer `saveRun/saveArtifact/saveEvent` delivery choreography with dedicated IPC
  commands.
- Remove the generic workflow entity save channels from the IPC contract, preload bridge, renderer
  API, and main handlers; LocalStore save primitives remain main-process implementation details.
- Commit locally before attempting remote summary upload.

HARD STOP:

- No renderer API accepts a complete `WorkflowRun` as authoritative input.
- `runProjectTests` accepts only IDs, and main reloads the latest Run before any runner side effect.
- No Clarify/Design/Build/Test/PR/Acceptance transition can bypass the shared evaluator.

### Slice 3: Build and Test continuity

RED:

- Coding Agent cannot start from a non-current Build node.
- Coding completion without a Coding Diff does not advance.
- Completed Coding Agent plus Diff advances Build to Test and survives reload.
- Failed/cancelled/timed-out Coding Agent or its worktree test failure does not advance.
- Test cannot run while Build is current.
- Passing Test advances Test to PR; failed Test remains current and blocks PR.

GREEN:

- Give Coding Runtime access to the authoritative workflow mutation writer.
- Remove renderer `createRunningRun` as a workflow write mechanism.
- Keep Coding Runtime worktree Test Evidence scoped to Build; do not silently use it as the
  independent Test-stage completion.

### Slice 4: PR and Acceptance continuity

RED:

- Non-current PR/Acceptance actions are hidden or disabled and rejected by Electron.
- PR rejects missing mapping, Diff, or latest passing Test, with no first-Team-Project fallback.
- PR success atomically saves artifact/event and advances to Acceptance.
- Bundle creation requires complete evidence but keeps Acceptance current.
- Final approval re-evaluates current evidence and policy; newer failure invalidates an older bundle.
- A second final approval is rejected without a duplicate event.

GREEN:

- Add dedicated PR Draft and Acceptance Bundle IPC handlers.
- Final Acceptance combines workflow readiness with Gate Enforcement authorization.
- Fix stage-specific success messages.

### Slice 5: Sync and project binding

RED:

- Same-ID remote Run with empty/lossy nodes never overwrites a complete local Run.
- Same-ID remote Artifact/Event always retains the local record.
- `remoteRunIds` marks only remote-only Runs.
- Team Sync never persists a lossy remote Run/Artifact/Event over a local workflow entity; the
  colliding local Run/Artifact/Event content remains unchanged after sync.
- Old paired credentials without a Local Project binding cannot perform remote writes.
- New pair requests without `localProjectId`, or with an unknown Local Project, are rejected.
- Pairing persists and reloads the selected Local Project binding.
- Every run/evidence/review/coding/policy/budget/override remote operation resolves the paired Team
  Project ID instead of a local project hash.
- PR uses only the bound Team Project repository.
- A project-scoped Desktop token cannot read or write another Team Project.
- Passing Test, Agent Review, or Coding summaries do not change the canonical remote Run status or
  current node and cannot create a missing canonical Run.

GREEN:

- Extend the stored pairing credential with an optional legacy-readable `localProjectId`, while
  making `{code, localProjectId}` mandatory for every new pair and verifying the Local Project
  exists.
- Add a central binding resolver and fail-closed remote write wrappers.
- Merge remote-only records while always retaining local records on collisions; Team Sync is a
  renderer/read-model merge and must never write lossy remote workflow entities into LocalStore.
- Scope paired-token sessions to their paired project without changing normal Web-owner semantics.
- Make Test/Review/Coding summary endpoints update evidence/read-model tables only. Require an
  existing canonical Run created by Run Summary, otherwise return a prerequisite conflict.
- Make Run Summary updates monotonic and reject attempts to move an existing Run across
  organization/project ownership.

HARD STOP:

- v1.3 implements paired-project scoping and closes the unsigned-header/browser write bypass;
  broader production auth and budget hardening remains out of scope.
- An unbound legacy credential is local-only until the user re-pairs; there is no inferred or
  first-project fallback.
- `remoteRunIds` contains exactly remote-only IDs, never a colliding local Run ID.

### Slice 6: Privacy and deterministic no-cost path

RED:

- POSIX, Windows, and `file://` forms of a known workspace path disappear from Test Evidence
  CWD/stdout/stderr.
- Secret redaction still applies after path replacement.
- Fake provider appears and resolves only with the fake-runtime flag.
- Fake provider never reads or writes a credential.

GREEN:

- Add exact known-root replacement first, then conservative cross-platform path/URL handling that
  preserves explicit API routes and web URLs before secret redaction.
- Expose and resolve `createFakeAgentProvider()` under the explicit fake-runtime flag.
- Update Electron smoke to use the built-in provider rather than an ad-hoc HTTP stub.

### Slice 7: Deterministic validation and runnable outputs

RED/GREEN:

- Normalize Windows relative paths in the demo-fixture boundary test.
- Pass `DEVFLOW_ENABLE_DEMO_DATA` into the API container during Docker smoke.
- Update E2E to reach the correct Gate before Knowledge Review; isolate service ports/state by
  default.
- Synchronize the already-modified knowledge Markdown with its embedded fixture copy.
- Add `test:build-output-smoke`.
- Produce minimal bundled API/Worker Node outputs with start scripts and verify clean-build startup.
- Add the required deterministic gates to Verify and Release workflows.

### Slice 8: Release metadata and signoff

RED/GREEN:

- Add pre-tag and tagged release-status modes.
- Set all package versions to `1.3.0` only after functional and automated gates are green.
- Create a clean candidate commit `C` containing the release code, docs, workflow, and aligned package
  versions, then run the candidate-wide gates and dated Computer Use walkthrough against `C`.
- Obtain explicit approval/credentials for the cost-bearing real opencode smoke and record only
  non-secret evidence.
- Create one signoff commit `S` whose first parent is `C`. The `C..S` diff must contain exactly
  `walkthrough.json`, `required-gates.json`, `real-opencode.json`, and the dated walkthrough result;
  all three JSON records must set `candidateSha` to `C`.
- Pre-tag mode runs at clean `S` and requires the version tag to remain absent. Tagged mode runs at
  the same `S` after tag creation and requires `v<rootVersion>` to resolve exactly to `S`.

## Stop Conditions

- Do not proceed to release verification while any generic renderer workflow-save channel remains
  usable or Test IPC still accepts a full Run.
- Do not proceed while Team Sync can persist a lossy remote workflow entity over LocalStore.
- Do not proceed while a legacy unbound pairing credential can perform any Team write or repository
  resolution.
- Do not run a paid provider or install/configure a real opencode provider without explicit user
  approval.
- Do not overwrite the 2026-07-25 failed walkthrough; add a new dated result.
- Preserve all pre-existing working-tree documentation changes and untracked files.
- Do not claim installer or production deployment completeness as part of v1.3.
