# DevFlow Studio v1.3：交付流程闭环

<a id="summary"></a>

## 摘要

v1.3 将 DevFlow 从擅长流程中段的工作台，扩展为连续的请求到交付流程。已有六阶段模型包含 `clarify`、`design`、`build`、`test`、`pr`、`accept`；v0.6–v1.2 已覆盖编码 Agent、测试证据、门禁执行、Agent 审查、预算守卫及团队同步。仍缺少的产品能力是流程连续性：

- 真实请求应创建初始工作流状态及原始请求产物；
- Gate 批准应通过 `workflow_edges` 推进当前节点；
- PR 和验收阶段应产出交付物，不再只是占位。

该里程碑不创建真实 GitHub PR。v1.3 创建可审查的 PR 草稿交接材料和验收证据包；在 v1.4 试点信任里程碑后，v1.5 才考虑接入 GitHub API。

<a id="key-changes"></a>

## 主要变更

<a id="v131-shared-workflow-core"></a>

### v1.3.1 共享工作流核心

- 在 `packages/shared` 增加 `createWorkflowRunFromRequest(input)`。
- 输入包含标题、原始请求、项目 ID、创建人 ID、分支名、Run ID 和时间戳。
- 输出包含：
  - 与既有领域模型一致的六阶段节点模板；
  - 从澄清到验收的工作流边；
  - 包含用户请求的 `raw_request` 产物；
  - 初始 `thinking` 事件。
- 保留请求构造辅助函数，通过 `evaluateWorkflowCommand(input)` / `applyWorkflowCommand(input)` 统一以下可信状态转换：
  - 澄清/设计 Agent 完成；
  - Gate 批准；
  - 开发完成；
  - 测试结果记录；
  - PR 完成；
  - 验收证据包挂接；
  - 最终验收批准。
- 每条命令检查当前节点、Run/节点不变量、成功的祖先、待处理的后代、证据归属及本次转换所需证据。

<a id="v132-desktop-request-intake-and-write-path"></a>

### v1.3.2 桌面请求录入与写入路径

- Electron `createRun` IPC 从“保存渲染进程构建的 Run”改为“接受请求输入，由主进程/共享层构建 Run”。
- 渲染进程仅传标题、请求、项目 ID、创建人 ID、分支名。
- 在同一个本地事务中创建 Run、产物和事件。
- Test、PR、Acceptance 和 Gate IPC 输入只传标识符；Electron 主进程重载正式本地状态并推导证据，不接受渲染进程构建的 Run 或产物。
- 通过 `commitWorkflowMutation` 提交已接受的工作流变更：更新的 Run 与候选产物/事件/测试证据在同一事务保存，检测过期 Run，失败时恢复快照。
- 浏览器预览对流程执行保持只读。缺少可信 Electron 主进程运行时时，Agent 完成、Gate 批准、Test、PR 和 Acceptance 动作均拒绝执行，避免 UI 测试和预览状态携带第二套工作流引擎。

<a id="v133-pr-draft-handoff"></a>

### v1.3.3 PR 草稿交接

- 在 `packages/shared` 增加 `createPrDraftArtifact(input)`。
- 草稿汇总：
  - 原始请求；
  - 已有设计摘要；
  - 编码差异产物中的变更路径；
  - 最新测试证据；
  - 门禁执行状态；
  - 预算决策；
  - Agent 审查摘要；
  - 项目仓库映射安全时的 GitHub 比较 URL。
- 不包含补丁原文、原始 stdout/stderr、提供方秘密或本地绝对路径。
- 桌面检查器在 `kind: 'pr'` 节点提供 `生成 PR Draft` 动作。
- 动作仅对当前运行中的 PR 节点有效，且要求已完成的 Coding Run、与之匹配的差异，以及最新通过的测试证据/报告。

<a id="v134-acceptance-evidence-bundle"></a>

### v1.3.4 验收证据包

- 在 `packages/shared` 增加 `createAcceptanceEvidenceBundleArtifact(input)`。
- 证据包引用：
  - 原始请求；
  - PR 草稿产物；
  - 变更路径；
  - 测试证据；
  - 策略状态；
  - 预算状态；
  - Agent 审查摘要。
- 桌面检查器在 `kind: 'acceptance'` 节点提供 `生成验收证据包` 动作。
- 只有当前验收节点已挂接 PR 草稿，且通过相同的编码/测试交付证据检查时，才接受证据包。
- 最终验收仍使用门禁执行，并额外要求已挂接证据包、获授权角色、不阻断的策略、匹配且不阻断的审查，以及不阻断的预算决定。

<a id="non-goals"></a>

## 非目标

- 不创建真实 GitHub PR。
- 不自动推送、合并或发布分支。
- 生成 PR 或验收产物后不自动绕过 Gate。
- 不增加数据库结构。
- 不执行 MCP 运行时。
- 不集成 RAG/向量检索。
- 不加固多桌面并发。
- 不增加持久远端同步发件箱、退避调度器或操作员重试控制台。

<a id="test-plan"></a>

## 测试计划

- 单元测试：
  - 从请求创建流程时产生六阶段、边、原始请求产物及初始事件；
  - 澄清/设计 Gate 批准推进 `currentNodeId` 和 Run 状态；
  - 验收批准完成 Run；
  - PR 草稿包含差异/测试/策略/预算/审查摘要及安全比较 URL；
  - 不安全仓库映射省略比较 URL；
  - 验收包引用请求、PR 草稿、差异、测试、策略、预算及审查。
- Electron/IPC：
  - `createRun` 接受请求输入并拒绝缺失字段；
  - Test/PR/Acceptance 输入只有标识符，不能注入渲染进程拥有的流程状态；
  - 可信运行时重载证据、拒绝过期/乱序命令，并原子提交已接受变更；
  - Gate 和最终验收批准使用共享命令语义。
- React/桌面端：
  - 新建 Run 弹窗发送标题/请求输入；
  - PR 节点显示 `生成 PR Draft`；
  - 验收节点显示 `生成验收证据包`；
  - 生成产物出现在检查器中。
- 验证：
  - 定向工作流/App/IPC 测试；
  - `corepack pnpm typecheck`；
  - 发布签收前运行默认 `corepack pnpm verify`。

<a id="release-criteria"></a>

## 发布标准

- 用户能从原始请求创建 Run，且只能按流程顺序推进。
- Coding、Test、PR 和 Acceptance 写入拒绝非当前动作及缺失/失败的必需证据。
- 缺少编码差异、通过的测试证据、PR 草稿、必需审查/策略证据或有效当前节点时，Run 不能完成验收。
- 已完成的本地 Run 在团队同步后保留完整流程、产物和事件。
- Local Project ↔ Team Project ↔ 仓库映射显式且已核实。
- 归档/展示的测试证据及远端摘要不暴露完整本地 cwd/路径；本地执行上下文留在可信桌面边界内。
- 确定性的 `verify:demo` 和 `test:electron-smoke`，以及单元/E2E、Windows、Postgres、Docker 门禁在同一候选版本通过。
- 全新发布构建输出可以按文档中的发布路径启动或安装。
- 仅用于发布的真实 `DEVFLOW_RUN_OPENCODE_SMOKE=1 ... corepack pnpm test:opencode-smoke` 在打标签前通过并记录。
- 带日期的电脑操作走查在同一候选版本通过，版本、标签和 HEAD 对齐。

- 桌面 `createRun` 接受请求输入，由 Electron 主进程/共享层构建流程。
- 含七类命令的工作流求值器统一 Agent/Gate/Build/Test/PR/Acceptance 转换。

- 配对将一个 Local Project ID 绑定到一个 Team Project；远端写入解析此绑定，对缺失或不匹配的旧绑定拒绝继续。Test/Review/Coding 子项先上传；仅明确的正式 Run 缺失冲突会上传最新 Run 并重试该子项一次。独立 lead 覆盖不重新发布创建人拥有的 Run。Postgres 节点 ID 为策略求值规范化，保存覆盖审计外键时恢复命名空间。
- 子摘要 ID 始终绑定原组织/项目/Run/节点作用域。只有正式 Run 摘要推进远端状态/当前节点；延迟子项不能重新激活旧节点。本地优先合并防止远端摘要覆盖同 ID 本地实体。
- 远端 Agent Review 保留精确阻断 ID 所需的最小脱敏意见详情；拒绝只有数量的意见。编码结构化元数据及嵌套费用/预算对象按白名单投影，路径/秘密脱敏后移除未知键，再保存到团队端。
- 未签名 `x-devflow-*` 身份请求头默认禁用，并拒绝浏览器来源；生产 Team 写入使用签名 Cookie 或已配对桌面 Bearer Token。显式本地冒烟会话要求 `DEV_AUTH_ENABLED=true`。
- `DEVFLOW_ENABLE_FAKE_RUNTIME=true` 显式开放确定性模拟 Agent 提供方，同时允许模拟编码引擎；模拟 Agent 路径不读取或解密已保存凭据。
- 测试证据归档前，先将已知 POSIX/Windows 工作区根路径替换为 `<workspace>`，再脱敏秘密；通用绝对路径/秘密过滤及数据库打开迁移，也覆盖派生测试报告、测试结果事件、孤立报告、编码 Agent 事件元数据、结构化元数据和嵌套费用/预算字段。
- API 和 Worker 构建打包为独立 dist 输出，`corepack pnpm test:build-output-smoke` 在工作区源码树外验证启动。
- Verify 和 Release 工作流包含构建/输出、E2E、Electron、Windows、Postgres、Docker 门禁；`release:status` 要求显式选择标签前或已打标签模式，以及绑定候选的证据。

2026-07-25 走查在早期候选中发现以下阻断：

- 即使从未运行编码 Agent，Build 没有产物、证据或轨迹，测试仍能隐式标记开发完成。
- Test 失败且 PR 等待时，仍能生成验收证据包。
- 最终验收可将 Run 标为完成，但 `currentNodeId` 仍指向失败的 Test。
- 已完成 Run 的团队同步，用有损远端摘要覆盖本地六阶段 Run。
- 缺少 Local Project ↔ Team Project/仓库映射，正常流程不能生成 PR 草稿。
- 测试证据仍暴露完整本地路径。
