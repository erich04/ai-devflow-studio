# DevFlow Studio v1.3: Delivery Flow Completion

## Summary

v1.3 moves DevFlow from a strong middle-of-flow workbench to a coherent request-to-delivery loop.
The existing six-stage model already has `clarify`, `design`, `build`, `test`, `pr`, and `accept`
stages, and v0.6-v1.2 already cover Coding Agent, Test Evidence, Gate Enforcement, Agent Review,
budget guard, and team sync. The missing product layer is workflow continuity:

- a real request should create the first workflow state and raw-request artifact;
- Gate approval should advance the current node through `workflow_edges`;
- PR and Acceptance stages should produce delivery artifacts instead of remaining placeholders.

This milestone does not create real GitHub pull requests. v1.3 creates a reviewable PR draft handoff
and an acceptance evidence bundle. After the v1.4 pilot trust milestone, v1.5 may turn the draft
into GitHub API integration.

## Key Changes

### v1.3.1 Shared Workflow Core

- Add `createWorkflowRunFromRequest(input)` in `packages/shared`.
- Input is title, raw request, project id, creator id, branch name, run id, and timestamp.
- Output includes:
  - a six-stage node template aligned with the existing domain model;
  - workflow edges from clarification through acceptance;
  - a `raw_request` artifact containing the user request;
  - an initial `thinking` event.
- Keep the request-construction helpers, and use `evaluateWorkflowCommand(input)` /
  `applyWorkflowCommand(input)` as the trusted transition boundary for:
  - clarification/design Agent completion;
  - Gate approval;
  - Build completion;
  - Test result recording;
  - PR completion;
  - Acceptance bundle attachment;
  - final Acceptance approval.
- Every command verifies the current node, Run/node invariant, successful ancestors, pending
  descendants, evidence ownership, and the evidence required for that transition.

### v1.3.2 Desktop Request Intake and Write Path

- Change Electron `createRun` IPC from "save a renderer-built run" to "accept request input and let
  main/shared build the run".
- Keep renderer input small: title, request, project id, creator id, branch name.
- Create the generated Run, artifacts, and event in one local transaction.
- Keep Test, PR, Acceptance, and Gate IPC inputs identifier-only; Electron main reloads canonical
  local state and derives evidence instead of accepting renderer-built Runs or artifacts.
- Commit accepted workflow mutations through `commitWorkflowMutation`: the updated Run plus
  candidate artifacts/events/Test Evidence are persisted in one transaction with stale-Run
  detection and snapshot restore on failure.
- Keep browser preview read-only for workflow execution. Agent completion, Gate approval, Test,
  PR, and Acceptance actions fail closed without the trusted Electron main-process runtime, so UI
  tests and preview state do not carry a parallel workflow engine.

### v1.3.3 PR Draft Handoff

- Add `createPrDraftArtifact(input)` in `packages/shared`.
- The draft summarizes:
  - original request;
  - design summary when present;
  - changed paths from Coding Diff Artifacts;
  - latest Test Evidence;
  - Gate Enforcement status;
  - budget decision;
  - Agent Review summary;
  - a safe GitHub compare URL when the project repository mapping is safe.
- Do not include raw patch bodies, raw stdout/stderr, provider secrets, or local absolute paths.
- Desktop Inspector exposes a `生成 PR Draft` action on `kind: 'pr'` nodes.
- The action is valid only on the current running PR node, after a completed Coding Run with its
  matching Diff and the latest passing Test Evidence/report.

### v1.3.4 Acceptance Evidence Bundle

- Add `createAcceptanceEvidenceBundleArtifact(input)` in `packages/shared`.
- The bundle references:
  - raw request;
  - PR draft artifact;
  - changed paths;
  - Test Evidence;
  - policy state;
  - budget state;
  - Agent Review summary.
- Desktop Inspector exposes a `生成验收证据包` action on `kind: 'acceptance'` nodes.
- The bundle is accepted only on the current Acceptance node after an attached PR Draft and the
  same Coding/Test delivery evidence checks.
- Final Acceptance still uses Gate Enforcement and additionally requires the attached bundle,
  authorized role, non-blocking policy, matching non-blocking review, and non-blocking budget
  decision.

## Non-Goals

- No real GitHub PR creation.
- No automatic push, merge, or branch publication.
- No automatic Gate bypass after generating PR or acceptance artifacts.
- No new database schema.
- No MCP runtime execution.
- No RAG/vector retrieval integration.
- No multi-Desktop concurrency hardening.
- No durable remote-sync outbox, backoff scheduler, or operator retry console.

## Test Plan

- Unit:
  - request-based workflow creation produces six stages, edges, raw-request artifact, and initial
    event;
  - clarification/design Gate approval advances `currentNodeId` and run status;
  - acceptance approval completes the run;
  - PR draft includes diff/test/policy/budget/review summaries and safe compare URL;
  - unsafe repository mappings omit compare URLs;
  - acceptance bundle references request, PR draft, diff, tests, policy, budget, and review.
- Electron/IPC:
  - `createRun` accepts request input and rejects missing request fields;
  - Test/PR/Acceptance inputs are identifier-only and cannot inject renderer-owned workflow state;
  - the trusted runtime reloads evidence, rejects stale/out-of-order commands, and commits accepted
    mutations atomically;
  - Gate and final Acceptance approval use shared command semantics.
- React/Desktop:
  - New Run modal sends title/request input;
  - PR node shows `生成 PR Draft`;
  - Acceptance node shows `生成验收证据包`;
  - generated artifacts appear in the Inspector.
- Verification:
  - targeted workflow/App/IPC tests;
  - `corepack pnpm typecheck`;
  - default `corepack pnpm verify` before release signoff.

## Release Criteria

- A user can create a Run from a raw request and advance only in workflow order.
- Coding, Test, PR and Acceptance write paths reject non-current actions and missing/failed required
  evidence.
- A Run cannot complete Acceptance without Coding Diff, passing Test Evidence, PR Draft, required
  review/policy evidence, and a valid current node.
- Completed local Runs retain their full workflow/artifacts/events after Team Sync.
- Local Project ↔ Team Project ↔ repository mapping is explicit and verified.
- Archived/displayed Test Evidence and remote summaries do not expose the full local cwd/path;
  local execution context remains inside the trusted Desktop boundary.
- Deterministic `verify:demo` and `test:electron-smoke`, unit/E2E, Windows, Postgres, and Docker gates
  pass on the release candidate.
- Fresh release build outputs can be started or installed using the documented release path.
- The release-only real
  `DEVFLOW_RUN_OPENCODE_SMOKE=1 ... corepack pnpm test:opencode-smoke` passes and is recorded before
  the release tag.
- A dated Computer Use walkthrough passes on the same release candidate, and version/tag/HEAD are
  aligned.

Implemented evidence:

- Shared workflow core added in `packages/shared/src/workflow.ts`.
- Desktop `createRun` now accepts request input and lets Electron main/shared build the workflow.
- A seven-command workflow evaluator now owns Agent/Gate/Build/Test/PR/Acceptance transitions.
- Electron main reloads canonical local state, and `LocalStore.commitWorkflowMutation` commits the
  Run plus candidate artifacts/events/Test Evidence atomically with stale-write rejection.
- Coding completion advances Build only after a matching completed Coding Run and Diff; a passing
  Test advances to PR, while a failed Test remains current and marks the Run failed.
- Desktop Inspector can generate PR Draft and Acceptance Evidence Bundle artifacts.
- PR and Acceptance commands reject non-current actions and missing/mismatched delivery evidence;
  final Acceptance additionally requires its attached bundle plus role/policy/review/budget
  approval evidence.
- Pairing now binds a Local Project id to one Team Project; remote writes resolve that binding and
  fail closed for missing or mismatched legacy bindings. Test/Review/Coding children upload first;
  only an explicit canonical-missing conflict uploads the latest Run and retries that child once.
  An independent Lead override does not republish the creator-owned Run. Postgres node IDs are
  normalized for policy evaluation and restored for persisted override-audit foreign keys.
- Child-summary IDs remain bound to their original organization/project/Run/Node scope. Only the
  canonical Run Summary advances remote status/current Node; delayed children cannot reactivate an
  older Node. Local-first merge prevents a remote summary from replacing a same-id local entity.
- Remote Agent Review preserves the minimal redacted finding details needed for exact blocker IDs;
  count-only findings are rejected. Coding structured metadata and nested cost/budget objects are
  allowlisted, path/secret-redacted, and stripped of unknown keys before team persistence.
- Unsigned `x-devflow-*` identity headers are disabled by default and rejected for browser origins;
  production Team writes use signed Cookies or paired Desktop Bearer Tokens. Explicit local smoke
  sessions require `DEV_AUTH_ENABLED=true`.
- `DEVFLOW_ENABLE_FAKE_RUNTIME=true` explicitly exposes the deterministic fake Agent provider as
  well as allowing the fake Coding Engine; the fake Agent path does not read or decrypt a stored
  credential.
- archived Test Evidence replaces the known POSIX/Windows workspace root with `<workspace>` before
  secret redaction; general absolute-path/secret filtering and database-open migration also cover
  derived Test Reports, Test Result Events, orphan reports, Coding Agent event metadata, structured
  metadata, and nested cost/budget fields.
- API and Worker builds are bundled into standalone dist outputs, with
  `corepack pnpm test:build-output-smoke` checking them outside the workspace source tree.
- Verify and Release workflows include build/output, E2E, Electron, Windows, Postgres, and Docker
  gates; `release:status` requires an explicit pre-tag or tagged mode and candidate-bound evidence.
- Electron smoke now resolves generated workflow node ids instead of depending on seed fixture ids,
  allocates an isolated port block, and asserts stable Web Evidence Chain/Human Gate surfaces instead
  of the removed `Team Console` label.
- Git status watcher replacement keeps one `destroyed` cleanup listener per `WebContents`; Electron
  smoke forces twelve resubscriptions and rejects `MaxListenersExceededWarning`.
- Manual guide added at `docs/guides/devflow-studio-v1.3-walkthrough.md`.

The 2026-07-25 walkthrough found these blockers in the earlier candidate:

- Tests can implicitly mark Build complete even when Coding Agent was never run and Build has no
  artifact, evidence, or trace.
- Acceptance Bundle can be generated while Test is failed and PR is still waiting.
- Final Acceptance can mark the Run completed while `currentNodeId` still points to failed Test.
- Completed-run Team Sync replaces the local six-stage Run with a lossy remote summary.
- PR Draft cannot be generated through the normal flow because Local Project ↔ Team
  Project/repository mapping is missing.
- Test Evidence still exposes full local paths.

The active closeout implementation addresses items 1-6 in code and adds the missing build-output and
release-status checks. Remaining release work uses two commits so the checked-in evidence does not
self-reference:

1. Create a clean candidate commit `C` containing the now-aligned `1.3.0` package metadata.
2. Re-run the candidate-wide deterministic gates and record them against `C`,
   including Windows, Postgres, Docker, build/output, E2E, and Electron smoke.
3. Run a new dated, fully paired Computer Use walkthrough against `C`, including PR Draft,
   Acceptance Bundle, final Acceptance, Team Sync, and restart persistence.
4. With explicit authorization for real provider usage, run and record the release-only
   `test:opencode-smoke`.
5. Create signoff commit `S` with first parent `C`; `C..S` contains only the three release JSON
   records and the dated walkthrough result, and every JSON `candidateSha` equals `C`. Run
   `corepack pnpm release:status -- --mode=pre-tag` at `S` while the tag is absent.
6. Only after pre-tag signoff, create the release tag at `S` and run
   `corepack pnpm release:status -- --mode=tagged`.
