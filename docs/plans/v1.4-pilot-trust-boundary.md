# DevFlow Studio V1.4 Pilot Trust Boundary — Execution Plan

Status: In progress

Baseline: `v1.3.0` / `06f3cc321300e3751aaa41c67f66d70cfaf6ebe4`

Development base: `b7b879c20f802dc8e4f2e27eb5413263b9998e37`

## Objective

Deliver the V1.4 scoped PRD through small, independently verifiable vertical slices while
preserving V1.3's canonical local state, scope immutability, redaction, evidence ordering, and human
Gate authority.

## Fixed Decisions

- Durable remote-sync outbox is a V1.4 release Must.
- An absent budget policy is not the same as an authenticated lead explicitly saving
  `enabled: false`.
- A real paid application runtime without a valid authoritative decision is blocked. The
  release-only provider smoke remains a separate explicit operation.
- Existing unsigned-header protections are tested and packaged safely; they are not rewritten
  without a demonstrated bypass.
- GitHub delivery stays in V1.5.
- Pilot packaging is unsigned and excludes installers, signing, notarization, and auto-update.
- API knowledge sourcing and Web/Desktop write authority require ADRs before their write paths land.

## Working Discipline

- Develop in `codex/v1.4-pilot-trust-boundary` from the clean post-V1.3 baseline.
- Do not stage or edit the user's modified guides, research note, `.zcode/`, `module.yaml`, or
  existing `work/` content in the main worktree.
- Use one RED → GREEN behavior at a time. Refactor only while green.
- Default tests must not call a paid provider.
- Do not start Docker until a Postgres, outbox, Web/API integration, or lifecycle slice needs it.

## Slice A1 — Coding Runtime Paid Budget Fail-Closed

### Tracer 1: guard dependency missing ✅

RED:

- A real paid Coding Engine without a budget guard returns a failed Coding Run before provider
  initialization/invocation.
- The failure is persisted as a redacted Run/Event and leaves no managed worktree.
- Fake/no-cost Coding remains usable without a guard.

GREEN:

- Replace the generic missing-guard allow fallback with a cost-aware unavailable decision.
- Use a precise unavailable summary rather than claiming every failure needs lead approval.

### Tracer 2: Team decision unavailable or invalid ✅

RED:

- Unpaired project, timeout/network error, 401/403, 5xx, and malformed 2xx budget response all block
  before provider initialization/invocation.

GREEN:

- Extract the Electron budget guard from `main.ts` behind a small testable interface.
- Add `unavailable` to the shared decision vocabulary.
- Runtime-validate the remote budget response before returning it to the runtime.

### Tracer 3: policy intent ✅

RED:

- Missing policy blocks as unavailable.
- An explicitly saved disabled policy remains an authenticated allow decision.
- Enabled policy allowed/warning/over-budget behavior remains unchanged.

GREEN:

- Separate missing from explicitly disabled policy in the shared evaluator.

### Tracer 4: approval scope ✅

RED:

- Wrong project, provider, requester, role, status, cost ceiling, or expiry cannot authorize a paid
  call.

GREEN:

- Bind approval validation to project and provider in addition to the existing fields.

### A1 hard stops

- No real paid Coding path may turn missing guard, pairing, auth, network, server, policy, or response
  validation failure into `blocksRun: false`.
- `engine.ensure` and `engine.start` are not called after a rejecting decision.
- A rejected attempt leaves no managed worktree.
- Fake/no-cost behavior remains explicit and green.
- No real provider is called by tests.

## Slice A2 — Knowledge Review Paid Preflight And Audit ✅

- Add the same paid decision contract before Electron and API `reviewKnowledge` invocation.
- Persist or server-audit rejected decisions without creating a fake successful Agent Review.
- Bind approvals to the exact project/provider/requester/cost/expiry scope.
- Cover fake/no-cost, missing policy, unavailable, malformed, over-budget, and valid approval paths.

The paid-runtime trust boundary is complete for the V1.4 Coding and Knowledge Review paths.

## Slice A3 — Authentication And Audit Closure ✅

- Prove unsigned headers are unavailable by default and for browser origins.
- Make pilot configuration reject `DEV_AUTH_ENABLED=true`.
- Audit remaining 401/403, membership, role, pairing, budget, and approval failures with redacted
  reasons.
- Fix code only where a failing negative test demonstrates a bypass.

## Slice B — Durable Remote-Sync Outbox ✅

- [x] Introduce versioned SQLite migration support before adding the outbox table.
- [x] Persist operation/entity IDs, stable idempotency key, status, attempt count, next attempt, and
  redacted error; never persist raw upload payloads.
- [x] Rebuild summaries from canonical LocalStore state at send time.
- [x] Add capped exponential backoff, restart recovery, terminal-error classification, manual retry,
  and operator-visible state.
- [x] Keep project binding immutable and preserve the exact V1.3 child-first/canonical-missing
  recovery.

## Slice C — Repository Knowledge Integration

- Build a bounded Electron main-process Markdown index service with path, symlink, size, and count
  controls.
- Feed one consistent snapshot into Gate, Knowledge Review, Coding Brief, and the Knowledge UI.
- Preserve the ADR rule that retrieval references are not Governance evidence.
- Decide API knowledge provenance in an ADR before connecting API Review.

## Slice D — Web Management Closure

- Land explicit project-scoped Run selection and the existing pairing panel first.
- Add Work Request and Gate command authority only after the Web/Desktop ownership ADR.
- Require signed session, membership, role, idempotency, expected versions, and server-side
  evaluation; do not duplicate the Electron workflow state machine.

## Slice E — Reproducible Pilot Lifecycle

- Define production API/Web images or bundles, environment allowlist, health contract, and migration
  entrypoint.
- Prove fresh deploy, retained-data upgrade, failed-upgrade recovery, and documented rollback
  compatibility.
- Keep lifecycle smoke separate from default `verify` where it requires Docker or mutable services.

## Verification Ladder

For each tracer:

1. Run the one new targeted RED test and record the expected failure.
2. Make the smallest GREEN implementation.
3. Re-run the targeted file.
4. Refactor only while green.

For a completed slice, run the relevant superset:

- `corepack pnpm typecheck`
- `corepack pnpm test`
- `corepack pnpm test:cross-platform`
- `corepack pnpm build` when package output changes
- `corepack pnpm test:electron-smoke` for Desktop end-to-end behavior
- `corepack pnpm test:postgres-smoke` for API/Postgres persistence or auth changes
- `corepack pnpm test:docker-smoke` for pilot stack/lifecycle changes

Any real paid smoke remains release-only and requires separate explicit cost authorization.
