## 负责人决定与授权边界

- 负责人明确要求使用本机已配置提供方凭据进行发布冒烟，并明确接受本次发布前不轮换它的风险。
- 执行者不得读取、打印、复制、粘贴、截图、序列化、提交或以其他方式暴露凭据值；证据中只能出现环境变量名。
- 每次绑定候选的顶层付费冒烟，只能由绑定该候选 SHA 的明确授权允许。获授权后恰可运行一次，不设硬性提供方费用上限，不允许无额度请求。内部精确允许三段获额度的提供方请求：仅 bash、仅 edit、仅完成。只有唯一批准的 bash 权限可激活 edit 段，只有唯一批准的 edit 权限可激活完成段；最多有一个待使用续行额度。
- 先前授权已被候选 `60617898adb40157e58d0da65bc84e3e42099cb1` 上失败的顶层冒烟消耗，不可转移。再次付费调用要求实质修复形成新候选、所有无费用门禁在该精确 SHA 通过，并取得该 SHA 的新明确授权。
- 默认测试、PR CI 和 Release CI 必须确定且不调用付费提供方。
- 负责人要求 Extra High 执行本计划时，可进行本地非破坏实现和验证。创建/更新 PR、分派远端工作流、合并、推送标签、发布 Release 是外部写入，只能在下方指定门禁进行。发布标签仍是最终明确决定点。

凭据风险接受决定在此留档，不为重复说明而在发布 JSON 增加含秘密或名称含 `credential` 的字段；发布验证器会主动拒绝敏感字段名。

<a id="release-topology"></a>

## 发布提交关系

执行分支预期第一父提交顺序如下：

```text
5b64354 -- P -- T -- D -- V/fixes -- C -- S
                                           \
                                            v1.4.0
```

- `P`：仅本计划，在 Extra High 开始前创建。
- `T`：支持版本的签收工具和完整候选 CI 契约。
- `D`：当前 V1.4 发布、操作手册及文档协调。
- `V`：自有包版本对齐 `1.4.0`。
- `C`：通过完整无费用矩阵的最终产品/工具/配置/文档提交；可等于 `V`。修复真实缺陷后，最终修复提交成为新 `C`。
- `S`：`C` 的直接子提交，恰含三份发布 JSON 及一份新的带日期候选走查结果。
- `v1.4.0`：精确解析为 `S` 的附注标签。

`C` 后不得修改产品、配置、测试、工作流、操作手册或普通文档；此类修改会使候选及全部绑定结果失效，必须形成新 `C` 并重跑完整矩阵。`C` 与 `S` 只能差四份证据文件。

<a id="failure-handling"></a>

### 失败处理

<a id="required-path"></a>

暂不提交结果；它与三份 JSON 一起进入 `S`。

<a id="phase-7--one-candidate-bound-paid-provider-smoke"></a>

## 阶段 7：一次绑定候选的付费提供方冒烟

仅当同一个 `C` 上全部本地无费用门禁、候选 CI、电脑操作均通过后进行。

<a id="preflight"></a>

### 预检

- 使用负责人选定提供方配置及本地安全配置中已有令牌。
- 确认令牌只通过环境变量名引用。
- 不运行 `env`、`printenv`、Shell xtrace 或可能回显值的诊断。
- `corepack pnpm --silent opencode:status` 是无费用预检；`--silent` 防止 pnpm 打印候选工作目录。
- 确认候选自有 V1.4 配置解析为提供方 `double`、模型 `ark-code-latest`、包 `@ai-sdk/openai`（Responses API）、基础 URL `https://ark.cn-beijing.volces.com/api/coding/v3`，且只有密钥引用 `{env:ANTHROPIC_AUTH_TOKEN}`；环境中的 OpenCode 配置不能覆盖它。显式设置 `DEVFLOW_OPENCODE_RELEASE_PROFILE=v1.4`；选择器/配置缺失或近似匹配都必须在 OpenCode 启动前阻止。状态输出应说明候选将应用内置 Responses API 发布配置；然后 `corepack pnpm --silent opencode:release-preflight` 经隔离、无网络的 `opencode debug config --pure` 核实解析出的包、基础 URL、模型及超时元数据，不打印解析 JSON。
- 确认负责人明确授权本次调用不设硬性费用上限；这只移除之前费用上限预检阻断，不授权无额度请求或第二次顶层付费冒烟。

<a id="invocation-boundary"></a>

### 调用边界

- `corepack pnpm --silent test:opencode-smoke` 只能启动一次绑定候选的顶层付费冒烟。
- `--silent` 仅抑制 pnpm 候选目录提示，不抑制冒烟结果或削弱其绝对路径/秘密检查。
- 顶层付费冒烟一旦开始，无论成功、失败或超时，均消耗本次授权。
- 受管进程禁用提问通道，会话拒绝不支持的 `question` 及子会话 `task` 权限。引擎只轮询精确父会话状态，丢弃重试消息/动作字段，首次观察到重试即以 `provider_retry_observed` 中止。每个初始/续行权限与状态发现段各有 240 秒边界，HTTP fetch 忽略取消时也必须拒绝继续；这不是整个冒烟的 240 秒期限。
- 真实发布配置必须使用候选自有凭据出站门禁。OpenCode 只收到假密钥及回环能力 URL，只有门禁可把真实密钥注入固定 Ark Responses 端点。门禁精确允许三段获额度的提供方请求（仅 bash、仅 edit、仅完成），强制唯一 bash 后 edit 批准顺序及最多一个待用续行额度。每段必须收到 SSE `response.completed` 终止事件；无额度/无效请求、无效批准、失败段或残留活动连接均永久拒绝继续。
- 不自动重跑顶层冒烟，不转发无额度请求。
- 第二次顶层付费冒烟要求实质修改后的新候选和新明确授权。

<a id="pass-criteria"></a>

### 通过标准

- 显式选择付费冒烟及真实 opencode 引擎/配置。
- 受管会话启动。
- 按 `bash -> edit` 顺序精确转交两个真实权限请求。
- 有工具调用/结果证据。
- 产生非空、脱敏、仓库相对路径的差异。
- 样例测试证据通过。
- 受管工作树清理通过。
- 输出和保留证据不含秘密、原始提示词、补丁、stdout/stderr 或本地绝对路径。

提供方未返回实际费用时不编造；只记录授权上限和已观察非敏感元数据，暂不提交结果。

## 阶段 9：标签前发布门禁、合并、打标签与发布

必须按以下顺序：

1. 推送 `S` 到已有 PR 分支。
2. 普通 Verify 在 `S` 通过，确认纯证据变更未破坏工作树。
3. 手动对分支/ref `S` 分派 Release 工作流。
4. 标签前运行必须通过，包括：

   - `release:status -- --mode=pre-tag`；
   - Windows、Postgres、Docker、Docker 生命周期作业；
   - 桌面产物构建及打包冒烟；
   - 非发布工作流产物上传成功。

5. 呈现 `C`、`S`、本地门禁摘要、CI URL、电脑操作结果、付费尝试结果及标签前 Release 结果，由负责人作最终发布决定；明确同意前不创建或推送标签。
6. 合并 PR 时不改写 `C` 或 `S`：

   - 不压缩合并；
   - 不变基合并；
   - 可行时优先快进；
   - 否则普通合并，确认 `S` 是 `origin/main` 祖先且合并树与 `S` 相同。

7. 发布成功前保留发布分支。
8. 确认本地/远端 `v1.4.0` 标签均不存在。
9. 创建精确指向 `S` 的本地附注标签：

```bash
git tag -a v1.4.0 <S> -m "AI DevFlow Studio v1.4.0"
```

10. 在 HEAD 为 `S` 的干净检出上，确保本地标签存在后运行：

```bash
corepack pnpm release:status -- --mode=tagged
```

11. 已打标签状态通过后才推送标签。
12. 等待标签触发 Release 工作流并核实：

   - 工作流 SHA 是 `S`；
   - 已打标签状态通过；
   - GitHub Release `v1.4.0` 存在；
   - 桌面归档包及完整性清单存在；
   - Web、API、Worker 产物存在。

纯远端基础设施失败可重跑无费用 CI；源码、证据或签收缺陷不能通过移动、删除或强推已发布标签掩盖，应停止发布声明并明确决定下一修正版。
