## Delivery Rules

- Use RED → GREEN → refactor for every behavioral slice.
- Keep each commit independently reversible and keep the branch green before starting the next
  slice.
- Do not widen V2.0 into V2.1 retrieval/Memory or V2.2 Multi-Agent work.
- Preserve deterministic Workflow, Gate, policy, budget, Desktop, Team, and GitHub Delivery authority.
- Default tests use fake decisions, fixture Tools/MCP, and fake/OpenCode contract fixtures with no
  paid provider calls.
- Team projections contain no raw prompt, source, patch, stdout, stderr, credential, or absolute path.

## Protocol Defaults And Hard Maxima

Defaults may be lowered by policy or scenario. Renderer/model input cannot raise the hard maxima.

| Bound | Default | Hard maximum |
| --- | ---: | ---: |
| Agent steps | 12 | 32 |
| Wall time | 10 minutes | 30 minutes |
| Tool/MCP calls | 16 | 64 |
| One Tool result | 64 KiB | 256 KiB |
| Trajectory event safe metadata | 16 KiB | 64 KiB |
| Checkpoint serialized safe state | 128 KiB | 512 KiB |
| Permission decision window | 60 seconds | 5 minutes |
| MCP startup | 10 seconds | 30 seconds |
| MCP call | 30 seconds | 2 minutes |

Cost/token budgets continue to use authoritative project policy and existing lead-approval rules;
the runtime adds consumed/remaining counters but no parallel budget source.

## Slice 1 — Runtime Domain And Deterministic Kernel

Outcome: shared pure contracts enforce bounds and state transitions without I/O.

RED:

- Reject malformed IDs/timestamps, unknown event/stop kinds, invalid bounds, oversized metadata,
  missing scope, capability-digest mismatch, sequence gaps, stale checkpoint versions, terminal
  continuation, late cancellation commits, and budget/step/deadline overrun.
- Prove one iteration creates at most one action and success never changes Workflow state.

GREEN:

- Add versioned Agent Runtime request, lifecycle, stop reason, trajectory event, checkpoint,
  evaluation, bound-counter, and redacted-summary types in `packages/shared`.
- Add a deterministic kernel that accepts one observation/decision/result at a time and returns the
  next persisted transition without performing I/O.
- Add the versioned V2.0 scenario manifest/parser and metric accumulator.

Verification:

- Shared focused tests, property/boundary matrices, typecheck, full unit suite, and cross-platform
  serialization checks.

Commit boundary: shared runtime kernel and scenario contracts only.

## Slice 2 — Durable Desktop Runtime

Outcome: Electron main owns crash-safe runtime execution and checkpoint/resume.

RED:

- Migration from Desktop schema 17 retains all 1.x state and creates no runtime rows.
- Atomic event/result/counter/checkpoint commit; injected crash before/after commit; exact replay;
  stale checkpoint; concurrent resume; cancel race; deadline/step/budget boundary; corrupt row; and
  restart recovery all fail safely.
- Renderer cannot submit paths, commands, capabilities, checkpoint contents, or terminal results.

GREEN:

- Add Desktop schema 18 for Agent runs, trajectory events, checkpoints, evaluations, capability
  grant references, and terminal summaries.
- Add main-process orchestrator, LocalStore transaction seam, strict IPC/preload DTOs, subscriptions,
  cancellation fencing, and startup recovery.
- Reuse the existing credential and project-authority boundaries.

Verification:

- SQLite migration/retention tests, local-store/runtime focused tests, Electron IPC negative tests,
  typecheck, Electron smoke, packaged pilot smoke, and restart probe.

Commit boundary: durable fake runtime with no native Tool/MCP/Coding side effects.

## Cross-Slice Invariants

- No Agent/Tool/MCP/Executor path can mutate Workflow or Gate state directly.
- Every external side effect has explicit authority, bounded input, deadline/cancel behavior, audit,
  and idempotency/reconciliation posture.
- Every durable write is versioned and uses optimistic concurrency.
- Full local evidence stays in Desktop; Team receives strict redacted summaries.
- Old Desktop/Team schemas retain 1.x data and fail closed for unknown 2.x authority.
- A failed or ambiguous operation never becomes success merely because a client timed out.
- New files are tracked and every slice ends clean, tested, documented, committed, and pushed.
