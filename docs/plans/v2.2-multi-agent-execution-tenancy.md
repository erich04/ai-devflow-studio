## Delivery Rules

- Use one observable RED → GREEN tracer at a time; refactor only while focused tests remain green.
- Keep commits reversible and preserve the full single-Agent baseline remains executable after every
  slice.
- Reuse V2.0 Agent Runtime, Tool/MCP, Coding Executor, trajectory, checkpoint, cancellation, and
  evidence contracts instead of creating parallel authority.
- Attenuate scope, capabilities, Context, resources, time, and budget before a Specialist can act.
- Reject cross-tenancy references before lookup or side effects and return one nondisclosing outcome.
- Never run two writers against the same mutable resource.
- Default CI and evaluation are deterministic and no-cost.
- Do not widen V2.2 into public SaaS, remote workers, recursive delegation, or an automatic V2.3.

## Slice 1 — Shared Coordination Domain

Outcome: pure versioned contracts reject malformed graph, tenancy, handoff, budget, and transition
state without I/O.

RED → GREEN tracers:

1. Parse one exact Coordination Session request; reject wider scope, unknown fields, bad versions,
   noncanonical timestamps/digests, and bounds above the parent or hard maxima.
2. Accept one bounded DAG and deterministic ready order; reject duplicate IDs, missing dependencies,
   cycles, disconnected hidden work, mutable terminal nodes, and depth above one.
3. Allocate a Specialist only for a ready task with a strict Context/capability/resource/sub-budget
   subset; reject a role, identity, grant, or budget escalation.
4. Accept one exact immutable handoff idempotently; reject conflicting replay, wrong tenancy,
   stale source/target, oversized summary, and unaccepted dependency result.
5. Apply monotonic task/session transitions, shared counters, stop/cancel propagation, and explicit
   failure attribution with property/boundary tests.
6. Parse the frozen dataset and compute the unchanged V2.0 single-Agent baseline deterministically.

Verification: shared focused tests, property/boundary tests, serialization/cross-platform tests,
shared typecheck, and full unit suite.

Commit boundary: shared pure domain and evaluator-baseline behavior only; no SQLite, renderer, Team,
Tool, or workspace effects.

## Slice 3 — Specialist Runtime And Attenuated Authority

Outcome: Electron main starts and joins bounded Specialist Runtimes using only strict subsets of the
Supervisor authority.

RED → GREEN tracers:

1. Register a fixed Specialist descriptor/role set; reject renderer/model/Team-created roles.
2. Derive one opaque task authority from exact current Supervisor/session/task versions and recheck
   Workflow, Node, policy, pairing, Context, capability, and tenancy before child creation.
3. Start one Specialist V2.0 Agent Runtime with exact child identity and sub-budget; prove a sibling,
   foreign tenant, stale task, or forged capability cannot access it.
4. Persist a terminal Specialist result and handoff atomically, then join dependencies once.
5. Attribute fail-fast and one explicitly allowed bounded recovery without silent reassignment or
   repeated effect.

Completed behavior keeps Specialist membership fixed in Electron main, derives every child from an
exact current Supervisor/session/task snapshot, and commits Runtime plus Coordination state through
one rollback-safe transaction. Success joins graph dependencies once. Failure derives a fixed safe
category from the accepted Runtime terminal transition and creates no handoff. The only Slice 3
recovery is one deterministic replacement for an exact failed read-only `repository_read` action;
it retains the task and agent identity, deducts observed usage, emits one `task_retried` audit, and
cannot repeat after the shared retry or child budget is exhausted. Mutable or ambiguous effects are
not made retryable by this slice.

Verification: main-owned authority tests, child Runtime parity, negative tenant/role/capability
matrix, restart tests, Desktop typecheck, and full unit suite.

Commit boundary: coordinator-to-Agent-Runtime integration only; no mutable Tool/workspace sharing.

## Slice 4 — Execution Tenancy And Resource Arbitration

Outcome: parallel coordination can use accepted resources without authority amplification or mutable
workspace races.

RED → GREEN tracers:

1. Grant concurrent read leases only for exact scope/capability/resource identity.
2. Grant one single-writer lease and reject a second writer, reader-to-writer upgrade, stale version,
   wrong task, or expired/cancelled commit.
3. Deduct Tool, token, cost, retry, and time use from Specialist and shared parent counters atomically;
   stop before the next side effect at the exact boundary.
4. Reuse V2.0 Tool/MCP/Coding Executor grants and reconciliation; prove coordination cannot transfer a
   grant or make an ambiguous effect repeatable.
5. Release/expire/cancel resources monotonically and join only a durable accepted lease outcome.

Completed behavior grants parallel reads and one exact writer only through Electron-main-owned
tenancy, task, Runtime, capability, resource digest, version, and time bounds. Active child Runtime
budgets are reserved from the shared parent before another child starts. Every Specialist Native
Tool, trusted Local MCP, and Coding Executor action reuses the V2.0 durable grant/audit seam and must
match one current lease; the same action cannot mint another grant, while a distinct action with the
same input remains valid. `settleCoordinationResourceLease` persists one monotonic release, expiry,
or cancellation with exact replay and rollback-safe failure handling. A Specialist cannot complete
or enter its bounded read-only recovery while a lease remains active, and success joins only after
all exact Runtime leases are durably released.

Verification: focused resource/budget tests, native Tool/Coding parity, concurrency races, retained
restart tests, and Electron smoke.

Commit boundary: resource and existing execution-boundary integration; no Team mutation authority.

## Slice 5 — Recovery, Cancellation, And Desktop UX

Outcome: developers can inspect, cancel, restart, and recover one bounded coordination session without
hidden authority or repeated effects.

RED → GREEN tracers:

1. Cancel once and prove every child Runtime, action, process, handoff, and lease is terminal before a
   late result attempts commit.
2. Cold restart one partially complete DAG and repeat zero accepted Specialist starts, handoffs, Tool
   calls, writes, joins, or terminal events.
3. Surface graph, roles, dependencies, bounds, resources, handoffs, failure attribution, cancellation,
   and recovery through a strict metadata-only renderer projection.
4. Keep all start/allocate/retry/cancel actions in Electron main with exact observed versions and
   explicit user confirmation where existing permission policy requires it.
5. Preserve the unchanged single-Agent UI/runtime path and compare it in packaged smoke.

Completed behavior derives the only supported three-task bounded repair plan inside Electron main,
keeps renderer input identifier/version-only, and exposes only strict redacted session, task,
handoff, lease, counter, and failure metadata. Resume and Specialist start revalidate the exact
Run/Node/policy/pairing/Context authority; confirmed parent cancellation atomically terminalizes
children and active leases before returning. Generic Agent Runtime startup recovery excludes both
Supervisor and Specialist runtimes referenced by the durable coordination tables, leaving their
single recovery owner intact across process restart. The packaged smoke starts exactly one
read-only Specialist, closes the application, reopens the exact partial DAG, proves session/task/
runtime/audit/checkpoint counts unchanged with `coordinationRestartDuplicateEffects: 0`, cancels it,
and completes the existing single-Agent GitHub Delivery, restart, Acceptance, and revocation path
without another provider, Git, Tool, or coordination effect.

Verification: shared projection tests, renderer-access/main IPC tests, component tests, real Electron
smoke, packaged cold restart, Desktop typecheck, and no-leak scans. The focused plan/store recovery
matrix passes 180 tests, the packaged contract passes 7 tests, and the rebuilt packaged Desktop gate
passes with exact coordination and delivery zero-repeat results.

Commit boundary: Desktop runtime/UX only; Team remains read-only and absent.
