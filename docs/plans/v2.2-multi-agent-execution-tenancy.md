<a id="delivery-rules"></a>

## 交付规则

- 每次完成一个可观察的先失败后通过流程，仅在针对性测试通过时重构。
- 提交可撤销，每批之后完整单 Agent 基线仍可执行。
- 复用 V2.0 运行时、工具/MCP、编码执行器、轨迹、检查点、取消与证据契约，不另建权限。
- 子 Agent 动作前收窄范围、能力、上下文、资源、时间和预算。
- 查询或副作用前拒绝跨租户引用，只返回统一不泄露结果。
- 同一可变资源绝不同时有两个写者。
- 默认 CI/评估确定且无费用。
- 不扩展公共 SaaS、远程 Worker、递归委托或自动延伸 V2.3。

## 第 1 批：共享协调领域

结果：纯版本化契约无 I/O，拒绝畸形图、租户、交接、预算和转换状态。

先失败后通过的验证路径：

1. 精确解析会话请求，拒绝更宽范围、未知字段、坏版本、非规范时间/摘要及超过父/硬上限的限额。
2. 接受有界 DAG 和确定性就绪顺序，拒绝重复 ID、缺依赖、循环、断开隐藏任务、可变终态节点及深度超过一。
3. 只为就绪任务分配子 Agent，上下文/能力/资源/子预算严格为子集，拒绝角色、身份、授权或预算提权。
4. 幂等接受精确不可变交接，拒绝冲突重放、错租户、旧源/目标、超大摘要及未接受依赖结果。
5. 属性/边界测试验证单调任务/会话转换、共享计数、停止/取消传播和显式失败归因。
6. 解析冻结数据集，确定性计算不变 V2.0 单 Agent 基线。

验证：共享/属性/边界、序列化/跨平台、共享类型和完整单测。

提交边界：纯领域/基线评估，无 SQLite、渲染器、团队、工具或工作区效果。

<a id="slice-3--specialist-runtime-and-attenuated-authority"></a>

## 第 3 批：专职运行时与权限收窄

结果：主进程只用监督 Agent权限的严格子集启动并汇合有界子运行时。

先失败后通过的验证路径：

1. 注册固定描述符/角色，拒绝渲染器、模型或团队创建角色。
2. 从精确当前监督 Agent/会话/任务版本推导不透明权限，创建前重核工作流、节点、策略、配对、上下文、能力和租户。
3. 精确子身份/预算启动 V2.0 运行时，证明兄弟任务、外租户、旧任务或伪造能力无法访问。
4. 原子保存子终态与交接，依赖只汇合一次。
5. 归因快速失败及一次明确允许的有界恢复，不静默改派或重复效果。

已实现：固定成员位于主进程，子任务均由精确当前快照推导，运行时及协调状态在同一可回滚事务提交。成功只汇合一次；失败从已接受终态推导固定安全类别，不创建交接。唯一恢复是对精确失败的只读 `repository_read` 确定性替换运行时一次，保留任务/Agent 身份、扣除已观察用量、记录一次 `task_retried`。共享重试或子预算耗尽后不能重复；可变/不确定效果不因此可重试。

验证：主进程权限、子运行时对等、租户/角色/能力否定矩阵、重启、桌面类型和完整单测。

提交边界：协调器到运行时集成，无可变工具/工作区共享。

<a id="slice-4--execution-tenancy-and-resource-arbitration"></a>

## 第 4 批：执行租户与资源仲裁

结果：并行协调使用已接受资源，不扩大权限或引起工作区写竞争。

先失败后通过的验证路径：

1. 仅为精确范围/能力/资源身份授予并发读租约。
2. 授予一个写租约，拒绝第二写者、读升写、旧版本、错任务或到期/取消后的提交。
3. 原子扣除子/父工具、Token、费用、重试及时间计数，到精确边界时在下个副作用前停止。
4. 复用 V2.0 工具/MCP/执行器授权及对账，证明不能转移授权或让不确定效果可重复。
5. 单调释放/到期/取消资源，只汇合已持久接受的租约结果。

已实现：并行读和精确单写者只能通过主进程拥有的租户、任务、运行时、能力、资源摘要、版本和时间限制授予。启动下一子任务前，从共享父预算预留活动子预算。每个子原生工具、可信 MCP 和编码执行器动作复用 V2.0 持久授权/审计接口，并匹配一个当前租约；相同动作不能再次签发授权，输入相同但身份不同的动作仍有效。`settleCoordinationResourceLease` 持久化单调释放/到期/取消，支持精确重放及可回滚失败。租约仍活动时，子任务不能完成或进入有界只读恢复；全部精确运行时租约持久释放后才汇合成功。

验证：资源/预算、原生工具/编码对等、并发竞争、保留重启及 Electron 冒烟。

提交边界：资源和已有执行边界集成，无团队修改权限。

<a id="slice-5--recovery-cancellation-and-desktop-ux"></a>

## 第 5 批：恢复、取消与桌面界面

结果：开发者可检查、取消、重启和恢复一个有界会话，不产生隐藏权限或重复效果。

先失败后通过的验证路径：

1. 一次取消后，全部子运行时、动作、进程、交接和租约在迟到提交前终止。
2. 部分完成 DAG 冷启动，已接受启动、交接、调用、写入、汇合及终态事件零重复。
3. 通过严格元数据投影展示图、角色、依赖、限额、资源、交接、失败归因、取消和恢复。
4. 启动/分配/重试/取消均留主进程，使用精确观察版本，现有权限规则要求时明确由用户确认。
5. 保留原单 Agent 界面/运行时，在打包冒烟中对比。

已实现：唯一受支持三任务修复计划由主进程推导，渲染器输入只含标识/版本，仅暴露严格脱敏会话、任务、交接、租约、计数和失败元数据。恢复和子启动重核精确 Run/节点/策略/配对/上下文；确认父取消在返回前原子终结子任务和活动租约。通用运行时启动恢复排除协调表引用的监督 Agent与专职运行时，保留其唯一恢复所有者。

打包冒烟启动恰好一个只读子角色，退出应用，再打开精确部分 DAG，证明会话/任务/运行时/审计/检查点计数不变且 `coordinationRestartDuplicateEffects: 0`；取消后完成既有单 Agent GitHub 交付、重启、业务验收和撤销，无额外模型、Git、工具或协调效果。

验证：共享投影、渲染器访问/主 IPC、组件、真实 Electron、打包冷重启、桌面类型和无泄露扫描。针对性计划/存储恢复矩阵 180 项、打包契约 7 项通过；重建打包门禁的协调/交付零重复通过。

提交边界：仅桌面运行时/界面，本批无团队投影，团队权限仍只读。

<a id="slice-6--redacted-team-projection"></a>

## 第 6 批：脱敏团队投影

结果：团队检查生命周期和比较质量元数据，不能读或控制本地工作。

先失败后通过的验证路径：

1. 团队模式 18→19 新摘要/审计表为空，不伪造行。
2. 上传绑定精确项目/Run/节点/会话及生命周期版本的严格单调摘要。
3. 只存计数、有界角色/状态、质量/费用/延迟/介入、失败类别、交接数和脱敏/隔离元数据，拒绝完整本地字段。
4. Web 严格只读，无创建/启动/分配/取消/重试/恢复/租约动作。
5. 种子/Postgres 一致地拒绝旧、重复冲突及跨项目摘要，不泄露信息。

验证：迁移/单测/路由/解析/Web、真实 Postgres、Docker 冒烟/生命周期、完整类型和脱敏扫描。

已实现：从精确持久会话推导严格标记脱敏/隔离的摘要，桌面模式 29 发件箱只入队稳定身份，上传前重建当前快照。团队模式 19 保存单调生命周期、角色/状态/失败数、有界用量、比较质量、延迟、介入及违规元数据，另存不可变版本审计；修改前拒绝原始任务详情、本地路径、旧/冲突重放及跨项目身份。种子/Postgres 语义一致，Web 精确键解析在异常时拒绝，面板没有本地执行控制。针对性 634 项、完整 3040 项测试、类型、生产构建、全新 PG16、Docker 冒烟及保留生命周期/迁移/回滚门禁通过。

提交边界：仅元数据团队投影与 Web 展示。
