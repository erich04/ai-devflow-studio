# V2.2 Formal Release Signoff

Status: Release procedure; no release result claimed

V2.0, V2.1, and V2.2 already have immutable feature-completion evidence. That evidence proves the
accepted 2.x milestones; it does not by itself publish `v2.2.0`. The formal release uses a new clean
candidate and separate `release-*` records so the historical milestone evidence is never rewritten.

## Release Identity

- All first-party package manifests declare `2.2.0`.
- `C` is one clean candidate commit containing all product, test, workflow, configuration, and
  ordinary documentation changes.
- The `Verify` workflow is dispatched against the exact SHA of `C`. Only its first successful
  attempt is accepted.
- `S` is the direct child of `C` and contains only the three formal release records plus their dated
  walkthrough result.
- The annotated tag `v2.2.0` points to `S`. Release artifacts are rebuilt and published only from
  that tagged signoff commit, while the Desktop archive is the exact candidate artifact downloaded
  from the recorded Verify run.

## Required Gates

The candidate-bound gate record must show passing results for:

- the production dependency audit, default verification suite, and Windows compatibility;
- V1.5 deterministic GitHub Delivery and its packaged smoke path;
- V2.0 Agent Runtime, V2.1 Retrieval and Memory, and V2.2 Multi-Agent evaluators;
- browser E2E, Electron smoke, Postgres integration, Docker smoke, and Docker lifecycle upgrade;
- production build, build-output smoke, Desktop pilot build, and packaged Desktop smoke;
- one private GitHub sandbox Draft PR walkthrough with restart, revocation, redaction, and cleanup
  checks.

The Verify workflow must upload `ai-devflow-studio-v22-candidate-desktop`. Its artifact index,
manifest, archive digest, version, platform, and architecture must agree exactly.

## Formal Evidence

After every gate passes for `C`, create exactly these files in `S`:

- `docs/releases/v2.2.0/release-walkthrough.json`
- `docs/releases/v2.2.0/release-required-gates.json`
- `docs/releases/v2.2.0/release-github-sandbox.json`
- `docs/guides/devflow-studio-v2.2-walkthrough-result-YYYY-MM-DD.md`

The records use the same bounded, secret-free release shapes as V1.5, but target `2.2.0`, Team
schema v19, Desktop schema v32, and the current candidate artifact. All four records use the same UTC
calendar date. They must not contain credentials, raw patches or provider output, repository
contents, or local absolute paths.

## Distribution Boundary

The supported release is a self-hosted source distribution with Web, API, Worker, and a
reproducible unsigned portable Desktop archive. Signed or notarized platform installers and a hosted
SaaS control plane are outside this release. The release notes must state this boundary plainly.

Real paid OpenCode execution remains an explicit local operator signoff path. It is not run by
default CI and no provider credential is stored in release evidence.

## Abort Conditions

Freeze a new `C` and repeat the matrix if any product, test, workflow, configuration, or ordinary
documentation changes after candidate verification. Do not create or move the tag when the worktree
is dirty, evidence targets another SHA, the recorded Verify run is not exact, a required gate is not
passing, or any formal record contains unsafe data.
