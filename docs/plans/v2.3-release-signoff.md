# V2.3 正式发布签署

状态：发布流程，未声称发布结果。

V2.0、V2.1、V2.2 已有不可变功能完成证据，证明里程碑验收，但不等于发布 v2.3.0。正式发布使用新干净候选及独立 release-* 记录，不重写历史证据。

<a id="release-identity"></a>

## 发布身份

- 全部自有包声明 2.3.0。
- C 为包含产品、测试、工作流、配置及普通文档的干净候选 commit。
- Verify 必须针对 C 的精确 SHA 手动分发，仅接受其首次成功尝试。
- S 为 C 的直接子提交，仅包含三份正式记录及带日期的验收结果。
- 附注标签 v2.3.0 指向 S。发布产物仅由该标签签署提交构建和发布；桌面归档使用记录的 Verify 运行所下载的精确候选产物。

<a id="required-gates"></a>

## 必需门禁

绑定候选的记录必须证明以下通过：

- 生产依赖审计、默认验证、Windows 兼容。
- V1.5 确定性 GitHub 交付和打包冒烟。
- V2.0 运行时、V2.1 检索/记忆、V2.2 多 Agent 评估器。
- 浏览器端到端、Electron、Postgres、Docker 及生命周期升级。
- 生产构建、构建输出冒烟、桌面试用包构建及打包桌面冒烟。
- 一次私有 GitHub 沙箱 Draft PR 真实验收，检查重启、撤销、脱敏及清理。

Verify 必须上传 `ai-devflow-studio-candidate-desktop`；索引、清单、归档摘要、版本、平台和架构必须完全一致。

<a id="formal-evidence"></a>

## 正式证据

C 的所有门禁通过后，S 只创建这四份文件：

- `docs/releases/v2.3.0/release-walkthrough.json`
- `docs/releases/v2.3.0/release-required-gates.json`
- `docs/releases/v2.3.0/release-github-sandbox.json`
- `docs/guides/devflow-studio-v2.3-walkthrough-result-YYYY-MM-DD.md`

复用 V1.5 有界、不含秘密的记录结构，目标为 2.3.0、团队 schema v28、桌面 schema v34 及本次候选产物。四份记录使用相同 UTC 日期，不得包含凭据、原始补丁/服务商输出、仓库正文或本地绝对路径。

<a id="distribution-boundary"></a>

## 分发边界

支持自托管源码，以及 Web、API、Worker 和可复现、未签名的便携桌面归档。不含签名/公证平台安装器或托管 SaaS 控制平面，发布说明必须直说。

真实付费 OpenCode 执行仍是明确的本地操作者签署路径，不进入默认 CI，发布证据不存服务商凭据。

<a id="abort-conditions"></a>

## 中止条件

候选验证后如产品、测试、工作流、配置或普通文档有任何变更，必须冻结新的 C 并重跑矩阵。工作区脏、证据指向其他 SHA、Verify 记录不精确、任一必需门禁未通过或记录含不安全数据时，不得创建或移动标签。
