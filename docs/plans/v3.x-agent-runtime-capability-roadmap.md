# V3.x Agent 运行时能力路线草案

状态：待审查草案，尚未纳入 `docs/roadmap.md`。

日期：2026-08-26

基线：AI DevFlow Studio 2.2.0 候选提交 `4ddd754`

<a id="purpose"></a>

## 目的

V3.x 将 DevFlow 的工作流和执行治理基础扩展为实用的通用编码 Agent。目标是建立同类核心能力层，同时保留 DevFlow 的显式作用域、权限、人工 Gate、证据、预算、受管工作树、重启安全及脱敏团队投影，而非逐屏复制 Claude Code。

源码对比表明，DevFlow 已有较强控制面，但模型驱动的实际执行能力仍不完整。草案选择以下产品顺序：

```text
V3.0 推理基础
  -> V3.1 原生编码工具
  -> V3.2 Skills 和 MCP 扩展
  -> V3.3 上下文与记忆质量
  -> V3.4 真实多 Agent 执行
  -> V3.5 无界面运行时产品化
  -> V3.6 Agent 工作台与 V3.x 收尾
```

该顺序不会把已有工作流或固定 V2.2 DAG 默认为 Agent 任务系统。会话 TaskProjection 纳入 V3.0 基础，持久后台管理器是 V3.4 前置条件。Schedule/Cron、Goal/Monitor、通知 Channels 和开放式后台自动化明确延后；计时器不得直接调用提供方。

<a id="current-release-boundary"></a>

## 当时的发布边界

以下保留草案编写时的状态，当前发布情况见[路线图](../roadmap.md)。当时 V2.0、V2.1、V2.2 功能里程碑已完成并推至远端候选分支，但正式 `v2.2.0` 签收仍未完成：发布专用证据提交、附注标签及已发布版本尚不存在。V3.x 可继续规划，但除非路线图明确例外，V3 实施应等待 V2.2 正式收尾。

<a id="v30-dependency"></a>

## V3.0 依赖

本次审查在当前检出、本地分支及已搜索工作区路径中，未找到另行编写的 V3.0 Markdown，因此本文不替代或重写 V3.0。

V3.1 及后续顺序假定 V3.0 交付源码对比识别的以下 P0 基础：

1. 仅追加、可重放的会话事件账本（Session Event Ledger）；
2. 流式提供方运行时，包含有类型的重试、取消、用量和回退事件；
3. 在已有有界 Agent 运行时内实现模型驱动的通用 Agent 循环；
4. 上下文预算及压缩（Compact），支持安全恢复和工具请求/结果配对；
5. 带版本的 `PromptSection` 和上下文组装契约，包含稳定前缀策略及 token 预算，高级检索质量可后续完善；
6. 持久化、提供方、工具、权限、凭据、工作区、时钟、事件及策略的宿主接口契约，Electron 主进程作为首个适配器；
7. 会话内 TaskProjection 表示 Agent 可见计划/进度，与确定性工作流节点及 V2.2 协调 DAG 分离；
8. 按轮次预算注入已有 V2.1 持久记忆和知识引用，不新建第二个记忆存储。

V3.1 实施前，必须链接实际 V3.0 文档并核对上述依赖。缺失基础留在 V3.0，不能悄悄移到更后版本。

会话 `fork` 和 `rewind` 指从更早事件创建新账本分支，不删除原始事件，也不撤销已接受的文件、Git、进程、工具或 MCP 副作用；这些效果需要补偿动作或人工恢复。

<a id="evidence-basis"></a>

## 证据依据

提案基于 2026-08-25 在相同 `4ddd754` 基线上的 Claude Code 对比。以下代码事实决定版本顺序：

| 既有资产 | 当时限制 | V3.x 处理 |
| --- | --- | --- |
| 共享 Agent 运行时状态机 | 边界/检查点较强，通用桌面路径实际近似单步 | 演进为唯一循环内核 |
| 原生编码执行器 | 固定计划/读取/编辑/测试/一次修复流程 | 产品路径改为通用循环，保留兼容证据 |
| 原生工具注册表 | 六类窄工具，授权/审计较强 | V3.1 扩展现有注册表，不创建另一工具运行时 |
| 提供方路径 | 主要为单次结构化 `/chat/completions` 请求 | V3.0 增加流式、重试、回退契约 |
| 本地 MCP | 可信 stdio 契约，产品接入较窄 | V3.2 完善生命周期，再独立治理远端传输 |
| V2.1 记忆 | 接纳、修订、过期、删除标记治理较强 | V3.0 注入，V3.3 提升质量，保持权限模型 |
| V2.2 协调 | 固定 DAG、租约、预算控制较强 | V3.4 接入运行共享循环的真实专职 Agent |

更广泛的工作编排缺口也明确处理：TaskProjection 是 V3.0 依赖，后台管理器是 V3.4 切片 1；调度器/监控/通知渠道自动化延后，不能误标为已有工作流或多 Agent 能力。

<a id="v3x-product-contract"></a>

## V3.x 产品契约

V3.x 结束时，开发者应能给 DevFlow 一个仓库目标，由 DevFlow 自有 Agent 产出可审查结果，并支持：

- 连续多轮会话、重启恢复、安全分叉、回退和压缩；
- 流式模型输出，基于真实环境反馈反复选择已授权工具；
- 搜索、读取、打补丁、运行有界命令和测试、检查 Git 状态，恢复时不重复已接受副作用；
- 按需加载受治理的技能、钩子、命令及 MCP 能力；
- 在相关轮次使用限定作用域的项目知识及持久记忆；
- 将有界工作委托给运行同一循环的专职 Agent；
- 通过 Electron 或无界面宿主运行，核心语义一致；
- 在统一开发界面呈现文件、诊断、终端输出、差异、会话、权限及证据。

Agent 成功仍不能批准 Gate、发布分支、创建/合并 PR、修改策略或扩大自身权限。

<a id="v32--governed-skills-and-mcp-extension-runtime"></a>

## V3.2：受治理 Skills 与 MCP 扩展运行时

### 结果

新增能力不必将每条流程硬编码进 Electron 主进程；所有加载内容和执行权限仍带版本、可检查且受策略约束。

### 交付切片

1. 定义 `SkillPackage`：带版本清单及 `SKILL.md`，可含脚本、素材、模板和引用；记录摘要、来源、依赖、权限及兼容性。
2. 增加技能加载器，支持内置、Team、项目、用户作用域，确定性优先级、显式启用、更新审查及回退。
3. 增加带版本命令及生命周期钩子；钩子可观察或请求动作，但不能绕过模型工具同样需要的能力/Gate 检查。
4. 增加工具搜索及按需加载定义，让 Skills/MCP 发现也通过该入口，使模型只看到相关定义。
5. 先完成可信本地 stdio MCP 生命周期：连接健康、重启、重连、能力刷新及 `list_changed`，保留精确安装权限。
6. 远端 Streamable HTTP、OAuth、资源和提示词作为独立冻结的 V3.2 切片；实施前需新 ADR 规定网络、凭据、回调、刷新及 Team/本地权限。没有 ADR，不能宣称远端 MCP 能力对齐。
7. 保存恢复和压缩后重建所需的精确已发现能力集合。
8. 增加包来源、可执行文件摘要、依赖锁、环境白名单、秘密访问及版本回退的供应链检查。

### 完成门禁

- 不改应用代码即可安装、审查、启用、发现、使用、停用和回退新本地技能。
- 本地 MCP 断开、重启、刷新工具列表并恢复会话时，不重复非幂等调用。
- 仅专门 ADR 和 HTTP/OAuth 反向测试矩阵通过后接受远端 MCP 完成；否则明确记为延后。
- 压缩和重启恢复精确的已启用 Skill/MCP 版本，不匹配则停止。
- 项目/Team 元数据不能直接选择可执行文件、凭据、cwd 或秘密值。
- 渲染进程和 Team 投影只呈现状态及安全来源，不暴露原始秘密或私有工具结果。

### 延后项

开放公共市场和自动执行未经审查第三方包不在范围内。

<a id="v33--context-and-memory-quality"></a>

## V3.3：上下文与记忆质量

### 结果

让 V3.0 上下文组装器具备可衡量价值：每轮从会话历史、项目规则、检索、Skills、MCP 状态、TaskProjection 及持久记忆组装最小相关上下文。跨会话学习不能把生成摘要视为事实。

### 交付切片

1. 在 V3.0 组装器上增加可测章节预算、相关性选择、稳定前缀复用和溢出诊断。
2. 改善现有逐轮知识/持久记忆注入，带来源、作用域、版本、新鲜度、置信度及效用依据。
3. 增加轮次/会话边界的记忆提取、去重、冲突处理、过期、人工/策略接纳及负反馈。
4. 完成三级上下文缩减：结果外存/截取、确定性微压缩、带持久边界的语义压缩。
5. 压缩后重建项目指令、计划、已启用技能、MCP 指令、已发现工具、引用及活动记忆。
6. 增加检索相关性、引用忠实度、记忆效用、压缩保留率、缓存复用及上下文溢出恢复的质量/费用评估。

### 完成门禁

- 长会话至少跨越两次压缩边界仍完成任务，工具请求/结果没有孤项。
- 恢复和分叉重现所选会话分支，回退保留原始事实。
- 必需项目约束及活动权限跨压缩保留，过期/删除记忆不重新出现。
- 在冻结的跨会话场景集上，长期记忆达到 V3.3 PRD 的质量和费用数值底线，无作用域泄露或无依据声明。
- 原始账本事件仍是审计来源；摘要和检索记忆仍是派生上下文。

### 延后项

未经审查的自修改系统提示词及自动接纳敏感记忆不在范围内。

<a id="v34--real-governed-multi-agent-execution"></a>

## V3.4：真实受治理多 Agent 执行

### 结果

V2.2 监督 Agent、DAG、租约、预算、重试和租户控制驱动真实专职 Agent。每个专职 Agent 与主 Agent 共用 V3 循环、提供方、账本、上下文、工具、Skills 和 MCP 契约。

### 交付切片

1. 增加持久后台任务管理器，明确归属、前后台转换、状态、结果通知、取消、重启恢复，禁止计时器直连提供方的捷径。
2. 用共享通用循环替代固定专职 Agent 结果生成。
3. 增加有界模型辅助任务分解，编译成现有已验证 DAG；运行时策略仍限制 Agent 数、深度、并发、重试、费用和墙钟时间。
4. 每个专职 Agent 拥有隔离会话分支、上下文预算、工具授权、记录及受管工作树或只读快照。
5. 增加持久邮箱、汇合、结果通知、取消及监督 Agent 综合结果。
6. 对并行成果增加冲突检测及确定性合并/审查规则。
7. 只投影脱敏团队级进度和证据；原始专职提示词、源码和输出留在本地。

### 完成门禁

- 一个有界任务分解为至少两个有用专职任务，并发执行、汇合并综合为可审查结果。
- 重启从各自一致账本/检查点恢复每个 Agent，不重复已接受外部效果。
- 父任务取消使子运行时、进程工作、租约和待处理权限进入终态。
- 跨 Agent 作用域、能力、工作区、会话、记忆访问尝试必须拒绝。
- 对比单 Agent 基线衡量质量增益及费用/延迟开销；仅在冻结评估表明有价值时使用多 Agent。

### 延后项

开放式群体、失控递归委托和远端不可信执行器不属于 V3.4。

<a id="v35--headless-runtime-productization"></a>

## V3.5：无界面运行时产品化

### 结果

将 V3.0 冻结的宿主接口契约变为受支持的第二宿主。Electron 仍是可信宿主，同一核心也能通过本地无界面接口用于自动化、测试和未来集成。

### 交付切片

1. 根据 V3.0–V3.4 使用情况稳定宿主接口兼容及版本规则。
2. 核实与宿主无关的循环、会话、上下文、压缩、工具选择及编排保留在共享运行时包，而非 Electron 编排文件。
3. 保留基于现有 SQLite、凭据、工作树、工具、MCP、工作流及策略服务的 Electron 适配器，增加等效本地无界面适配器。
4. 增加本地无界面 CLI/API，支持 start、attach、stream、pause、resume、fork、rewind、cancel、export 命令。
5. 对公开请求/事件/会话格式版本化，增加向后兼容迁移测试。
6. 同一一致性套件分别运行 Electron 和无界面宿主。

### 完成门禁

- 同一确定性会话在两宿主产生等效的有序运行时事件和终态结果。
- 业务决策不直接依赖 Electron IPC 或渲染类型。
- 凭据、路径、工具执行和持久化由宿主适配器拥有，共享核心无显式接口不能访问。
- 无渲染进程运行时，无界面会话仍可中断及恢复。
- 不引入重复运行时状态机或并行事实来源。

### 延后项

托管 SaaS 执行、公开远端控制及多租户提供方凭据托管不属于 V3.5。

<a id="v36--agent-workbench-surface-and-v3x-closeout"></a>

## V3.6：Agent 工作台与 V3.x 收尾

### 结果

让运行时能力适合日常开发，易理解且高效；通过绑定候选的运行时评估完成 V3.x 验收，避免被嵌入式 IDE 的庞大范围阻塞。

### 交付切片

1. 增加仓库树、全文搜索、变更文件导航及有界文件上下文。
2. 增加集成进程/终端输出视图和带版本诊断适配器；V3.x 运行时验收不要求嵌入编辑器或广泛 LSP 客户端。
3. 增加行内差异、部分接受/拒绝、安全情况下的补偿撤销及精确证据关联。
4. 增加会话时间线、分叉/回退/压缩标记、权限、Agent/子 Agent 状态、工具/MCP 健康、token/费用预算及失败处理建议。
5. 冻结覆盖单 Agent、长会话、工具、Skills、MCP、记忆、多 Agent、无界面一致性和开发者走查的 V3.x 能力评估。
6. 打标签前运行完整单元、集成、迁移、Electron、打包、无界面、跨平台、安全、确定性求值器及显式有界真实提供方门禁。

### 完成门禁

- 新用户能打开仓库、启动/恢复受治理会话、查看流式工作、回答权限、审查诊断/差异、运行测试，并将结果交回工作流。
- 打包桌面端和无界面宿主通过同一运行时一致性套件。
- 冻结评估记录质量、恢复、费用、延迟、人工干预、隔离、脱敏和重复副作用指标。
- 精确候选、不可变证据、标签及已发布产物一致前，不宣称 V3.x 完成。

### 延后项

嵌入式编辑器、完整 LSP 语言矩阵、调试器、扩展市场、远端协同编辑及逐功能对齐 Claude Code 界面，需另行批准未来范围。

<a id="cross-version-engineering-rules"></a>

## 跨版本工程规则

- 不创建第二 Agent 运行时；演进共享内核，让桌面、原生编码和专职 Agent 经适配器使用。
- 演进已有资产：会话账本扩展 Agent 轨迹；V3.1 扩展 `native-tools`；V3.3 扩展 ADR 0018 记忆生命周期；V3.4 将共享循环接入 ADR 0019 协调 DAG；无界面执行使用同一内核。
- 工作流、Gate、策略、证据及发布权限保持在 Agent 循环之外。
- 会话账本是持久事实，检查点是可恢复运行时状态，压缩是派生上下文投影，Git 提交是仓库历史。
- 保存可观察输入、决定、工具动作、结果、用量及停止原因，不保存提供方隐藏推理。
- 默认 CI 确定且无费用；真实提供方测试须显式、有界、绑定候选。
- 每个副作用都需幂等，或明确在结果不确定时停止并人工恢复。
- 每个版本以冻结契约/评估切片开始，以绑定候选的证据结束。
- 没有另行批准移除计划前，保留 V2.x 数据、迁移、本地隐私、Team 脱敏及 OpenCode 兼容。
- Schedule/Cron、Goal/Monitor、通知 Channels、开放式后台自动化及计时器触发提供方执行不在 V3.x 范围内；除非之后路线图正式纳入并定义权限、持久化、预算及取消契约。

<a id="promotion-checklist"></a>

## 纳入正式路线图的检查清单

仅在以下条件满足后，草案才可纳入活动路线图：

1. V2.2 正式发布收尾完成，或明确记录顺序例外；
2. 链接实际 V3.0 Markdown，完成门禁满足 V3.1 依赖；
3. 每个提议版本都有负责人批准的需求、ADR 集合、可执行计划、求值器契约和有限非目标；
4. 版本数量/范围作为规划边界被接受，不自动承诺交付全部条目；
5. `docs/roadmap.md` 仍是活动版本及下一门禁的唯一事实来源。
