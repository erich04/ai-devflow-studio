# 产品界面与各层职责

<a id="desktop-workbench"></a>

## 桌面工作台

开发者的主要操作界面。当前结构来自[以开发任务为中心的工作区改造](../../plans/task-centered-workspace-redesign-2026-09-28.zh-CN.md)。

必要界面区域：

- 一级导航：任务、知识、团队、设置。
- 顶栏：项目菜单（选择本地仓库、任务列表、团队请求收件箱及「创建本地任务」）、搜索、团队连接弹层、主题图标、新建任务。团队连接弹层只显示连接、团队数据、结果上传三类状态的摘要和「更新团队数据」；配对在设置 › 团队连接中完成。
- 任务页标题行：任务菜单、本任务用量、「讨论」开关。
- 六阶段导航：子步骤并入各阶段项，不单独占行。
- 状态行：一行写明结论、一个主动作和可见的次要动作；停止、取消和拒绝始终可见。结论与按钮来自同一份状态投影。
- 三个页签：当前工作、材料与版本、执行记录。门禁审查、编码执行和测试都在任务内运行，没有单独的 Agents 页和测试页。
- 需求阶段只有一个版本阅读器。方案评审的审批发送所显示方案的 `{artifactId, updatedAt, contentDigest}`，版本过期或缺失时由主进程拒绝。
- 材料与版本页签按当前待处理、已确认依据、原始输入与参考、讨论提案、历史记录分组。
- 项目讨论（项目范围的独立会话）默认收起，从标题行的「讨论」在右侧展开。
- 设置：
  - 本地项目：仓库、测试命令。
  - 模型与执行方式：模型提供方与凭据、项目执行工具。团队预算只读显示，在 Web 的设置 › 预算中修改；一次性预算批准保留在桌面端。
  - 扩展能力：Skills、MCP。
  - 团队连接：配对码输入与「连接／重新连接」、连接详情、团队数据更新、结果上传状态。替换现有连接前，先确认会被替换的连接和会被撤销的交付。
  - 外观：主题。
  - 高级：诊断、脱敏自检、本地数据。
- 知识页：仓库 Markdown 索引、按文档分组的引用来源、知识图谱。
- 团队页：团队项目的进度摘要。
- GitHub 交付的准备、修订（Revise）、继续（Resume）、重试（Retry）、停止（Stop）控件及状态。

桌面端拥有本地执行权。Electron 主进程从权威托管工作树派生交付意图，只在活动发布尝试期间持有限定仓库的短期 GitHub App 安装令牌。渲染进程只能收到状态，绝不接收凭据。桌面端可以展示不得原样同步给团队的私有详情。GitHub 交付不会合并。

<a id="web-team-console"></a>

## Web 团队控制台

团队处理待办、了解项目状态的界面。

必要界面区域：

- 一级导航：我的待办、项目任务、团队、设置。
- 我的待办：当前项目中待处理的 Gate（需求确认、方案评审、其他 Gate、业务验收）、待审交付和异常。写明团队数据的读取时间；数据未能读取时说明列表不完整，不显示“没有待办”。没有审批权限的成员看到“等待负责人审批”。
- 项目任务：团队请求（新建与列表）和只读的任务列表。
- 任务详情（`?projectId=&runId=`）：
  - 状态事实，包括数据时效。
  - 审批：所审材料的版本取自桌面端上传的审查对象快照，并写明所需角色和你的角色。需求确认、方案评审 Gate 没有快照时不能批准；Lead/Owner 始终可以驳回。
  - 交付审批：目标仓库、分支、预期提交、改动文件、验证范围、请求修订号，完整标识在「技术详情」中；只有 Lead/Owner 可以批准或驳回精确修订。审批后继续显示交付进度，直到草稿 PR 创建完成。
  - 进度与材料：六个阶段的步骤，含业务验收。
  - 执行摘要（只读）：执行记录、门禁审查、测试证据、团队记忆、多 Agent 协作。
  - 项目预算、策略与警告的摘要，链到对应设置。
- 团队：成员、项目费用、最近的任务与测试证据。
- 设置：预算、策略、桌面连接（生成配对码）、GitHub 仓库（GitHub App 仓库绑定与撤销，只有 Owner 可以修改）。
- 旧链接：带 `projectId` 与 `runId` 的链接直接打开任务详情；`view=team`、`view=settings` 照旧解析；`/legacy-shell` 重定向到团队页；项目页上的旧锚点 `#runtime`、`#policy`、`#work-request` 分别跳到设置 › 预算、设置 › 策略和项目任务。

Web 只展示脱敏后的团队数据，不展示本地原始执行详情；需要原始差异时，到有权限的桌面端查看。旧链接只负责定位，服务端仍按当前身份校验权限。

<a id="api-backend"></a>

## API 后端

团队状态和策略的权威来源。

必要职责：

- 认证会话和项目成员身份。
- 团队概览。
- 项目创建与按成员身份控制的项目访问。
- 桌面配对。
- 接收脱敏同步。
- 策略和预算持久化。
- 使用检索到的知识为依据，执行针对当前 Gate 和阶段产物的门禁审查。
- GitHub App 私钥权限、仓库绑定/撤销，以及限定范围的凭据授权元数据。
- 脱敏交付请求持久化、签名 Web 审批、远端提交核验、草稿 PR 创建或核对。

<a id="shared-domain-core"></a>

## 共享领域核心

跨运行时复用的产品逻辑。

必要职责：

- 领域类型。
- 工作流创建与推进。
- 产物创建辅助函数。
- Gate 策略评估。
- 知识治理。
- 预算保护逻辑。
- 满足脱敏要求的契约。
- 交付系列/尝试/修订校验、动作转换，以及启用 GitHub 的业务验收证据要求。

GitHub 交付（GitHub Delivery）的草稿 PR（Draft）完成证据与业务验收（Acceptance）决定分别保存。
