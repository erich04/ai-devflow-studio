# DevFlow Studio V1.4：试点信任边界需求

生命周期：已作为 `v1.4.0` 发布；当前发布与里程碑状态以 `docs/roadmap.md` 为准。

历史规划快照：实现已完成；候选版本形成和正式签收待完成。

当时的发布基线：`v1.3.0`

里程碑负责人：DevFlow Studio 维护者

<a id="product-outcome"></a>

## 产品目标

V1.4 将 V1.3 从请求到交付的流程扩展为可信的外部试点边界。团队使用真实提供方和协作流程时，不能因为依赖缺失或不可用，就悄悄绕过身份认证、预算、证据、脱敏或恢复控制。

V1.4 仍是自行托管的试点，不扩展为公共 SaaS 产品或自主交付机器人。

<a id="release-musts"></a>

## 发布必须项

1. **付费运行时可信性：**权威预算上下文缺失、无效、未认证、超出作用域或不可用时，拒绝真实付费提供方调用。模拟和已确认无费用的路径保持显式、确定。
2. **身份认证可信性：**联网的 Team 写入使用签名会话 Cookie 或已配对桌面端的 Bearer Token。未签名身份请求头仅限显式本地演示/测试模式，试点部署配置不得启用。
3. **持久远端同步：**正式 Run、Test、Review 和 Coding 摘要任务在重启后仍可恢复，采用有界退避，向操作员呈现恢复状态，并保持 V1.3 子证据先上传及正式 Run 归属不变量。
4. **仓库知识：**真实仓库 Markdown 索引进入 Electron Gate、知识审查和编码上下文。API 审查仅使用另行授权的服务端或已批准脱敏知识源；不得隐式上传本地仓库内容。
5. **Web 管理闭环：**已认证用户可以创建工作请求、选择 Run、创建桌面配对码、提交经过角色检查的 Gate 操作，同时保持单一工作流状态机。
6. **可复现试点生命周期：**未签名的 Electron/Web/API 试点包具备显式配置契约，以及全新部署、保留数据升级和有限回退的自动冒烟验证。

持久化发件箱是 V1.4 发布必须项。README、基线需求、后端数据源矩阵及 V1.3 收尾计划已经承诺该能力，本次不能再次推迟。

<a id="paid-runtime-decision-contract"></a>

## 付费运行时决策契约

必须在初始化或调用真实提供方之前完成决策。拒绝时留下可理解、经过脱敏且持久保存的证据，不得残留受管工作树。

| 运行模式 | 要求结果 |
| --- | --- |
| 显式模拟提供方或可信预计费用 `<= 0` | 按无费用路径允许；不得称为预算批准的付费使用。 |
| 真实付费运行时未配置预算守卫 | 以 `unavailable` 阻止。 |
| 真实付费运行时缺少 Local Project 到 Team Project 的绑定 | 阻止并引导操作员配对项目。 |
| 已绑定团队的付费运行时遇到超时、网络故障、401/403、5xx 或格式无效响应 | 以 `unavailable` 阻止，保留本地状态。 |
| 已绑定团队的付费运行时没有已保存策略 | 阻止并引导 lead 配置策略。 |
| 已绑定团队的付费运行时有显式保存的 `enabled: false` 策略 | 作为经过认证的管理决定允许，明确区别于策略缺失/不可用。 |
| 已启用策略且未超限 | 以 `allowed` 或 `warning` 允许。 |
| 已启用策略且超限，没有有效批准 | 以 `requires_lead_approval` 阻止。 |
| 已启用策略且超限，有匹配且未到期的批准 | 以 `approved_over_budget` 允许。 |

预算批准只对精确匹配的项目、提供方、请求人、额外费用上限、角色、状态和有效期生效。TypeScript 类型断言不能代替响应校验；桌面端必须在运行时拒绝格式无效的预算决定。

仅用于发布的真实提供方冒烟验证，仍是独立且需明确授权的签收操作，不能形成应用运行时的绕过通道。

<a id="authentication-contract"></a>

## 身份认证契约

- 生产和试点浏览器请求不能通过未签名请求头构造身份。
- 桌面端 Team 写入必须使用配对项目的 Bearer Token 和不可变项目绑定。
- 演示请求头要求显式开发标志、仅限回环地址的部署契约，且没有浏览器 `Origin`。
- 审计安全的输出应区分认证、成员身份、角色、作用域及决策失败，且不能泄露 Cookie、Bearer Token、API 密钥或提供方凭据。

V1.3 已默认关闭未签名请求头，并拒绝带浏览器来源的请求使用该方式。V1.4 验证试点配置中的边界、补齐失败路径；没有证据表明可绕过时，不重写已有认证代码。

<a id="durable-sync-contract"></a>

## 持久同步契约

- 发件箱只保存实体标识和操作元数据，绝不保存提供方原始提示词、stdout、stderr、补丁、凭据或序列化上传载荷。
- 发送时从正式 LocalStore 状态重新构建脱敏摘要。
- 稳定幂等键防止重复逻辑任务。
- 可重试失败采用有上限的退避；认证、作用域、不可变 ID 冲突等终止性失败应向操作员可见，不得无限重试。
- 重启恢复待处理任务；重新配对不能把旧任务发送到其他 Team Project。
- 子证据仍先上传。只有精确的正式 Run 缺失响应，才允许上传一次正式 Run，然后重试子项一次。
- 有损远端摘要不能覆盖更完整的本地状态，也不能推进本地流程。

<a id="repository-knowledge-contract"></a>

## 仓库知识契约

- Git 管理的 Markdown 是事实来源。
- Electron 主进程负责仓库路径解析、文件访问、索引、限额及符号链接/路径越界防护；渲染进程输入不能选择任意特权文件。
- 知识引用包含来源路径、章节、策略、评分和内容哈希。
- 检索引用为人和 Agent 提供参考，本身不能满足治理检查或批准 Gate。
- API 审查不能通过隐式同步旁路获取桌面仓库原文。

<a id="web-authority-contract"></a>

## Web 权限归属契约

Team 服务拥有工作请求和协作命令；桌面端继续拥有私有本地仓库执行权及完整的正式本地 Run。

- Web 需求录入创建带版本的工作请求，不能伪造本地 Run。
- 桌面端显式认领请求并创建/绑定正式本地 Run。
- Web Gate 操作是经过认证和角色检查的命令请求，携带预期 Run/策略版本，不能直接修改有损 Run 摘要或绕过本地证据检查。
- 显式 Run 选择应稳定且限定在项目内。
- 当前 Web 界面可创建配对码，不得暴露已有令牌。

在实现这些写入路径前，必须通过 ADR 明确工作请求和 Gate 命令的归属模型。

<a id="pilot-package-contract"></a>

## 试点包契约

V1.4 试点包指可复现、未签名的产物和容器，具备有文档说明的输入、健康检查、迁移及生命周期冒烟测试，不包含：

- 签名/公证安装器；
- 自动更新（`auto-update`）；
- 托管云部署；
- 公开分发基础设施。

回退支持必须说明数据库结构兼容窗口。旧应用不能读取升级后的结构时，回退测试不能宣称安全。

<a id="non-goals"></a>

## 非目标

- 真实 GitHub 推送、PR 创建、合并或分支发布（留给 V1.5）。
- 公共 SaaS、计费、企业 SSO、托管多租户或托管提供方凭据。
- 真实 MCP 执行、多 Agent 编排、向量/完整 RAG 检索。
- 仓库监听器、应用内 Markdown 编辑器或隐式远端知识同步。
- 完整的多桌面冲突处理及协作加固（留给 V1.7）。
- 签名安装器、公证、自动更新或真实 Windows 安装器签收。

<a id="release-acceptance"></a>

## 发布验收

每一项发布必须项都必须对同一个候选提交 SHA 留下已提交证据，V1.4 才算完成：

- 决策缺失、无效、不可用、未认证或超出作用域后，绝不调用付费编码和知识审查提供方；
- 预算批准作用域及响应校验的反向测试通过；
- 未签名请求头及试点配置反向测试通过；
- 发件箱重启、去重、退避、终止性错误、手动重试及重新配对隔离测试通过；
- Gate、Review 和 Coding 一致使用同一仓库知识快照，不上传仓库原文；
- Web 请求、选择、配对及 Gate 命令流程通过认证角色/作用域测试；
- 全新部署、保留数据升级及声明的回退窗口验证通过；
- 默认验证保持确定且无费用，任何付费签收另行批准。

包版本对齐与发布证据应在形成候选版本时进行，而非开发开始时。
