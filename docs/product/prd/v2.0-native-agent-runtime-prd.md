# V2.0 原生 Agent 运行时基础需求

状态：已批准实施；已由绑定候选的 V2.0 证据证明完成

日期：2026-08-12

路线图位置：V1.5/1.x 发布完成门禁之后的首个 2.x 里程碑

<a id="summary"></a>

## 概要

V2.0 为 DevFlow Studio 增加有界的自有 Agent 循环：观察受治理上下文，从明确授权的原生工具、本地 MCP 和编码执行器能力中选择动作，评估结果、保存检查点、恢复，并以确定性原因停止。它仍受现有工作流、策略、预算、证据和人工 Gate 权限模型约束。

现有 OpenCode 适配器同时演进为统一的受治理编码执行器契约，并在同一契约后增加一个刻意限定范围的 DevFlow 自有编码 Agent；不替换 OpenCode，也不声称功能对等。

<a id="problem"></a>

## 问题

已发布的 1.x 产品有两条用途不同的模型路径：

- 知识审查是有界单次调用，留下持久结果和轨迹。
- OpenCode 是受管适配器与权限转发之后的外部编码引擎。

两者都不是 DevFlow 自有的迭代运行时。此前系统无法依据观察选择已批准工具、持久化可移植检查点、恢复精确轨迹、执行可信本地 MCP 工具、以同一结果契约比较原生与委托编码，或用版本化场景数据集评价这些行为。

<a id="users-and-jobs"></a>

## 用户与任务

<a id="developer"></a>

### 开发者

- 只从合格工作流节点启动 Agent，理解其范围和限额。
- 看懂请求的能力，批准/拒绝敏感动作，安全取消，中断后从精确检查点恢复。
- 用一致的事件、差异/测试证据及停止原因比较原生与 OpenCode，不把本地源码或凭据暴露给团队状态。

<a id="lead-or-reviewer"></a>

### 负责人或审查者

- 批准下一 Gate 前，检查脱敏轨迹、策略/预算决定、工具/权限时间线、评估和证据。
- 区分 Agent 任务成功、工作流证据被接受与交付授权。

<a id="local-operator"></a>

### 本地操作员

- 安装/启用可信本地 MCP 服务，且不允许团队元数据或模型提示词选择可执行文件、参数、工作目录或秘密环境变量。
- 诊断生命周期、模式、超时、取消和审计失败，不泄露原始秘密。

<a id="product-principles"></a>

## 产品原则

1. 工作流和人工 Gate 权限位于 Agent 循环之外。
2. 模型只能选择已经存在的能力；文字不是授权。
3. 每次继续执行都须有界、版本化、可取消、可保存检查点且可观察。
4. 轨迹指可观察事件与证据，不是隐藏推理。
5. 本地源码、原始输出、凭据与完整运行时状态留在桌面端。
6. 原生与委托编码共用一个受治理契约。
7. 默认验证确定且不产生费用。

<a id="functional-requirements"></a>

## 功能要求

<a id="fr1--runtime-start-and-scope"></a>

### FR1：启动与范围

- 只接受合格的当前 Run/节点，要求精确版本、本地项目绑定、权威策略/预算上下文及显式能力集合。
- 启动请求记录最大步数、截止时间、工具调用数、结果大小和费用/Token 预算；渲染器不能提高系统/策略上限。
- 同一检查点版本只能有一个活动继续执行者。

<a id="fr2--bounded-agent-loop"></a>

### FR2：有界 Agent 循环

- 循环为观察 → 决定 → 执行 → 验证 → 评估 → 保存检查点。
- 每轮最多产生一个外部动作。
- 稳定终止原因为 `success`、`failure`、`cancelled`、`timeout`、`step_limit`、`budget_exhausted`、`policy_denied`。
- 达到任一限额后，必须在下次模型、工具、MCP 或执行器动作前停止。
- Agent 成功绝不直接推进工作流节点。

<a id="fr3--trajectory-and-checkpoint"></a>

### FR3：轨迹与检查点

- 持久化有序、白名单事件，序号与检查点版本单调增加。
- 只保存固定、有界决定摘要与摘要值，不保存隐藏推理或服务商私有草稿。
- 原子提交已接受结果引用、计数器、轨迹事件与检查点。
- 恢复时重新验证工作流/节点版本、策略、能力集合摘要、本地项目、截止时间、剩余预算和执行器/安装可用性。
- 过期、终态、超时、不匹配或被并发消费的检查点均拒绝继续。

<a id="fr4--native-tools"></a>

### FR4：原生工具

- Electron 主进程拥有版本化原生工具注册表。
- 首批工具限于仓库读取、有界工作区文件编辑、已保存测试命令执行，以及场景数据集所需的确定性评估辅助工具。
- 每项工具具有严格输入/输出模式、权限/副作用分类、截止时间、取消、大小上限、幂等策略和审计脱敏规则。
- 执行前立即要求不透明的 `ToolCapabilityGrant` 授权。

<a id="fr5--trusted-local-mcp"></a>

### FR5：可信本地 MCP

- 开发者显式创建可信本地 MCP 安装，绑定已核验可执行文件、固定参数、本地 `stdio`、环境变量名白名单、截止时间、身份和版本。
- 团队 `McpServerDefinition` 仍只是展示/目录元数据，不能创建或执行进程。
- 发现阶段验证协议、服务身份和工具模式，不授予调用权限。
- 只有精确 `ToolCapabilityGrant` 才允许运行时调用 MCP 工具。
- 超时、取消、崩溃、畸形模式/消息、重复工具身份、意外输出和关闭，都必须有明确类型并在不确定时拒绝继续。

<a id="fr6--coding-executor-contract"></a>

### FR6：编码执行器契约

- 选择前，执行器公布稳定身份/版本、可用性与能力。
- OpenCode 包装在新契约之后，不替换已验证 HTTP 传输。
- 原生编码 Agent 只在受管工作树使用已接受原生工具，执行已保存测试命令，进行有界修复循环并确定性停止。
- 两者提供可比较事件族及相同终态结果：停止原因、检查点、相对变更路径、脱敏差异引用、测试证据引用、用量/费用及清理状态。
- 两者都不能发布、合并、批准 Gate、选择更宽工作区或自行签发能力。

<a id="fr7--permission-cancellation-and-recovery"></a>

### FR7：权限、取消与恢复

- 权限请求标识工具/执行器、有界操作摘要、权限类别、范围和到期时间；到期前无回复视为拒绝。
- 一次批准只覆盖一个精确请求，不能授权后续不同调用。
- 取消幂等，先持久化再传播，并隔离迟到提交。
- 中断的确定性场景通过检查点恢复时，不重复最后一个已接受的非幂等动作。

<a id="fr8--evidence-ux-and-team-projection"></a>

### FR8：证据、界面与团队投影

- 桌面显示生命周期、当前步骤、活动能力、权限、已消费/剩余限额、检查点、评估、停止原因、执行器身份、证据和清理。
- 本地 SQLite 保存完整白名单轨迹及私有本地结果引用。
- API/Postgres 只保存严格脱敏的运行时摘要和审计元数据。
- 团队数据不含原始提示词、源码、补丁、标准输出/错误、凭据、环境变量、可执行文件路径、工作目录或本地绝对路径。

<a id="evaluation-contract"></a>

## 评估契约

V2.0 提供版本化场景数据集。每个场景固定初始仓库/上下文、允许能力、适用时的确定性模型决定、预期工具/执行器事件、限额、终态、证据和清理结果。

基线评价质量、费用、延迟、人工介入、恢复和隔离，至少覆盖：

1. 无副作用的原生工具成功任务；
2. 一次获批编辑且已保存测试通过的原生编码修复；
3. 经 OpenCode 契约样例完成的等价受治理编码；
4. 可信测试 MCP 的发现及工具调用；
5. 注入中断后的检查点恢复；
6. 工具及执行器工作中的取消；
7. 精确步数、耗时、调用数和预算耗尽；
8. 拒绝畸形工具/MCP 模式及超大结果；
9. 拒绝过期工作流、检查点、能力、策略和本地项目；
10. 跨组织、项目、用户、会话和本地项目的否定路径。

默认验证确定且无费用。真实 OpenCode/服务商签收必须显式执行、单场景、预算有界、保护秘密，并与默认 CI 分开记录。

<a id="v20-completion-gate"></a>

## V2.0 完成门禁

只有以下条件全部满足才完成：

- 干净候选上的版本化数据集通过共享层、桌面、团队/Postgres、打包桌面和跨平台门禁；
- 自有 Agent 完成已接受原生工具和本地 MCP 场景，精确恢复检查点并确定性停止；
- 同一运行时通过 OpenCode 与原生执行器完成受治理编码，事件、取消、证据、终态和清理契约对等；
- 所有限额、过期版本、权限、不确定结果、重启及租户/范围否定路径均拒绝越界；
- 轨迹与团队投影通过秘密、路径、源码和输出脱敏扫描；
- 基准证据记录质量、费用、延迟、介入、恢复和隔离结果。

完成证据：候选 `dfc74831552a0e8910529420c6383b6474e8a12c` 通过全部 15 个冻结的无费用场景、原生/OpenCode 对等、零泄露扫描、精确 SHA 的首次 Verify 五个作业及唯一桌面产物校验。不可变记录为 `docs/releases/v2.0.0/agent-runtime-evaluation.json` 和 `docs/releases/v2.0.0/required-gates.json`。

<a id="non-goals"></a>

## 非目标

- 公共 SaaS、托管共享基础设施多租户、计费、企业 SSO 或托管模型凭据。
- V2.1 混合/向量检索、重排或 Agent 记忆。
- V2.2 调度者/专长 Agent 协调或任务图。
- 远程 MCP、任意团队编写的进程命令、无限制命令行或通用插件市场。
- 原生编码 Agent 与 OpenCode 的功能对等。
- 自主批准 Gate、发布分支、创建/合并 PR、部署或修改策略。
- 持久化或展示隐藏推理及服务商私有内部轨迹。
