# V2.1 Evaluated Retrieval And Memory PRD

Status: Approved for implementation

Date: 2026-08-13

Roadmap position: Active second 2.x milestone after completed V2.0

## Summary

V2.1 makes DevFlow retrieval measurable and gives the bounded Agent Runtime scoped, reviewable
Memory. It adds hybrid retrieval, deterministic reranking, exact citations, a versioned evaluation
corpus, and a governed Memory lifecycle while preserving local repository authority, ADR 0007, and
the deterministic Workflow/Gate boundary.

## Problem

The current lexical retriever is deterministic and explainable but cannot recover semantic matches
that share little vocabulary. Agent Checkpoints support exact continuation but do not provide
governed recall across later sessions. Adding embeddings or storing model output without contracts
would risk unmeasured quality, fabricated citations, stale source references, tenant leakage, and
undeletable shadow state.

## Users And Jobs

### Developer

- Retrieve the most relevant current repository Knowledge with exact, inspectable citations.
- See when Memory influenced an Agent and its scope, version, provenance, and expiry.
- Promote, revise, or delete eligible Memory without exposing source or credentials to Team state.

### Lead Or Reviewer

- Compare hybrid retrieval to the lexical baseline using stable metrics and a frozen corpus.
- Verify that cited chunks support bounded claims and that retrieval still is not Governance
  Evidence.
- Audit Memory promotion/deletion and redacted Team projections without reading private local data.

### Local Operator

- Rebuild a local index deterministically, diagnose stale/corrupt entries, and verify deletion/purge.
- Enable an explicit paid provider scenario without making it part of default CI or leaking secrets.

## Product Principles

1. Measure retrieval improvement; do not equate vector storage with product completion.
2. Citation identity and scope are authoritative; similarity scores are not.
3. Memory is curated, versioned, scoped, expiring, and deletable; it is not chat history.
4. Retrieval and Memory remain Context, not Workflow State or Governance Evidence.
5. Full repository content and local Memory remain inside Electron main by default.
6. Scope filtering and deletion happen before ranking and model use.
7. Default verification is deterministic, versioned, and no-cost.

## Functional Requirements

### FR1 — Versioned Retrieval Request And Result

- Bind each request to exact organization/project/user/session, Run/Node, Local Project, Knowledge
  snapshot hash, categories/tags, TopK, score bounds, and retrieval contract version.
- Return bounded hits with exact document/chunk/content/snapshot identity, strategy chain, rank,
  finite scores, and reason metadata.
- Reject unknown fields, noncanonical IDs/timestamps, invalid dimensions, stale snapshots, duplicate
  identities, and cross-scope results.

### FR2 — Hybrid Retrieval And Reranking

- Keep lexical retrieval as the stable baseline and fallback.
- Admit vector candidates only from the prefiltered exact scope, combine candidates deterministically,
  and rerank only the admitted set.
- Version embedding and ranking identities; deterministic tie-breaking cannot depend on map/DB order.
- External embedding/reranking requires explicit bounded provider authority and budget before text
  leaves the local boundary.
- No provider credential is resolved before scope, budget, and text-transmission authority pass.

### FR3 — Exact Citation

- Bind a citation to document, chunk, source-relative path, heading, content hash, snapshot hash,
  strategy chain, and retrieval rank.
- Reject stale, deleted, inaccessible, fabricated, mismatched, or unsupported citations.
- Record citation precision and faithfulness separately; citation presence alone is not correctness.
- Never promote a citation or hit into Governance Evidence automatically.

### FR4 — Memory Candidate And Promotion

- Runtime observations may create bounded Memory Candidates with exact scope and provenance digest.
- Candidates are inert until main-owned policy/actor authority promotes them.
- Promotion produces immutable revision 1 with visibility, sensitivity, retention, expiry, and audit.
- Hidden reasoning, raw prompts, credentials, source, patches, stdout/stderr, and absolute paths are
  never Memory fields or Team projection fields.

### FR5 — Memory Revision, Conflict, Expiry, And Deletion

- Updates require exact optimistic concurrency and create immutable superseding revisions.
- Conflicts remain explicit; no model or last-write-wins timestamp silently selects authority.
- Expired or purge-pending Memory is excluded before ranking.
- Deletion is monotonic, tombstoned, restart-safe, purges derived index entries, and cannot be undone
  by an older replay or Team sync.

### FR6 — Isolation And Placement

- Enforce organization/project/user/session/Local Project/visibility intersection before retrieval.
- Cross-tenant requests reveal neither item contents nor existence/count/timing distinctions.
- Desktop schema 22 is the first planned local persistence slice; Team schema 17 is reserved only
  for a later metadata-only redacted projection after local semantics pass.
- API/Postgres cannot resume local retrieval, promote full-fidelity Memory, or request repository
  content.

### FR7 — Runtime And UX Integration

- Agent Context labels Knowledge and Memory independently and records exact accepted citation/Memory
  revision identities in the observable trajectory.
- A stale/deleted citation or Memory invalidates the next continuation before another Tool,
  provider, MCP, or Coding Executor action.
- Desktop exposes source/provenance, strategy, score/rank, scope, version, conflict, expiry, and
  deletion state. Team/Web receives only allowlisted redacted summaries.

## Evaluation Contract

The frozen corpus is `scripts/fixtures/v2.1-retrieval-memory-evaluation.json`. It contains only
reviewable synthetic content and exact expected/forbidden identities. The evaluator compares lexical
baseline and hybrid candidate on Recall@K, nDCG@K, mean reciprocal rank, citation precision,
citation faithfulness, latency, Memory task quality, and isolation violations.

The V2.1 completion gate requires:

- hybrid retrieval improves the frozen aggregate quality threshold over lexical baseline;
- citation precision and faithfulness meet the frozen floor with zero fabricated/stale citations;
- Memory improves the selected task outcomes over no-Memory without additional human intervention;
- cross-tenant, deleted, expired, stale-revision, and no-resurrection scenarios record zero leaks;
- default evaluator calls no paid provider and records candidate/corpus/contract digests; and
- local, retained migration, real Postgres, Docker, packaged Desktop, Windows, macOS, redaction, and
  direct-child completion evidence gates pass.

## Non-Goals

- V2.2 Multi-Agent supervisor/specialist coordination or hosted execution tenancy.
- Public SaaS, managed vector infrastructure, billing, enterprise SSO, or managed provider secrets.
- Replacing reviewable Git Markdown as the Knowledge source of truth.
- Treating Memory, retrieval score, citation, or model confidence as Workflow/Gate authority.
- Arbitrary provider text upload, implicit repository synchronization, or hidden chat-history Memory.
- Selecting a permanent vector database before the behavioral and evaluation slices prove need.

## Dependencies

- ADR 0007: Knowledge Retrieval is not Governance Evidence.
- ADR 0014: bounded Agent Runtime and observable trajectory.
- ADR 0017: evaluated hybrid retrieval and citation authority.
- ADR 0018: scoped Agent Memory lifecycle.
- Completed V2.0 Runtime, Native Tool, Local MCP, Coding Executor, Desktop/Team authority, redaction,
  and evaluation boundaries.
