# V2.2 多 Agent 与执行租户需求

状态：已完成

日期：2026-08-13

路线图位置：V2.1 完成后，当时计划的最后一个 2.x 里程碑；现行优先级见路线图。

<a id="summary"></a>

## 概要

V2.2 在既有运行时、工具、编码执行器、上下文、记忆、工作流与 Gate 边界内，协调一个有界监督 Agent和少量固定专职 Agent。增加依赖感知拆解、基于证据的交接/汇合、共享资源限额、取消/恢复及精确执行租户。完成须证明相对冻结 V2.0 单 Agent 基线的可测收益，不能只计算模型调用次数。

<a id="problem"></a>

## 问题

部分受治理工程任务适合并行开展契约、测试、诊断或实现，再汇合结果。原运行时一次只执行一个 Agent。提示它“使用子 Agent”，或统计外部执行器内部动作，都无法建立 DevFlow 自有的范围、费用、终止、证据、失败归因与租户隔离。

无界委托还可能扩大权限、竞争共享工作区、跨用户/项目泄露上下文、重启后重复不确定副作用，或耗尽预算却不确定停止。V2.2 必须改善选定结果，并把这些失败模式变成明确可测条件。

<a id="users-and-jobs"></a>

## 用户与任务

<a id="developer"></a>

### 开发者

- 为合格运行中任务启动有界协调计划，看到精确任务图与限额。
- 理解各专职 Agent 的任务归属、上下文、能力及返回结果/失败。
- 一次取消整个会话，并确认取消覆盖全部子任务及可变资源。

<a id="lead-or-reviewer"></a>

### 负责人或审查者

- 在同一冻结场景比较多 Agent 与 V2.0 单 Agent 的质量、费用、延迟、介入和恢复。
- 检查脱敏任务、交接、失败归因及限额消耗，不读取本地源码或隐藏推理。
- 核实没有 Agent 改变工作流、Gate、发布、凭据或租户权限。

<a id="local-operator"></a>

### 本地操作员

- 诊断依赖阻塞、专职任务失败、过期租约或不确定效果，不编辑 SQLite 或重放副作用。
- 桌面重启后恢复精确协调版本，已接受交接、工具调用、可变写入及子运行时均零重复。

<a id="product-principles"></a>

## 产品原则

1. 协调只收窄既有权限，不创造权限。
2. 一个监督 Agent与少量固定专职角色是产品能力，不支持开放群体。
3. 任务图、预算、能力和租户身份属于数据契约，不是提示词建议。
4. 可并行只读，可变资源仍须单写者。
5. 交接携带证据和摘要，不携带隐藏推理或仓库原文。
6. V2.0 单 Agent 路径保持可执行，作为比较基线。
7. 默认评估确定且无费用。

<a id="functional-requirements"></a>

## 功能要求

<a id="fr1--bounded-coordination-session"></a>

### FR1：有界协调会话

- 会话绑定精确组织/项目/用户/会话、本地项目、Run/节点版本、监督 Agent运行时、上下文/能力摘要、截止时间和共享限额。
- 允许一个监督 Agent、最多四个专职 Agent，禁止递归委托。
- 硬限制图、边、并发、重试、交接、工具调用、Token、费用、结果大小和耗时，权威策略的更低上限优先。
- 拒绝未知字段、非规范 ID/时间、旧版本、更宽范围及无效限额。

<a id="fr2--dependency-aware-agent-task-graph"></a>

### FR2：感知依赖的任务图

- 专职任务产生副作用前，验证版本化有向无环图。
- 要求唯一任务/边 ID、依赖目标存在、有界扇出、已接受角色、显式能力/上下文/资源需求及就绪任务确定性排序。
- 任务状态单调推进，所有依赖成功后下游才就绪。
- 拒绝循环、模型改图、重写已完成节点、重复归属及隐藏/断开的执行。

<a id="fr3--supervisor-and-specialist-authority"></a>

### FR3：监督 Agent与专职角色权限

- 当前工作流/策略/配对及监督 Agent所有权通过后，仅主进程可签发不透明专职任务权限。
- 子权限是父权限与精确任务需求的交集；能力、上下文、资源、截止时间及预算只能收窄。
- 子 Agent 不能再创建 Agent、扩大角色、转移工具授权或使用其他任务运行时/检查点/资源句柄。
- 监督 Agent及专职角色不能推进工作流、接纳证据、批准 Gate、发布、合并、签发凭据或绕过交付契约。

<a id="fr4--handoff-join-and-failure-attribution"></a>

### FR4：交接、汇合与失败归因

- 交接绑定精确源/目标任务及运行时版本、租户、结果/证据/上下文摘要、序号和有界白名单摘要。
- 同一交接身份幂等接受；拒绝冲突重放、旧依赖、错目标、外范围、未接受结果或超大元数据。
- 只汇合已接受依赖结果；保留失败、取消、超时、预算耗尽、策略拒绝、工具/执行器错误或无效结果的精确来源。
- 恢复显式有界，不能静默替换专职角色或重复非幂等效果。
- 首个恢复路径仅在只读 `repository_read` 已持久失败后替换运行时一次，不换任务或 Agent。扣除已观察用量，记录一次 `task_retried` 检查点；可变或不确定效果不适用。

<a id="fr5--shared-budgets-and-resource-arbitration"></a>

### FR5：共享预算与资源仲裁

- 所有子分配及实测用量从一个权威协调预算扣除，子总量不能超过父预算。
- 可变资源由主进程单写者租约绑定精确任务、能力、资源摘要、版本、截止时间和租户。
- 只有各自能力/资源范围均允许才并发只读；绝不并发编辑同一受管工作区。
- 到期、取消、过期版本、不匹配或释放租约不能提交结果。

<a id="fr6--cancellation-checkpoint-and-restart"></a>

### FR6：取消、检查点与重启

- 父取消传播到全部就绪/运行中子任务、工具/MCP/执行器、交接和写租约，迟到事件不能回退状态。
- 原子保存图/任务、共享计数、已接受交接、租约、子运行时引用及安全轨迹元数据。
- 恢复要求精确乐观并发，并重核权限、上下文、能力、租户、截止时间、策略和资源。
- 冷启动不重复已接受子启动、交接、工具效果、可变写入或终态事件；不确定效果保持阻断，交由既有对账契约处理。

<a id="fr7--execution-tenancy-and-placement"></a>

### FR7：执行租户与存放位置

- 每个对象绑定精确组织/项目/用户/会话/本地项目、Run/节点、协调、任务和 Agent 身份。
- 查数据或调用模型/工具前拒绝跨范围输入，不泄露存在性、数量或时间差异。
- 桌面模式 28 是首批持久会话；后续团队模式 19 仅保存严格脱敏的生命周期、任务数、失败、质量、费用、延迟和介入元数据。
- API/Postgres/Web 不能创建、恢复、取消、重新分配或修改本地协调、图、能力、交接及资源。

<a id="fr8--ux-and-evaluation"></a>

### FR8：界面与评估

- 桌面显示图状态、调度/专职角色、依赖就绪、限额、资源归属、交接、失败归因、取消和恢复，不展示隐藏推理。
- Web 只读，不接收源码、提示词、补丁、标准输出/错误、凭据、本地路径、范围会话、不透明能力、上下文正文或记忆陈述。
- 同一冻结输入分别运行 V2.0 单 Agent 基线和 V2.2 候选。
- 完成须证明多 Agent 相对冻结基线在质量、费用、延迟及人工介入约束下改善选定任务，同时权限、隔离、终止和重放违规为零。

<a id="evaluation-contract"></a>

## 评估契约

版本化样例 `scripts/fixtures/v2.2-multi-agent-evaluation.json` 固定任务图、租户限额、角色、场景、基线观察、候选预期及指标下限。默认执行器移除模型凭据，使用确定性监督 Agent/专职决定、工具、时钟和故障注入。

完成门禁要求：

- 相对精确单 Agent 基线，选定任务聚合改进至少 `0.25`；
- 不增加人工介入，费用/延迟倍数受冻结上限约束；
- 依赖汇合、循环拒绝、失败归因、共享预算耗尽及取消传播正确；
- 权限、隔离、终止、重放、脱敏、源码、路径、原始输出及付费调用违规为零；
- 完整单 Agent 基线仍可执行且未变化；
- 本地、保留迁移、真实 Postgres、Docker、打包、Windows、macOS、重启及干净直接子提交证据门禁通过。

<a id="non-goals"></a>

## 非目标

- 开放群体、递归委托、动态市场成员或任意角色创建。
- 公共 SaaS、托管共享执行、Kubernetes Worker、远程桌面或企业租户开通。
- 将 OpenCode 内部行为当作 DevFlow 自有协调。
- 同一工作区并发编辑、隐式解决合并冲突或 Agent 自主管理 Git 历史。
- 新的工作流、Gate、证据接纳、交付、凭据或策略权限。
- 新远程 MCP 传输或任意团队提供的可执行程序。
- 通用聊天室、社交 Agent 网络或隐藏长期后台执行群体。
- 不自动延伸出 V2.3；完成 V2.2 即关闭当时已接受的有限 2.x 序列，后续版本需另行批准范围。
