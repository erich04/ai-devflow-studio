# AI DevFlow Studio 项目简介

## 一句话介绍

AI DevFlow Studio 是面向小型研发团队的自托管 AI 交付工作台。它以工作流为主线，串联需求澄清、方案设计、编码、测试、PR 交付和业务验收，让 Agent 的工作可查看、可追溯、可审批。

## 最值得关注的能力

项目在一条交付流程中组织职责明确的 Agent，让它们围绕同一个工作流实例（Run）协作：

- 阶段 Agent 负责需求澄清和方案设计。
- 门禁审查 Agent 执行基于知识的门禁审查（Knowledge-Grounded Gate Review）：以团队知识、规则和已有证据为依据，审查当前门禁（Gate）、审批条件和阶段产物，识别风险与缺口。
- 编码 Agent 通过统一的编码执行器边界接入 OpenCode 或 DevFlow Native，完成代码修改、测试和结果回传。

这些 Agent 按工作流阶段各自完成任务，把结果放回同一条证据链。团队可以看到每一步做了什么、依据是什么、是否具备进入下一阶段的条件。能力受范围和权限约束；Agent 协作本身不赋予审批或发布权限。

## 技术特点

<a id="1-workflow-是主干"></a>

### 1. 工作流是主干

项目用统一的 Run、节点（Node）和 Gate 表达交付过程。需求、设计、实现、测试和验收构成有顺序、有状态、有检查点的流程。

<a id="2-agent-产出直接进入交付链"></a>

### 2. Agent 产出进入交付链

正式归档的澄清结果、设计文档、评审意见、代码差异和测试结果构成交付证据。会话草稿需经正式产物流程确认，不能直接替代阶段完成。Gate 根据证据和团队规则评估是否可继续，关键节点仍由人确认。

<a id="3-opencode-只负责执行devflow-负责管理"></a>

### 3. 编码执行器可替换，DevFlow 统一治理

通过编码运行时接口（CRI）接入 OpenCode 时，外部运行时负责代码执行，DevFlow 负责上下文组装、权限确认、工作树隔离、差异采集、测试、运行记录和结果脱敏。当前源码也提供能力范围较窄的 DevFlow Native 内置编码执行器，两者遵循共同的执行和证据契约；都不拥有 Gate 审批或 GitHub 发布权限。

### 4. 本地优先，团队可见

代码、命令、原始日志和本地模型密钥保留在 Electron 桌面端。本地状态存入 SQLite；经过范围控制和脱敏的摘要同步到 API、Postgres 和 Web 团队视图。服务端自身持有的认证与 GitHub App 凭据遵循独立安全边界。

<a id="5-运行时可以替换也便于验证"></a>

### 5. 运行时可替换，也便于验证

模型服务商（Provider）和编码运行时通过明确接口接入。项目保留用于可重复验证的模拟运行时，也支持显式启用真实执行器，便于区分开发测试、演示和真实模型验证的结果。

<a id="为什么值得采用"></a>

## 适合什么团队

如果团队已经使用 AI 或编码 Agent，但缺少统一的需求、评审、测试和审批流程，DevFlow Studio 可以补足交付管理。它保留既有模型和编码工具，让团队能够理解和管理 Agent 的产出。

## 30 秒介绍

> AI DevFlow Studio 用一条工作流管理 AI 研发交付，组织需求、门禁审查和编码 Agent 协作。它接入 OpenCode 与 DevFlow Native，把权限、代码差异、测试和运行记录汇入可核对的证据链，由 Gate 和人工审批控制推进。源码执行留在本地，团队同步受限的脱敏结果。
