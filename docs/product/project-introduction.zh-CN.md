# AI DevFlow Studio 项目简介

## 一句话介绍

AI DevFlow Studio 是面向小型研发团队的本地优先、自托管 AI 交付工作台。它以工作流为主线，串联需求澄清、方案设计、编码、测试、PR 交付和业务验收，让 Agent 的工作可查看、可追溯、可审批。

## 最值得关注的能力

项目在一条交付流程中组织职责明确的 Agent，让它们围绕同一个工作流实例（Run）协作：

- 阶段 Agent 负责需求澄清和方案设计，并通过统一门禁决定页的**修订清单**生成可追溯的新版本。
- 门禁审查 Agent 执行基于知识的门禁审查（Knowledge-Grounded Gate Review）：以常驻仓库知识、规则和已有证据为依据，审查当前门禁（Gate）、审批条件和阶段产物，识别风险与缺口；支持不依赖 OpenCode 的内置仓库只读审查。
- 编码 Agent 通过统一的编码执行器边界接入 OpenCode 或 DevFlow Native（v2），在受管理 Git 工作树中完成代码修改、精确行级差异审阅、测试和结果回传。其中 OpenCode 编码支持交互式问答、单层串行有界子任务（`devflow-worker`）和白名单只读公开文档读取；Native v2 支持按修订清单继续修订与手动自检。
- 右侧「答疑」独立会话与当前查看的任务、步骤和版本联动，支持只读调查仓库、知识、项目记忆与待批准改动，并将建议直接加入修订清单或保存为待确认提案。

这些 Agent 按工作流阶段各自完成任务，把结果放回同一条证据链。团队可以看到每一步做了什么、依据是什么、是否具备进入下一阶段的条件。能力受范围和权限约束；Agent 协作本身不赋予审批或发布权限。

高级协作运行时提供 Supervisor/Specialist 模式：Supervisor 按预定义任务依赖图分派任务并汇合结果，Specialist 在限定能力和共享预算内执行。委派深度、并发和工作区写入都有约束；这一能力不表示所有阶段都会自动启动多 Agent 协作。

## 技术特点

<a id="1-workflow-是主干"></a>

### 1. 工作流是主干

项目用统一的 Run、节点（Node）和 Gate 表达交付过程。需求、设计、实现、测试、PR 交付和业务验收构成有顺序、有状态、有检查点的流程；前四个阶段共享统一的决定页（「你的决定」栏、原文/差异、卡片与本机修订清单）。

<a id="2-agent-产出直接进入交付链"></a>

### 2. 经校验的产出进入交付链

澄清结果、设计文档、评审意见、不可变代码变更修订和绑定精确改动指纹的测试结果经过相应校验及正式归档后构成交付证据。测试通过后需人工显式确认证据才进入 PR 交付；会话草稿需经正式产物流程确认，不能直接替代阶段完成。Gate 根据证据和团队规则评估是否可继续，关键节点仍由人确认；Agent 完成任务不等于自动通过验收。

<a id="3-opencode-只负责执行devflow-负责管理"></a>

### 3. 编码执行器可替换，DevFlow 统一治理

通过编码运行时接口（CRI）接入 OpenCode 时，外部运行时负责代码执行，DevFlow 负责上下文组装、命令输入绑定授权、问答与有界子任务边界、工作树隔离、差异采集、测试、运行记录和结果脱敏。当前 `main` 源码也提供能力范围较窄的 DevFlow Native v2 内置编码执行器（支持按修订清单迭代与手动自检；多轮 Native v3 仍在独立分支开发评测中），两者遵循共同的执行和证据契约；都不拥有 Gate 审批或 GitHub 发布权限。

<a id="4-本地优先团队可见"></a>

### 4. 本地优先，团队可见

代码、命令、原始日志、私有答疑对话和本地模型密钥保留在 Electron 桌面端。本地状态存入 SQLite；经过范围控制和脱敏的摘要同步到 API、Postgres 和 Web 团队视图。仓库根目录 `AGENTS.md` 与 `docs/knowledge/` 按阶段常驻提供规范上下文（ADR 0025）；已配对项目可选开启基于本机 Hindsight 的**项目记忆**（ADR 0030），自动采集讨论、编码记录、已批准产物与 Git 提交信息，抽取调用经桌面中继计入团队预算，提供多语言召回与五张知识页，但记忆始终只作低信任背景。服务端自身持有的认证与 GitHub App 凭据遵循独立安全边界。

<a id="5-运行时可以替换也便于验证"></a>

### 5. 运行时可替换，也便于验证

模型服务商（Provider）和编码执行器通过明确接口接入。项目级配置可以选择 OpenCode 或绑定模型 Provider 的原生编码执行器，并检查能力与运行条件；版本化运行费用目录统一治理调用前预算上限与结算口径。自动化验证可以显式启用确定性测试执行器；真实模型调用需要明确配置，并可能产生费用。开发测试、演示和真实模型验证的结果分别记录。

<a id="为什么值得采用"></a>

## 适合什么团队

如果团队已经使用 AI 或编码 Agent，但缺少统一的需求、评审、测试和审批流程，DevFlow Studio 可以补足交付管理。它保留既有模型和编码工具，让团队能够理解和管理 Agent 的产出。

## 30 秒介绍

> AI DevFlow Studio 用一条工作流管理 AI 研发交付，组织需求、门禁审查和编码 Agent 协作。它接入 OpenCode 与 DevFlow Native，结合常驻仓库知识与受预算治理的 Hindsight 项目记忆，把权限、代码差异、测试和运行记录汇入可核对的证据链，由统一决定页、Gate 和人工审批控制推进。源码执行留在本地，团队同步受限的脱敏结果。

## 简历表述参考

以下条目按项目能力组织，请按实际负责的部分选用；量化结果需要对应的验证记录。

- **工作流与交付治理**：围绕 Run、Node、Gate 建模研发流程，以统一决定页、版本化修订清单与精确指纹证据串联阶段产物、测试验证与人工审批。
- **编码执行抽象**：设计统一 Coding Executor 接口，接入 OpenCode（含问答、有界子任务与受控公开文档读取）与原生执行器，统一管理授权、代码变更和测试结果。
- **知识上下文与项目记忆**：建立按阶段常驻的仓库知识上下文（ADR 0025）与基于 Hindsight 的自动项目记忆（ADR 0030），经本地预算中继实现多语言召回、多意图拆分与知识页治理。
- **多 Agent 协调**：实现 Supervisor/Specialist 任务协作，通过依赖图、共享预算和权限约束控制执行范围。
