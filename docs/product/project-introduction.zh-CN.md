# AI DevFlow Studio 项目简介

## 一句话介绍

AI DevFlow Studio 是一个面向小型研发团队的本地优先、自托管 AI 交付工作台。它以可追溯、可审批的 workflow 串联需求澄清、方案设计、编码、测试、PR 交付和验收，通过统一编码执行接口和受控多 Agent 协作组织 AI 参与研发。

## 最值得关注的能力

项目围绕同一个 Run，按照交付阶段组织职责明确的 Agent：

- 阶段 Agent 负责需求澄清和方案设计。
- 门禁审查 Agent 执行基于知识的门禁审查（Knowledge-Grounded Gate Review）：以团队知识、规则和已有证据为依据，审查当前 Gate、门禁条件及阶段产物，找出风险与缺口。
- Coding Agent 通过统一的 Coding Executor 接口使用 OpenCode 或原生编码执行器，完成授权范围内的代码修改、测试和结果回传。

需要协作的任务可使用 Supervisor/Specialist 模式：Supervisor 根据固定的任务依赖图组织分派和结果汇合，Specialist 在限定权限与共享预算内执行任务。委派深度、并发数量和工作区写入都有约束；工作流推进和 Gate 审批由独立规则及人工确认控制。

## 技术特点

### 1. Workflow 是主干

项目用统一的 Run、Node 和 Gate 表达交付过程。需求、设计、实现、测试和验收按明确的状态和节点顺序推进，关键步骤具有证据要求和人工检查点。

### 2. 经校验的产出进入证据链

Agent 生成的澄清结果、设计文档、评审意见、代码 diff 和测试结果经过相应校验后纳入交付证据链，用于门禁判断和人工审批。Agent 完成任务不等于自动通过验收；Gate 根据证据和团队规则约束后续流程，并保留人工确认。

### 3. 统一的编码执行层

项目通过统一的 Coding Executor 接口，支持 OpenCode 外部运行时与 DevFlow 原生编码执行器。代码变更在明确授权和受管 worktree 内执行，代码 diff、测试结果与执行记录纳入交付流程。执行器的能力范围、权限、取消和结果格式由统一契约约束，后续交付由工作流门禁控制。

### 4. 本地优先，团队可见

代码、命令、原始日志和密钥保留在 Electron 桌面端。本地状态存入 SQLite；经过批准和脱敏的摘要再同步到 API、Postgres 和 Web 团队视图。

### 5. 运行时可以替换，也便于验证

Agent Provider 和 Coding Executor 都通过明确的接口接入。项目级配置可选择 OpenCode 或绑定模型 Provider 的原生编码执行器，并检查所需能力和运行条件。自动化验证可显式启用确定性测试执行器，真实运行则需要明确配置，方便分别验证执行契约和模型接入。

## 为什么值得采用

如果团队已经在使用 AI 或 Coding Agent，但还缺少统一的需求、评审、测试和审批流程，DevFlow Studio 可以补上中间这一层。它保留现有模型和编码工具，同时让 Agent 从个人工具变成团队可以理解和管理的交付能力。

## 30 秒介绍

> AI DevFlow Studio 是面向小型研发团队的本地优先 AI 交付工作台，将需求、设计、编码、测试和验收组织成可追溯、可审批的工作流。项目通过统一执行接口支持 OpenCode 和原生编码执行器，并通过 Supervisor/Specialist 协作完成任务分工。执行过程受到权限和预算约束，产出经过校验后进入证据链，由门禁和人工审批控制交付。
