## 已核实的实现证据

- 全仓测试：307 个文件通过，1 个跳过；4,123 项测试通过，15 项跳过。记账/界面细化后，先后通过 238 项应用/IPC 测试、115 项 API/治理/仓储测试，以及 PostgreSQL 冒烟测试。完整类型检查（包括 OpenCode/记忆/组织冒烟配置）、API/桌面构建及桌面跨平台检查通过。
- PostgreSQL 冒烟测试使用独立可丢弃数据库，验证并发费用预留串行化、不可变/幂等结算、失败用量、实际报告总量、未知金额阻断，以及最新禁用预算策略。客户端时间不能把预留移到上个账期。重复导入历史记录必须匹配原项目、用户和结算。
- 关键正文测试覆盖实际序列化请求的覆盖情况、Unicode/转义、截断、旧版本、跨目标输入、有界恢复和独立语义标准验证。无法观察的 OpenCode 输入不能宣称已验证完整；已保存提案按真实目标和文档版本重新检查。
- 审查测试覆盖默认省略输出限制、保留思考设置、分类停止/失败条件、解析前保存用量、迟到取消，以及保留之前成功的审查产物。API 在记账期间取消时保留用量，但不保存审查。
- 受控 Direct/Native/OpenCode 请求按每次实际服务商调用预留并结算，云端策略和支出为权威。同步失败后，本地持久化待处理队列对账元数据；未知费用绝不能静默当作零。OpenCode 转发测试覆盖认证、配置模型约束、流式工具调用/UTF-8、预算及取消。
- API 在最终记账前还会持久化收到的结算，并在下次请求预算预检前完成对账。PostgreSQL 验证在持久化与结算之间重建仓储，确认恢复后原子删除待处理标记。临时调用派发标记不向其他工作进程暴露为最终结果。
- 预算配置位于项目基础设置。所有模型入口都显示警告/阻断原因；无需配置编码执行器，也能显式申请超预算审批。创建审批不会运行模型或推进 Gate。
- 桌面试点包构建成功：Electron 42.11.6、arm64、应用版本 2.3.0。沿用原数据档案更新既有安装应用及 API/Web 服务。
