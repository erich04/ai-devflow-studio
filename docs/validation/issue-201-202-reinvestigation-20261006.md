## #202：结算故障和窗口时序

先在新构建上复跑原 H6 的 10 组实验，通过。随后扩展 `scripts/hardening-settlement-electron.mts`，增加显式的 `DEVFLOW_H6_STRESS=1` 模式。最终完整复跑结果：

| 条件 | 次数 | 结果 |
| --- | ---: | --- |
| 正常结算 | 1 | 保存设计 |
| 结算 HTTP 503 | 8 | `settlement_sync_failed`、已确认用量；窗口仍响应 |
| 结算连接中断 | 8 | 同上 |
| 服务端已提交结算，回执丢失 | 8 | 同上 |
| 结算延迟 5 秒后返回 503 | 2 | 同上 |
| 结算 HTTP 200 后响应正文中断 | 2 | 同上 |
| 模型响应完成、结算尚在等待时取消阶段操作 | 2 | 及时返回已取消；等待最终费用记录收尾后仍可恢复 |

31 组实验共 61 次本机合成模型调用，**没有付费模型调用**。每次失败都不保存设计、不推进 Run；服务未恢复时明确重试不新增模型请求，恢复服务后明确重试成功。取消场景的错误是“已取消”，不要求它返回结算错误；这不意味着已发生的模型用量免费。

全部故障场景中，renderer IPC 仍能读取状态，主进程存活，清理前没有窗口关闭、渲染进程退出或 WebContents 销毁事件。末尾强制崩溃、主动关闭窗口的正对照仍能采集到对应事件。故障实验与脚本清理分开记录。

实验校准时，临时脚本曾错误地要求取消场景也返回 `settlement_sync_failed`，因此断言失败。核对时间线可见实际返回了预期的 `cancelled`；修正测试预期后，最终整套 31 组实验通过。没有把这个测试夹具错误当成产品缺陷。
