## 本轮发现并修复的诊断持久化缺口

注入一次 SQLite 写入失败，分别命中 Direct/Native 保存 Provider `invalid_json` 诊断的位置。修复前，最终状态把原始失败替换成存储错误或泛化 Native 错误；红测试记录分别为 `persistence-red.log` 和 `native-persistence-red.log`。

修复后保留该调用原始失败、响应元数据和真实返回的 usage，导出标记 `diagnosticPersistenceFailed=true`，UI 提示存储故障，禁止再发付费重试。同样覆盖 Direct/Native 的总结请求，补存时绑定真正失败的调用 ID，不能写到前一个正常请求。仅在存储恢复可写时能够补存这些记录；永久磁盘故障不能声称已持久化。原子存储行为和原有聊天/产物保留不变。

另一个补强是为每次调用持久化批次 ID、当时的步数/时间上限和配置来源，包括总结调用；用户修改配置后继续，不会把旧调用解释成采用新配置。缺少历史字段的旧数据仍显示未知。该场景先有失败断言，再补齐实现。
