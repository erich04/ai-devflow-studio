# OpenCode 费用记录与恢复：第二、三批本地验证

日期：2026-10-04。分支：`codex/opencode-error-reporting`。第一批已保留为本地提交 `d11c921`；用户随后授权在同一工作区连续完成第二、三批。实现决定见 [费用恢复计划](../plans/opencode-cost-recovery.md)。

## 完成范围

- Web 预算页和 Electron 项目模型设置显示同一费用来源：缺用量、缺定价、最终结果待同步、迟到冲突、运行中预留及长时间未结算。实际花费与预计占用分开，历史月份保留可见但不加入本月阻断；阶段预算/结算失败可进入费用记录。
- 重传只上传已保存的最终结算，不调用模型。桌面写入原组织、用户、团队项目和本地项目作用域；旧记录须由服务端证实身份才能手动重传。服务端也按原用户过滤，旧版无明确 final 标记的失败占位不能重传。SQLite 写入、删除和冲突回执在返回前持久化。
- Lead/Owner 使用专门核对命令，提交精确财务版本、幂等键、执行状态、原因和非敏感依据。Postgres v31 追加核对、迟到确认和冲突事件，保留原调用者及原结算。成员不可核对；不能在正文伪造操作者；未知执行状态不因超过十分钟而变成免费。
- 项目/成员费用、预算准入和批准剩余额度均使用有效账目。核对金额不伪造未知 Token；零金额需要账单或未发送证明。核对与 reserve/settle 使用相同事务锁；冲突有持久回执，重复上传不会重复计费或重新打开已处理的旧冲突。
- 相符的迟到结果追加确认事件，可补齐未知 Token；相矛盾的金额或已知用量重新进入待核对。原设备尚未上传的数据不能由 Web 读取；界面明确提示回原设备同步。费用恢复不会自动推进或重跑工作流。

## 确定性验证
