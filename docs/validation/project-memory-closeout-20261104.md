# 项目记忆收尾验证（2026-11-04）

在隔离的 Todo 仓库、Electron 用户目录和 Hindsight 1.0.0 容器内，用正式采集、召回和提示词组装路径验证。模型为 DeepSeek Flash，所有试验通过限额中继。桌面流程使用独立的内存 Team 测试 API，走真实的配对、宿主预算检查及 IPC。模型提供方的凭据只在本机网关使用。

| 场景 | 观察到的结果 |
| --- | --- |
| 跨对话记忆 | 用户在第一段讨论指定英文注释、重试 5 次和退避上限 30 秒。由空闲讨论自动写入后，另一段 Direct 聊天答对了三项。另起真实 OpenCode 1.18.15 会话也答对注释语言。两份宿主回执各有 4 条记忆，包括约定页。 |
| 需求、设计、Gate | Electron 中生成的需求、需求评审、设计和设计评审分别记录了 4 条记忆。回执只保存裁剪后交给执行器的 ID、修订和文本摘要。 |
| Native 编码和浏览器 | 编码简报有 4 条记忆。审阅精确 diff 后在独立工作树完成“清除已完成任务”，宿主测试通过。Playwright 在真实 Electron Chromium 内通过 9 项界面检查，包括刷新后记录不复活、保留顺序、全清和无确认弹窗。PR 评审记录了 5 条记忆。合成项目停在 PR 交付节点，业务验收仍受交付前置条件约束。 |
| 压缩 | 大样本运行中，结构化 Direct 第 3、4 轮压缩后分别附带 6、5 条记忆（含沟通偏好），末轮依据历史回答 November 3。Native 也通过原有的压缩后重新附带检查。 |
| 采集过滤 | 54 份合成文档覆盖对话、代码执行、批准的产物和提交消息。只过滤带轮号的数字采样句，同条消息中的决定（如行高 44px）保留。分段 ID 仍按过滤前的原文分配。 |

额外用同一评估 bank 的两个固定编码简报比较“同步重试，次数和上限按我们定好的来，只改这个文件”。旧规则除整句外发出 3 次查询，新规则只查整句。正确观察在召回的 8 条里由第 6 位升到第 3 位，简报由 6,481 变为 5,958 字节。每种简报各调用真实模型 6 次，顺序交替，两组都 6/6 返回 5 次和 30,000 毫秒。这是数值选择实验；10 月 31 日代码生成中出现的 5/6 到 3/6 仍不能由这个实验归因。

完整脚本首跑有 103/106 项通过。其余三项集中在编辑与遗忘，暴露了两个验收问题。Hindsight 对归纳观察的 PATCH 返回 400；编辑与删除应从可修改的原始事实或经历中选择。忘记来源时，后台可能在检查时已经重写知识页，因此先核对二次失效标记，再检查用户还能读到的页面是否含已忘记的内容。原来只看“等所有任务完成后页面是否为空”会误报。远端清空失败时，本次修改也会按本地失效时间遮住旧页。

在修正后的记忆面板里，Playwright 打开“观察”确认它为只读，再切换到“事实”点击编辑和删除。每次都从 Hindsight 列表重新读取，确认保存的是新文字、删除的 ID 已消失。独立重建的 Todo bank 还检验了修改前后回执的有效性。

独立 bank 暴露了另一种失败：在缩短的编码查询里，“归档沿用删除的撤销窗口时长”只查到了测试定时器推进 15,000 ms。Native 最终写出了正确常量，但那条计时器经验不能证明业务规则。现在保留完整请求，同时查明确的参照对象和属性（“删除任务的撤销窗口时长”）。同一 bank 复查时，简报拿到了写明业务决定从 5 秒、10 秒改为 15 秒的观察。完整脚本的简报检查也改用桌面路径的查询和拆句参数。

复验入口：

- `scripts/hindsight-fullchain-electron.mts` 沿用原有的真实 Electron 验证配置，另设 `DEVFLOW_FULLCHAIN_PROJECT_MEMORY=1`。可加 `DEVFLOW_MEMORY_VERIFY_OPENCODE=1` 验证本机 OpenCode。`DEVFLOW_FULLCHAIN_PROJECT_MEMORY=curation` 则只跑真实聊天、后台采集及记忆页的编辑和删除，写后从 Hindsight 重新读取核对。Hindsight 的抽取目标应指向该 Electron 的记忆中继，所有上游模型请求经过同一个已授权的本机预算网关。
- `scripts/project-memory-full-validation.mts` 覆盖长期采集、真实 Native 编码、两种讨论协议、阶段和 Gate、编辑、遗忘和清空。可按阶段续跑。运行时检查报告里的每一项检查。
- `scripts/project-memory-retry-probe.mts` 使用完整脚本的合成评估工作目录（`DEVFLOW_MEMORY_FULL_RESUME`），在清空 bank 前运行。设置 `DEVFLOW_MEMORY_LIVE_AUTHORIZED=1` 并用 `DEVFLOW_FULLCHAIN_MODEL_ENDPOINT` 指定带有人民币累计硬上限的本机网关。

两个研究项各自需要独立的判据。要测“模型采用了什么”，先在有预期值的任务里对照生成的补丁与宿主测试；产品里若增加引用，应校验模型返回的引用 ID 属于本次回执，分别记录模型自述和独立证据。要减少过时事实，应区分“当前值”和“为何修改”的查询，在带明确替代关系的数据上试验，并保留历史可追溯性。单凭观察引用过某个事实就压掉它，会一起丢失仍有效的事实。
