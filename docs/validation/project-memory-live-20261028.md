# 项目记忆真实模型验证（2026-10-28）

对应 [ADR 0030](../adr/0030-hindsight-project-memory.md)。用户授权的总预算为 3 美元，所有运行累计记在 `out/project-memory-validation/ledger.json`（不提交）。

## 方法

`scripts/project-memory-live-validation.mts`，合成数据，不读业务项目：

- 用 DevFlow 自己的采集函数构造 5 个文档：两段讨论（第二段把撤销窗口从 5 秒改为 10 秒）、一次失败和一次修复成功的编码记录（DevFlow 自己运行的测试标为 `HOST_VERIFIED`）、一份已批准的设计。
- 经 PR1 的发件队列写入固定版本 Hindsight 1.0.0（本仓库 Compose，Docker Desktop，macOS）。Hindsight 的抽取和归纳通过 DevFlow 中继调用 DeepSeek `deepseek-v4-flash`，thinking 关闭。
- 中继使用脚本内的硬上限预算：按最坏情况（1M 输入 tokens、8192 输出 tokens、高峰价）预留，按实际 usage 结算，未结算的预留按已花费计。
- 再用 PR2 的召回服务提 4 个问题，按编码（8 条）和讨论（4 条）两种预算检查真正会送进提示的内容。
- 结束后删除测试 bank。

## 结果

| 运行 | 调用 | 输入 / 缓存命中 / 输出 tokens | 费用 | 说明 |
|---|---|---|---|---|
| run-…16-01-07 | 0 | 0 | 0 | 中继返回 401：上一次检查导出的 `DEVFLOW_MEMORY_RELAY_TOKEN` 残留在 shell 里，Compose 优先使用 shell 变量，容器拿到了旧令牌。没有模型调用。 |
| run-…16-13-15 | 8 | 38,218 / 20,608 / 4,162 | $0.0052 | 基线。5 个文档首次即写入，得到 31 条记忆（12 条 observation）。 |
| run-…16-17-59 | 8 | 37,877 / 23,936 / 3,445 | $0.0042 | 调整任务说明和召回排序后重跑。 |

累计 $0.0094，占 3 美元预算的 0.3%。每个文档约 1.6 次模型调用、不到 0.1 美分。

基线发现的问题和处理：

1. **旧决定没有被替换。** 5 秒和 10 秒两条 observation 同时存在。调整 observations 任务说明后（较新的用户决定替换旧信念），第二次得到一条：「撤销窗口原定 5 秒，因用户反馈 5 秒太短，于 2026-10-28 改为 10 秒」。
2. **助手的复述被记成「未经验证的声明」。** 例如「助手声称已记录：撤销窗口从 5 秒调整为 10 秒」。retain 任务说明改为讨论中只记用户的要求、决定和偏好，跳过助手的确认和复述；编码 Agent 的「已修复」「测试通过」仍记为声明。第二次没有这类条目，`HOST_VERIFIED` 与 Agent 声明的区分保持正确。
3. **召回排序对中文问题几乎无效。** 镜像自带的 embedding（`bge-small-en-v1.5`）和 reranker（`ms-marco-MiniLM-L-6-v2`）都是英文模型，4 个问题返回的顺序基本相同；讨论栏只取前 4 条时，「用什么语言回答」排在第 10 位。现在 DevFlow 向 Hindsight 多要候选，再用自己的中文 BM25 与 Hindsight 顺序做倒数排名融合。

调整后，在编码预算内 4 个问题的预期内容全部命中；在讨论预算内命中 3 个，「删除后列表不刷新怎么办」的 `refreshTasks()` 修复细节排在第 5，讨论栏仍可用 `memory_search` 查到。
