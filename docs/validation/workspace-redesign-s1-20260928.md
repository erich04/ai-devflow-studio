# 工作区改造 S1：桌面首屏减负

日期：2026-09-28。对应[工作区改造方案](../plans/task-centered-workspace-redesign-2026-09-28.zh-CN.md) 7.1 节的改动清单与 8.1 节的验收。S1 不另建 spec，以 7.1 节为任务清单。分支 `feat/workspace-redesign-s1`，基于 S0 提交 `b07b1fb`。

## 结论

- 2.2 节的 S1 数字目标在三档内容区（1440、1280、1024 × 742）的主基线上全部达到，深色主题数字相同。32 个状态样例中可制备的 30 个都已重新测量；23 个任务页样例里，除“浏览尚未开始的阶段”多出一行浏览提示外，状态行与首个正文区块的位置都与主基线一致。
- 7.1 节各项都已实现。有一处按安全要求与原文不同：代码改动类权限请求的「批准」仍需在 Agents 页看过精确差异后执行，状态行提供跳转、「拒绝」与「停止执行」，见“与方案的差异”。
- 只改了呈现层、导航和一个抽出的纯函数。IPC 写入、同步队列、交付撤销逻辑和数据库结构都没有改；主进程的需求版本校验抽成独立函数后，判断条件与错误信息逐字不变。一级导航仍是 8 项。
- S0 报告中“深色主题下的数字与浅色相同”一条不成立：S0 的深色截图实际按浅色渲染。原因和修正见“对 S0 报告的更正”。

## 环境与方法

与 S0 相同：macOS arm64，Node.js 24.18.0，Electron 42.11.6，加载构建产物；每个样例使用新的临时用户数据目录、示例仓库和内存演示 Team API；需求、方案、审查由 Deterministic Fake Provider 生成，编码用 fake 引擎或受控模型服务，讨论用固定回答的受控模型服务，主进程拦截所有非本机请求。未覆盖真实模型、远端发布、GitHub 交付、Postgres 团队仓储和 Web 页面。

测量口径与 S0 相同（方案 2.2 节）。样例脚本只做了与新界面对应的定位调整：项目菜单、团队连接弹层、子步骤展开、「⋯」中的修订入口、重新配对确认、默认收起的讨论栏。测量脚本另外记录页面实际生效的主题（`renderedTheme`）。

数据与截图在 [`evidence/workspace-redesign-s1-20260928/`](evidence/workspace-redesign-s1-20260928/)，结构与 S0 相同，可按文件名逐张对照 [S0 证据](evidence/workspace-redesign-s0-20260928/)。

## 与方案的差异

- **代码改动的批准**（X2）：权限请求分两类处理。依赖安装、执行授权等请求在状态行直接「批准本次」；代码改动（Change Set）和最终接收修改的请求，状态行主动作是「审查并批准修改」，跳到 Agents 页的精确差异审查后再批准。「拒绝」和「停止执行」对两类请求都在状态行。原因：现有设计要求批准前看到与摘要一致的差异，状态行放不下差异内容。确定性样例 `build-permission` 属于前一类。
- **合并提交**：原计划按主题拆成更多提交。渲染层改动集中在 `App.tsx` 和 `DesktopViews.tsx`，按主题拆分会留下无法编译的中间提交，因此合并为产品代码、测试脚本、文档三次提交。

## 发现并在 S1 内处理的问题

- 讨论栏在 1100px 以下以覆盖方式展开时层级高于模态对话框，会话说明的「关闭说明」按钮点不到（会话冒烟测试首次运行失败）。已把讨论栏层级降到对话框之下。
- 团队连接弹层对服务端拒绝的凭据仍提供「重试」，而重试必然再次失败。现在只有在拒绝发生于当前凭据签发之前（也就是已重新连接）时才提供重试。
- 审批核对清单与状态值使用英文原值（`ready`、`empty`、`3 events`），并在策略未读取时显示“已阻断”。状态值已按 6.3 节改为中文，原值保留在悬停提示中。

以下三项是 PR 的 CI 发现的，首次提交前本地没有运行对应的检查：

- Playwright 端到端测试（`tests/e2e/desktop.spec.ts`）有 13 个用例仍按旧界面定位。已按新界面更新，`corepack pnpm test:e2e` 全部 41 项通过。
- 打包交付冒烟测试找不到「Verify credential revocation」：S1 把交付完成后的这个核验动作收进了「⋯」。它是这个状态下唯一的后续动作，已改回状态行显示，并补了断言。这个冒烟测试需要 Postgres 和 Linux 打包环境，本地无法运行，以 CI 结果为准。
- 顶栏项目菜单打开后不会自动关闭，会一直盖住左侧导航。已改为按 Escape 或点击菜单外部时关闭，焦点回到触发按钮。

CI 的生产依赖审计同时失败，原因是 Electron 依赖的 `undici@7.29.0` 在 2026-09-29 出现中危公告，与本批改动无关，另开 PR 固定到 7.29.1。

## 对 S0 报告的更正

S0 报告写“深色主题下的数字与浅色相同（`variants/dark`）”。复查截图发现 S0 的深色样例实际按浅色渲染：应用默认的主题偏好是“跟随系统”，而 Playwright 启动 Electron 时默认模拟 `prefers-color-scheme: light`，覆盖了 `DEVFLOW_INITIAL_THEME=dark`。S1 在测量脚本中按 `--theme` 设置模拟的配色，并记录 `renderedTheme`。S0 的深色数据不代表深色主题；布局数字与主题无关，S1 深色与浅色的数字确实相同，所以对首屏结论没有影响。S0 的入库证据保持原样，不重新生成。
