# 工作区改造 S2：任务内操作

日期：2026-09-28。对应[工作区改造方案](../plans/task-centered-workspace-redesign-2026-09-28.zh-CN.md) 7.2 节的改动清单（W1–W9）与 8.2 节的 S2 验收。分支 `feat/workspace-redesign-s2`，基于 S1 合入后的 `main`。

## 结论

- W1–W9 已实现。门禁审查、开发实现的权限决定与重试、测试执行都在任务页完成；Agents 页和测试页只保留配置、只读证据与诊断，执行入口改为「在任务中处理」，新旧界面不会同时发起同一动作。
- S1 设了目标的首屏指标在 32 个样例上没有变化，包括三档主基线：状态行底部 226px，首个正文区块 272px，顶栏 56px、5 个控件，字号最多 4 种、最小 12px。无横向溢出，阶段标签没有截断。
- 视口内可交互控件变多：主基线由 39 个增至 45 个，其他 Gate 样例增加 4–7 个。原因是「当前工作」合并了「概览」与「内容与审查」，首屏现在是待确认的需求正文及其分节，不再是核对清单。这个数 S1 没有设目标，按计划在 S3 验收（≤ 28）。
- 200% 缩放下状态行底部由 268px 变为 286px，多出一行。W2 要求状态行写明门禁审查使用的模型，模型名就占了这一行。窄宽度下状态行说明已改为行内换行，否则会多两行。
- 只改了呈现层与导航。IPC 写入、同步队列、交付撤销逻辑、数据库结构和会话契约都没有改。任务内的动作调用的都是原有写入函数，只是完成后不再跳到 Agents 页或测试页。
- 所有模型调用来自 Deterministic Fake Provider 或本机受控服务。没有真实模型调用，没有远端发布，也没有推送交付。

## 环境与方法

与 S1 相同：macOS arm64，Node.js 24.18.0，Electron 42.11.6，加载构建产物。每个样例使用新的临时用户数据目录、示例仓库和内存演示 Team API。主进程拦截所有非本机请求。

样例脚本只做了与新界面对应的调整：门禁审查改在状态行运行；测试样例先在任务测试步骤点「运行检查」，再打开测试页测量；需求版本样例改为打开「当前工作」。

```sh
corepack pnpm exec tsx scripts/workspace-baseline.mts --out docs/validation/evidence/workspace-redesign-s2-20260928
corepack pnpm exec tsx scripts/workspace-baseline.mts --samples clarify-gate-warn --sizes 1440x742 --theme dark --out docs/validation/evidence/workspace-redesign-s2-20260928/variants/dark
corepack pnpm exec tsx scripts/workspace-baseline.mts --samples clarify-gate-warn --sizes 1440x742 --zoom 2 --out docs/validation/evidence/workspace-redesign-s2-20260928/variants/zoom200
corepack pnpm exec tsx scripts/workspace-baseline.mts --self-check
```

数据与截图在 [`evidence/workspace-redesign-s2-20260928/`](evidence/workspace-redesign-s2-20260928/)，结构与 S1 相同，可按文件名对照 [S1 证据](evidence/workspace-redesign-s1-20260928/)。

## 8.2 节 S2 验收

| 场景 | 结果 | 依据 |
| --- | --- | --- |
| 门禁审查、编码、测试都在任务内完成，记录的身份与版本正确 | 通过 | Electron 冒烟：方案 Gate 从状态行运行审查，令牌用量记在配对用户名下，每个 Gate 只存一份审查；编码权限在状态行「批准本次」，决定人是配对用户；测试步骤在状态行「运行检查」，渲染层只传项目、任务和步骤标识，证据为 `passed`、命令为已保存的 `npm test`。App 测试核对重新审查携带 `previousReviewId`，追加尝试携带次数，重试携带预算批准编号 |
| 权限请求不被导航隐藏，恢复不会自动授权 | 通过 | 权限请求显示在「当前工作」，「拒绝」「停止执行」一直在状态行。「重新核验并请求审批」只调用原有的重新核验，提示写明尚未批准执行（App 测试） |
| 代码改动在看到精确差异后才能批准 | 通过 | 精确差异审查在「当前工作」中渲染，状态行没有批准按钮；批准还要求差异已显示。组件测试与 e2e 多文件改动用例 |
| 修改代码后，旧的测试结果不显示为仍然有效 | 通过（按“适用性无法核实”） | 任务内的测试结果与测试页都写明执行时间和“适用性无法核实”。“已过期”要等测试证据记录提交号，属于写入改动，未做 |
| 同一内容在三个页签中只出现一次 | 通过 | 状态投影测试逐一核对各页签的内容分配。五处重复已消除：知识引用只在「材料与版本」，正文中是指向它的链接；测试步骤的测试结果只在「当前工作」；交付面板只在正文中，验收步骤也显示一次；正文待核对事项只在正文中；审查报告原文只在「材料与版本」 |
| 保存聊天提案后只有目标提案成为共享材料，流程不自动推进 | 通过 | 「保存为节点提案」先预览目标和内容，确认后调用原有的 `publish`。会话冒烟核对了三点：保存前后没有模型调用；提案在目标步骤的「材料与版本」中标为「讨论提案（待确认）」；保存后提示“提案已保存，尚未更新正式需求”。流程不推进由原有的会话服务测试覆盖，这次没有改动这部分 |
| 设置保存后回到原任务和阅读位置，不自动执行付费或发布动作 | 部分通过 | 从「去设置执行工具」或「设置测试命令」进入设置页后，页面显示「返回任务」，保存后提示可以返回；返回后恢复步骤和页签，不运行任何动作（App 测试）。讨论栏与用量弹层中的“配置”链接走同一个入口，没有单独测试。材料与滚动位置的恢复已实现，但没有自动化测试：jsdom 不计算滚动，Electron 冒烟也未覆盖 |

## 与方案的差异

实施中的差异已记回方案 7.2 节末尾，主要有：

- 测试 Gate 的状态行与恢复计划提供「查看测试步骤」，不在 Gate 上运行测试。
- 「重新审查」和上次审查失败的说明放在被审材料的下方；运行、停止、模型和费用说明在状态行。
- 团队策略未读取时，审批核对清单的「审批权限」改为「待核实」。
- 任务内「运行检查」校验已保存的命令，不再校验测试页上的草稿。
- 讨论引用的数量、长度都有上限。

## 发现并在 S2 内处理的问题

- 删去 Gate 自己的结论分组后，团队策略未读取时，清单中「策略与权限」一组显示“已阻断”，与状态行的「状态待核实」矛盾。原因是 `approvalStatus` 在不可审批时一律按阻断计。现在策略未读取时显示「待核实」（方案 X4）。
- `executeTestPlan` 校验的是测试页上未保存的命令草稿，而主进程运行的是已保存的命令。执行搬进任务页后，这会让任务内的检查被一个看不见的草稿阻断。现在改为校验已保存的命令；已保存的命令本身若不安全，仍在调用主进程之前拒绝，有测试覆盖。
- 需求阅读器的「审查依据」链接没有间距。它原来在第二个页签，现在是首屏内容，已补上样式。
- 验收步骤的正文里原先不显示交付面板，因为代码按阶段值 `acceptance` 判断，实际的阶段值是 `accept`；它只出现在原「概览」页签。S2 删去「概览」里的那一份，交付面板在 PR 与验收步骤的正文中各显示一次。

- 交付交接面板（Delivery Handoff、PR Delivery Package、Acceptance Bundle）和「Gate 影响」卡片仍有英文和旧称，归 S3 文案。
- 模型、执行工具、预算设置仍在 Agents 页，从任务进入时显示「返回任务」，S3 迁入设置。
- 视口内可交互控件数在 S3 收拢导航后按 ≤ 28 验收。
