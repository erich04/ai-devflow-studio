# 工作区改造 S3：导航与设置

日期：2026-09-28。对应[工作区改造方案](../plans/task-centered-workspace-redesign-2026-09-28.zh-CN.md) 7.3 节的改动清单（Y1–Y9）与 8.2 节的 S3 验收。分支 `feat/workspace-redesign-s3`，基于 S2 合入后的 `main`（`bd2fc1f`）。

## 结论

- Y1–Y9 已实现。一级导航收为任务、知识、团队、设置 4 项。原 Agents 页的配置、Skills、MCP、测试命令、诊断和主题迁入设置的 6 个分区，删除了 Agents 页与测试页。开发执行证据移到开发步骤的「执行记录」，记忆管理移到知识页。
- 主基线三档的视口内可交互控件由 45 个降到 28 个，达到 2.2 节的 S3 目标。其他常规样例是 21–28 个。
- S1 设了目标的首屏指标在任务页样例上都没有变化：状态行底部 226px，首个正文区块 272px，顶栏 56px。顶栏控件由 5 个减为 4 个，字号最多 4 种、最小 12px，无横向溢出，阶段标签没有截断。
- 只改了呈现层与导航。IPC 写入、同步队列、交付撤销逻辑、数据库结构和会话契约都没有改。设置中的保存与一次性预算批准调用的是原有写入函数。执行仍只在任务页发起，设置页没有执行入口，「在任务中处理」「在任务中重新运行」只跳回任务。
- 所有模型调用来自 Deterministic Fake Provider 或本机受控服务。没有真实模型调用，没有远端发布，也没有推送交付。

## 环境与方法

与 S2 相同：macOS arm64，Node.js 24.18.0，Electron 42.11.6，加载构建产物。每个样例使用新的临时用户数据目录、示例仓库和内存演示 Team API，主进程拦截所有非本机请求。

样例脚本只做了与新导航对应的调整，旧布局下同样能运行：

- 导航名兼容「任务」与「工作台」。
- 配对表单改在设置／团队连接中填写。
- 测试样例改为打开设置／本地项目。
- 阶段项自身展开子步骤。

```sh
corepack pnpm exec tsx scripts/workspace-baseline.mts --out docs/validation/evidence/workspace-redesign-s3-20260928
corepack pnpm exec tsx scripts/workspace-baseline.mts --samples clarify-gate-warn --sizes 1440x742 --theme dark --out docs/validation/evidence/workspace-redesign-s3-20260928/variants/dark
corepack pnpm exec tsx scripts/workspace-baseline.mts --samples clarify-gate-warn --sizes 1440x742 --zoom 2 --out docs/validation/evidence/workspace-redesign-s3-20260928/variants/zoom200
corepack pnpm exec tsx scripts/workspace-baseline.mts --self-check
```

数据与截图在 [`evidence/workspace-redesign-s3-20260928/`](evidence/workspace-redesign-s3-20260928/)，可按文件名对照 [S2 证据](evidence/workspace-redesign-s2-20260928/)。

## 首屏指标

样例 `clarify-gate-warn`：需求确认 Gate，策略仅警告，缺少门禁审查，未连接团队。

| 指标 | S2（1440 / 1280 / 1024） | S3（1440 / 1280 / 1024） | 目标 |
| --- | --- | --- | --- |
| 状态行底部 | 226 / 226 / 226px | 226 / 226 / 226px | ≤ 240px（S1） |
| 默认页签首个正文区块顶部 | 272 / 272 / 272px | 272 / 272 / 272px | ≤ 280px（S1） |
| 顶栏总高度 | 56px | 56px | ≤ 56px（S1） |
| 顶栏控件 | 5 | 4 | ≤ 6（S1） |
| 视口内可交互控件 | 45 / 45 / 45 | 28 / 28 / 28 | ≤ 28（S3） |
| 主区字号 | 4 种，最小 12px | 4 种，最小 12px | ≤ 5 种，最小 12px |
| 空讨论栏 | 0 | 0 | 0 |
| 被截断的阶段标签、页面横向溢出 | 无 | 无 | — |

主基线的 28 个控件与 2.2 节的推算一致：

| 位置 | 个数 | 内容 |
| --- | --- | --- |
| 顶栏 | 4 | 项目、搜索、团队连接、新建任务 |
| 导航 | 4 | 任务、知识、团队、设置 |
| 标题行 | 2 | 任务菜单、讨论 |
| 阶段行 | 6 | 6 个阶段项 |
| 状态行 | 4 | 运行门禁审查、确认需求 v1、请求修订当前版本、「⋯」 |
| 页签 | 3 | 当前工作、材料与版本、执行记录 |
| 正文 | 5 | 讨论此材料、阅读工具，以及需求范围、验收标准、待确认事项 3 个分节页签 |

与 S2 相比少了 17 个：

- 导航少 4 项，顶栏少主题切换。
- 「本任务用量」改为常显文字。
- 阶段行少了子步骤和 3 个视图按钮。
- 审查依据的 3 个链接、目录的 4 个锚点和「查看原文」收进「阅读工具」。

其他样例：

- 深色主题（`renderedTheme: dark`）的数字与浅色相同。
- 200% 缩放：状态行底部 281px（S2 为 286px），首个正文区块 327px（S2 为 332px），视口内控件 23 个（S2 为 27 个），无横向溢出。
- 其余任务页样例的状态行与首个正文区块位置都与 S2 相同，控件数：

  | 样例 | S2 → S3 |
  | --- | --- |
  | 需求 Gate 的其他三种（有建议、无建议、强制阻断）、策略重新读取失败 | 44 → 27 |
  | 方案 Gate | 38 → 28 |
  | 开发执行中、开发执行中断 | 33 → 23 |
  | 开发权限请求 | 35 → 25 |
  | 测试步骤 | 32 → 22 |
  | PR 交付 | 34 → 24 |
  | 业务验收 | 31 → 21 |
  | 等待上游 | 32 → 22 |

- 非常规场景仍超过 28 个：
  - 阅读历史版本（`clarify-history`）31 个，多了版本选择、「返回待确认版本」和其他版本的修订草稿。字号由 3 种变为 4 种，仍在目标内。
  - 团队连接弹层打开时（`team-*`、`upload-*`）29–31 个，多出的是弹层中的关闭按钮和进入设置的按钮。
  - 讨论栏展开时（`discussion-messages`）39 个。
- 7 个测试样例和 `team-existing-credential` 现在测量的是设置页（设置／本地项目、设置／团队连接），不再是原测试页和团队连接弹层，没有状态行，不与 S2 直接对比。

| 场景 | 结果 | 依据 |
| --- | --- | --- |
| 视口内可交互控件在三档内容区常规场景下达到 S3 目标 | 通过 | 主基线三档都是 28 个，其他常规样例 21–28 个（上节）。停止、取消与拒绝仍在状态行，未知费用仍以文字显示在标题行 |
| 旧入口和搜索结果定位到正确的项目、任务、材料与页签 | 通过 | 旧入口的映射有单元测试（`SettingsView.test.tsx`）：执行工具与模型 → 模型与执行方式，测试命令 → 本地项目，Skills、MCP → 扩展能力，诊断 → 高级。任务中的「去设置」进入对应分区，显示「来自任务 · 返回任务」，返回后恢复步骤与页签，不运行任何动作（App 测试）。搜索结果和知识引用的跳转沿用原有测试，都通过 |
| 知识引用按文档分组，版本、章节与审查关系不丢失 | 通过 | 同一文档只出现一次，下列引用它的任务、步骤、材料或 Gate，每条保留内容版本、材料版本、章节路径、引用关系与审查状态。内容哈希和各类标识放在「详情」中。任务内跳到知识页时，被引用的一条高亮并滚动到可见位置（`knowledge-reference-groups.test.ts`、`KnowledgeView.test.tsx`、App 测试） |
| 连接详情的三类状态在各组合下含义都正确 | 通过 | 视图模型测试覆盖 4 种组合：已绑定未读取、策略已加载但团队数据失败、数据已更新但上传待完成、切换项目或绑定过期。策略快照单独一行，读取失败时写明仍在使用的本机缓存版本。设置／团队连接列出身份、团队项目与有效期，弹层只留摘要和进入设置的入口 |
| 上传的五种情况与 6.5 节一致 | 通过 | 逐条记录的文案与重试条件沿用 S1 的 `describeUploadRecord`，没有改动，原有测试全部通过。记录与重试移到设置／团队连接后，App 测试改在设置中重试 |

7 节表中 S3 的其他完成条件：

- **高级能力仍可到达**：独立 Runtime 与多 Agent 诊断在设置／高级，默认折叠；记忆管理在知识页。App 测试与 e2e 都覆盖。
- **切换项目不串上下文**：模型与执行方式分区按本地项目与凭据重建。切换项目后知识索引、团队数据与凭据归属不串，由原有的 App 测试覆盖。连接详情有切换项目后的视图模型测试。

## 与方案的差异

实施中的差异已记回方案 7.3 节末尾：

- 证据分组按“只出现一次”取舍。开发步骤的「执行记录」合并了费用、结算、预算评估和历次执行的权限与轨迹，折叠区不再重复这些内容。
- 模型提供方设置不再列出审查总数等执行统计。
- 设置／团队连接的上传部分补了自动重排与手动重试的说明。
- 搜索框与搜索结果的类型名改为中文。

## 发现并在 S3 内处理的问题

- 窄于 1100px 时，设置分区列表被压成 0 高度，无法切换分区。原因是横向滚动容器的自动最小高度为 0。e2e 的 760px 用例发现后，已给列表固定内容高度。
- 阶段项内新增的展开标记起初单独占了一行，阶段行高了约 10px，首个正文区块到了 282px，超出 S1 目标。标记已改为与状态文字同行。
- 「阅读工具」起初沿用了材料正文里折叠项的边框样式，在首屏占了一大块，已改为分节页签旁的文字入口。
- 多 Agent 诊断的不可用说明仍写着“在页面顶部绑定”，已改为指向设置／团队连接。设置／本地项目的测试记录原先直接显示状态原值，已改为中文。
