# 工作区改造 S5：Web 待办、任务详情与交付审批

日期：2026-09-28。对应[工作区改造方案](../plans/task-centered-workspace-redesign-2026-09-28.zh-CN.md) 7.5 节的改动清单与契约变更（Q1–Q8），以及 8.2 节的 S5 验收。分支 `feat/workspace-redesign-s5`，基于 S4 合入后的 `main`（`5c4d8f4`）。

## 结论

- **Web 首屏改为我的待办。** 一级导航为我的待办、项目任务、团队、设置。配对、仓库绑定、指标卡已移出任务首屏。旧链接仍可用：`projectId + runId`、`view=team`、`view=settings`、`view=workbench` 都能解析，旧锚点 `#runtime`、`#policy`、`#work-request` 会跳到新位置。
- **我的待办列出三类事项。** 当前项目的待审 Gate（需求确认、方案评审、其他 Gate、业务验收）、待审交付和异常。
  - 每行写明请求方、材料版本、更新时间，以及是否需要你处理，并提供一个「查看」入口。
  - 顶部写明团队数据的读取时间。
  - 交付或身份没有读到时，列表写明“不完整”，不显示“没有待办”。
- **任务详情与交付审批首屏。**
  - 审批区写明所审材料、审批角色和你的角色。没有权限的成员看到“等待负责人审批”，不显示按钮。审批前检查读不到时会写明原因。
  - 交付审批卡首屏显示仓库、分支、预期提交、改动文件、验证范围、请求修订号和截止时间。完整标识放在「技术详情」中，可以复制。
- **契约变更：Web 发起的需求确认与方案评审审批绑定材料版本**（见下节）。缺少快照或版本不一致时，API 预检和桌面端都会拒绝。桌面端执行成功后写入与本地审批相同的审计记录，需求版本同时标为已确认。
- **桌面端团队预算改为只读。** 设置中写明到 Web「设置 › 预算」修改；同步、一次性批准和批准编号保留。
- **范围之外不变。** 没有改数据库结构、同步队列、结果码和 IPC。所有模型调用都来自 Deterministic Fake Provider 或本机受控服务，没有真实模型调用、远端发布或推送交付。

## 契约变更

只影响 Web 发起的需求确认与方案评审 Gate 的批准，驳回、其他 Gate 和业务验收不变。

| 环节 | S5 行为 | 依据 |
| --- | --- | --- |
| API 预检 | 任务投影没有与当前步骤、任务版本一致的审查对象快照时，返回 `preflight_blocked`（409），不创建命令 | `gate-command-preflight.ts`；预检单元测试覆盖三种情况：缺少快照、版本不符、属于其他步骤。另验证驳回仍可用 |
| 桌面端处理器 | 命令不带快照，结果为 `evidence_blocked`。快照与本机重新计算的一致后，再核对本机审批对象：需求取待确认的澄清版本，方案取 Gate 关联的唯一方案（S4 的规则）。标识与记录时间都必须与快照一致，否则同样为 `evidence_blocked` | `gate-command-processor.ts`、新增 `gate-command-material.ts`。处理器测试覆盖：缺少快照、材料已变、关联多份方案、本机版本已不在待确认状态、需求与方案两类审计记录、缺少快照时驳回仍可用 |
| 本地写入 | 写入层按评估时的材料推导审计记录和已确认的版本，调用方带来的审计必须与推导结果一致。已有的事务内材料核对保证材料未变 | `local-store.ts` 的 `commitGateCommandExecution`。测试覆盖：没有快照、审计指向其他版本、需求 Gate 带方案审计，这三种情况都拒绝且不写入任何内容；成功时版本变为 `approved` |
| Web | 需求确认或方案评审缺少快照时，批准按钮不可用并说明原因，驳回可用。执行结果 `evidence_blocked` 的说明提到材料变化 | `GateCommandPanel.tsx`、`WebTaskDetail.tsx` |

审查对象快照原有的解析器、数据库列（`gate_review_subject`、`review_subject`）和指纹计算都没有改。快照中的摘要只覆盖材料正文，所以桌面端另外用 S4 的方案摘要（标题、摘要、正文）写入 `designAudit`。Web 看不到需求修订号，只显示材料类型和记录时间。

## 8.2 节 S5 验收

| 场景 | 结果 | 依据 |
| --- | --- | --- |
| 无权限或数据滞后时不泄露对象、说明数据时效，不显示虚假的空列表或可审批状态 | 通过 | 待办适配层测试（41 项）：只列当前项目；没有浏览器身份、交付读取失败时写明不完整；已登录但不属于该项目时显示“等待负责人审批”；数据时效写读取时间和各行更新时间。页面测试：成员看不到批准和驳回按钮；审批前检查读取失败时写明原因；材料未同步时批准不可用 |
| 材料或绑定变化后，旧审批失效，桌面与 Web 状态一致 | 通过 | 契约变更一节列出的预检、处理器、写入测试。交付审批测试：绑定变化后已勾选的确认会清除，按钮不可用；请求版本变化（`state_conflict`）或过期时写明没有应用决定 |
| 修订、继续、重试、停止按既有契约工作，不重复发布 | 通过（未改动） | 交付决定、仓库绑定、Gate Command 的请求与响应校验保持原样，由改写后的组件测试逐项锁定（交付面板 74 项，包括返回内容过宽、项目不符、版本未前进等异常响应）。Web 没有新增写入接口；交付修订仍在桌面端 |

## 与方案的差异

- 任务详情的执行摘要多了「门禁审查」面板，只读列出本任务的审查结论。原页面在非审批步骤也显示审查结论，改版后若不保留，这部分信息会丢失。
- 写入层自己推导审计记录与已确认的版本，调用方不传材料，只需带与推导一致的审计。这比起草时“接收已确认的版本”更窄，已回写 7.5 节的契约表。
- 交付审批：绑定变化后清除已勾选的确认；技术详情中与首屏重复的两项（预期提交、测试证据标识）不再放复制按钮，保证每张卡片内复制按钮的名称不重复。
- 仓库绑定状态 `stale` 显示为“已失效，需要重新验证”。

## 发现、留给后续批次

- 工作请求表单、配对码面板、预算表单的字段名，以及 Web 代理路由的服务端提示仍是英文（S6 前收尾，7.5 节已列为不包括）。
- 待办中的 Gate 只按角色判断“需要你审批”，不对每一行调用审批前检查。策略阻断在任务详情中显示。逐行评估需要每个任务一次请求，未在 S5 做。
- Web 的时间统一按 UTC 显示。
- `studio-onboarding-postgres-smoke` 已按新导航更新，但需要真实 Postgres 与 Electron，本批次没有运行。
